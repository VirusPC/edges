# 每周一 edges 周复盘

何时跑见同目录 [schedule.md](schedule.md)。本文件不写日程。

## 提示词

每周一给 peng cheng 做 VirusPC/edges 上一个自然周的周复盘（周一 00:00 到周日 23:59，Asia/Shanghai），用中文写。只做复盘和总结，不改代码，不动看板。

本次运行只看 GitHub：commits，PR 的开启、合并和审阅，Issue 和 `.harness/tasks` 看板的状态变化，CI 情况。其他助手的对话本次运行读不到，不要尝试。结尾附一段交接说明：请主聊天逐个助手扫一遍上周对话补进来，合成一版发给用户，再经云端代理 PR 写入 `retrospectives/weekly/<周一日期>--周复盘/INDEX.md`。

正文结构以仓库里的 `retrospectives/weekly/README.md` 为准。一级标题写 `# <周一日期> 周复盘`，下面六节都用 `##`，顺序是：范围、本该怎样、实际怎样、为什么、下次做什么、建议补充内容清单。上期的行动放在「本该怎样」里列出，到「实际怎样」里逐条验收。

每条结论都要写依据。仓库方面给 PR 链接、commit 链接或文件路径，必要时引一两行原文。对话方面写明是哪个助手、什么时间，附原话摘录，再交代上下文：当时在讨论什么，谁答应了什么，后来有没有落地。找不到依据就直说找不到。建议补充内容清单里的每一条都要写清楚：这条是什么、建议放到哪里、为什么值得补、不补会付出什么代价、处理结果。「下次做什么」最多 3 条，每条写明怎样算完成，并注明来源。

鸡毛小事不写，比如 PR 合并时间刚好跨过周边界。对事不对人，不编造，公开仓库内容必须脱敏。篇幅以足够支撑决策为准。

## 对话层

例程运行时读不到其他助手的对话，所以对话层要由主聊天逐个助手去读（每个助手的转写先写到文件，按时间戳筛出时间窗，再交给便宜的模型提炼），最后由主聊天合成。
