### 安装依赖与 ESP-IDF v6.0.1

- 把登录账号加进 `dialout` 组（`sudo usermod -aG dialout <用户>`，重新登录后生效）。
- 按 Espressif 文档装好依赖：`git wget flex bison gperf python3-venv cmake ninja-build ccache libffi-dev libssl-dev dfu-util libusb-1.0-0`。
- 在 `~/esp/esp-idf-v6.0.1` 浅克隆 v6.0.1（`--recursive --depth 1 --shallow-submodules`），再运行 `./install.sh esp32s3`。
- 克隆 Muse Gadget SDK 到 `~/muse-gadget-sdk`。
- 踩坑：长时间任务别依赖 SSH 前台。一开始用 tmux 跑，结果会话无声无息地挂了；改成 `nohup … > log &` 再轮询日志才稳。
- 踩坑：`idf_tools.py install` 要从 GitHub 下载 ESP32-S3 工具链（几百 MB），国内网络下长时间停在 0%，看起来像卡住了。杀掉后改用 Espressif 国内镜像 `IDF_GITHUB_ASSETS=dl.espressif.cn/github_assets`，再加上 pip 清华镜像 `PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` 重新执行，很快就装完了。光克隆 ESP-IDF 源码就用了大约 15 分钟。

### 编译 Waveshare 1.75 固件（暂不带 token）

- 1.75 属于上游「完整 UI，手动构建」那一类，在 `~/muse-gadget-sdk/esp32` 下先执行 `. ~/esp/esp-idf-v6.0.1/export.sh`，再运行：

```
idf.py -B build-muse-waveshare-s3-175 -DIDF_TARGET=esp32s3 \
  -DSDKCONFIG=build-muse-waveshare-s3-175/sdkconfig \
  -DSDKCONFIG_DEFAULTS="sdkconfig.defaults;devices/sdkconfig.muse;devices/sdkconfig.muse-waveshare-s3-175" build
```

- 16 线程大约 3 分钟编完，共 2205 步，app 大小 0x211000，4 MB app 分区还空着 48%。唯一的警告是「No SDK token」。
- Secure Boot 和 flash 加密默认都是关的，不会烧 eFuse，也不要打开。
- SDK token 是**编译期**写进固件的（`CONFIG_GADGET_SDK_TOKEN`，格式是 `mgst_…`），从 Muse 账号的 SDK tokens 页面获取。它不是环境变量，配对时也不会另外写进去。所以拿到 token 后要改 build 目录里的 `sdkconfig` 再重新编译。token 绝不能提交进仓库。
- -G 版：SDK 里没有 GPS 相关代码；LC76G 的 I2C 地址是 0x50 和 0x54，和固件用到的地址不冲突。实机上会不会有问题，要看第一次启动的日志。

### 填入 token、备份、刷机

- token 经 SSH 标准输入写进一个权限 600 的临时文件，再用脚本写进 build 目录的 `sdkconfig`，全程不出现在命令行和日志里。只核对了前缀和长度，事后删掉了临时文件。
- 备份出厂固件：`python -m esptool --chip esp32s3 -p /dev/ttyACM0 read-flash 0 0x1000000 ws175g-backup.bin`，16 MB，走 USB-Serial/JTAG 大约 1 分钟。芯片识别为 ESP32-S3 (QFN56) rev v0.2，内置 8 MB PSRAM。
- 重新编译后，「No SDK token」警告消失。
- 在 build 目录里执行 `esptool ... write-flash @flash_args` 刷入四个镜像，哈希校验全部通过，不用按 BOOT/RESET。
- 踩坑：`dialout` 组要新开登录会话才生效，这一次先用 sudo 跑 esptool。
- 踩坑：nohup 脚本里 source ESP-IDF 的 `export.sh` 时，如果开了 `set -x`，脚本会悄悄退出，去掉就好了。

用 pyserial 抓了 30 秒串口日志：

- -G 版：没有任何 I2C 报错，也没有 LC76G 相关的输出，看不出地址冲突。**-G 版可以直接用标准 1.75 固件**，只是 GPS 不工作。

- 状态：未配对，正在以 `MuseGadget-XXXXXX` 名称广播 BLE，没有保存 Wi-Fi。
- 固件日志里会打印截断后的 token，分享日志前还是要把 `mgst_*` 打码。

### BLE 名改成 MuseGadget-VirusPC

- 想要的名字不带 MAC 后缀，用现成的 Kconfig 前缀/后缀选项做不到，只能改源码。
- 先查了 BLE 名的所有用到的地方：没有哪里会解析 `-XXXXXX` 后缀，名字放在扫描响应里，30 个字符以内都放得下。pairing 身份（node_id `homelink-XXXXXX`、device_id）依赖的是 MAC，跟这个名字无关。
- 补丁：新增 Kconfig 选项 `HOMEHUB_BLE_NAME_OVERRIDE`，默认留空；`identity_init()` 里只要它非空，就用它作 BLE 名。补丁提交在 SDK 克隆的本地分支上，也导出了 patch 文件。
- 只在板子 build 目录的 `sdkconfig` 里设置 `CONFIG_HOMEHUB_BLE_NAME_OVERRIDE="MuseGadget-VirusPC"`。注意这个文件不进 git：删掉 build 目录后要重新填 token 和名字。
- 重新编译、刷机，启动日志显示 `advertising as MuseGadget-VirusPC`，没有新的报错。
- 风险：用同一份构建刷多块板会重名，App 里不好区分，但配对本身不会受影响。
- 踩坑：刷完第一次看日志还是旧名字。对一下日志里的「Compile time」才发现看的是旧的输出，实际已经是新版本了。

### 配对与配网

- Muse App 打开开发者模式后添加设备，板子以 `MuseGadget-VirusPC` 被发现，配对成功，配好 Wi-Fi 后屏幕显示 READY。

### 语音发送失败：SAVED NOTE: WILL TRY AGAIN

- 录音本身正常：2.66 s，峰值 -24.5 dBFS，麦克风和编解码器都没问题。
- 失败在发送：板子连 `api.muse.ai`（Meta 的服务器）时 TLS 建连超时（`select() timeout` → `ESP_ERR_HTTP_CONNECT` → `CAN'T REACH MUSE`），于是把录音存在本地，之后自动重试，最多 8 次。
- 板子当时连的是手机热点，走运营商网络，访问不了 Meta。不是固件或 token 的问题。

### 找一个能连上 Meta 的 2.4GHz 热点

逐个排除：

- 手机热点：访问不了 Meta。
- 企业 Wi-Fi：要账号密码（WPA2-Enterprise），Muse App 配网只能填一个密码，用不了。
- minigtr 开热点：网卡（RTL8852BE）支持一边连网一边开热点，但热点只能和当前连接同信道。minigtr 连的是 5GHz，ESP32-S3 只支持 2.4GHz，看不到这个热点。
- Mac mini 开互联网共享：网络条件合适（网线上网，能连上 Meta），但开 Wi-Fi 共享要管理员权限，macOS 26 上也只能在系统设置里手动点。
- **最终方案**：4070ts 有线接在 minigtr 共享的网络上，能连上 Meta。用 Windows 自带的「移动热点」开一个 2.4GHz、WPA2 个人级的热点，热点名和密码都用纯英文。4070ts 没有 SSH 服务端，热点由 IT资产管理在本机开启。

### 换网络后跑通

- 切 Wi-Fi 后板子卡死，串口也没有任何输出。用 pyserial 拉一下 RTS 重启后恢复。
- 启动后的流程：设备 token 刷新 → 找到 VM → TLS 连上 Muse 服务 → Noise 握手 → 聊天通道建立，用时约 3.8 s。
- 按住 BOOT 说话，Muse App 收到了语音消息。✅

### 回复没有声音

- 日志显示回复已经收到（两条文字消息，"21 s 音频"），但听不到语音，只能听到 UI 提示音。
- 原因：上游 2026-10-02 起只要文字回复（服务端语音模型下线了），去掉了 TTS 请求。固件按字数（16 字/秒，每条再加 2 秒）往扬声器里写一段静音，只用来控制字幕节奏，所以回复本来就不会出声。
- 要出声就得自己接一个 TTS 服务，把文字转成 MP3 交给现成的解码和播放代码。计划部署在 4070ts 上，暂时搁置。

### 字幕显示方块 → 打开中文字体

- 原因：默认字体只有 ASCII，中文都显示成方块。固件自带一套中文字体（GNU Unifont 16×16），开关 `CONFIG_MUSE_CJK_FONT` 默认是关的。
- 在 `devices/sdkconfig.muse-waveshare-s3-175` 和 build 目录的 `sdkconfig` 里都设成 `=y`，然后重新编译。build 目录的 sdkconfig 要原地修改，不能删，因为里面有 token 和 BLE 名。
- 固件从约 2.1 MB 涨到约 2.9 MB，4 MB 的 OTA 分区放得下。刷写时不擦除 flash，配对和 Wi-Fi 信息都还在。
- 用中文提问，字幕能正常显示汉字了。✅

## 坑点汇总

1. **网络是最大的坑**：板子必须连一个能访问 Meta 服务的 2.4GHz、WPA2 个人级 Wi-Fi。手机热点（国内运营商网络）不行，企业认证 Wi-Fi 不行，5GHz 不行。症状是录音正常，但屏幕显示 `SAVED NOTE: WILL TRY AGAIN`。
2. **Linux 开热点受信道限制**：网卡同时连网和开热点时只能用同一个信道，主机连的是 5GHz，热点也就只能开在 5GHz，ESP32 看不到。
3. **Windows 移动热点**：没有设备连着时会自动关闭，重启后不会自己再开。要关掉自动关闭得用管理员权限改注册表。热点名不要带特殊字符（之前有个名字里带弯撇号的 iPhone 热点就连不上）。
4. **切 Wi-Fi 后可能卡死**：重启一次就好。
5. **回复没有语音是固件的设计，不是故障**：上游已经去掉了 TTS，日志里的 "audio" 其实是静音。
6. **中文显示**：要手动打开 `CONFIG_MUSE_CJK_FONT`。
7. **token 安全**：token 是编译时写进固件的，存在 build 目录的 `sdkconfig` 里，不进 git。固件会把 token 打到串口日志里，抓下来的日志用完就删，分享前要把 `mgst_*` 打码。
8. **build 目录的 sdkconfig 不要删**：里面有 token 和 BLE 名覆盖，删了就要重新填。
9. **工具链安装**：国内用 Espressif 镜像和清华 pip 镜像。长时间任务用 nohup，不要用 tmux 前台跑。`export.sh` 和 `set -x` 不要同时用。
10. **串口抓取**：直接 `cat /dev/ttyACM0` 什么都读不到，要用 pyserial。用 RTS 重启板子就能抓到启动日志。看日志时先核对「Compile time」，确认是不是新固件。
