## 主题

这场在按机验收组网客户端与隧道客户端是否真正可用：用「主机 × Tailscale × cloudflared」矩阵逐行核对命令是否在 PATH、服务是否在跑；缺项补装，并区分「二进制在 PATH」与「已登录开隧」；修好换安装通道后残留的坏命令包装。

- 难点：控制台绿点不等于终端能敲到命令；卸图形版后 PATH 残留坏包装是高概率坑。
- 难点：`cloudflared` 装进 PATH 不等于已 login、已开隧道；凭证不能进聊天。
- 难点：修命令行包装时不能乱动正在跑的组网守护进程。

## 行动指南

### 主题行动指南

#### 背景

多机已加入组网，部分还跑隧道客户端；换安装通道、卸图形版或新机入网后，容易出现「控制台看起来在线、终端却找不到命令」或「二进制在 PATH 但从未登录开隧」。

#### 核心问题

如何按机验收组网客户端与隧道客户端真正可用——命令行能敲、服务在跑——并在缺项或错路径时有固定补齐步骤，而不是凭印象。

#### 核心解决方案

按顺序做：

1. 列出要审计的主机，做成「主机 × 组网客户端 × 隧道客户端」矩阵。不做：口头问「都装了吧」就下结论。
2. 逐行在终端核对：命令是否在 PATH、守护进程 / 服务是否在跑、节点是否在线。
3. 缺项则补装；装完仍须区分「在 PATH」与「已登录 / 已开隧」。不做：把「能敲到命令」当成隧道已开。
4. 若刚换过安装通道（例如卸图形版改守护进程），检查是否残留指向旧路径的坏包装，修好后再验。
5. 修命令行包装时不要乱动正在跑的组网守护进程。
6. 新主机入网时复制同一张矩阵做验收，标准含终端状态查询，不只看控制台绿点。

#### 验收标准

以后按本主题执行时，下列全部成立才算完成：

- 矩阵每一行有明确结论：已装 / 未装、在线与否、隧道进程或服务状态。
- 各机终端能执行组网状态查询（不仅控制台绿点）。
- 宣称要用隧道的机器：二进制在 PATH，且登录 / 开隧状态已知（未做则明确标「未登录」）。
- 换过安装通道的机器：无指向已卸应用的坏命令包装，或已记录待删路径。

### 细节与其他

#### 若 Windows 要用 Cloudflare 隧道

则：先确认 cloudflared 已在 PATH（当晚 winget 装上 **2026.9.3**，且明确未做 login）。在本机补官方 login，密钥走安全卡片，不进聊天。不做：在聊天里粘贴 tunnel token。

#### 若 Mac 仍命中坏 stub

则：

1. 确认有管理员权限。
2. 删除 `/usr/local/bin/tailscale`。
3. 执行 `hash -r`。
4. 再确认 brew 版 `tailscale status` 可用；**不要乱动**正在跑的 `tailscaled`。

不做：为修 CLI 而重启或重装整套守护进程（除非守护进程本身已坏）。

#### 若新主机入网

则：复制本审计表逐行勾选；验收必须含终端 `tailscale status`，不仅控制台绿点。

#### 若只看到控制台绿点就下结论

则：不够。补做终端状态查询与隧道进程 / 服务核对后再写入矩阵。
