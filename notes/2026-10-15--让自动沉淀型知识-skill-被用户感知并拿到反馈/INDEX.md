# 让自动沉淀型知识 skill 被用户感知并拿到反馈

## 背景

2026-10-14 晚，在调研阿里、字节、腾讯怎么搭团队知识库之后，用户提出一个一直没想好的问题：知识库做出来了，怎么让大家用起来。随后补充了具体情境：做的是一个 skill，在用户 coding 过程中自动沉淀经验和实用知识，但用户「很无感，体验不到」。接着追问：怎么提升用户的感知，并让他们给出有价值的反馈。

以下是讨论中助手给出的思路，属于观点和方案建议，未经实验验证。

## 让知识库被用起来

核心判断：别指望人「去用」知识库，要让它出现在人本来就在做的事里。

1. **嵌进工具，不另开入口。** 仓库里的 `AGENTS.md` 和规则文件能成，是因为 Agent 每次干活都会自动读；飞书知识问答也是在提问处直接给答案。先问：知识库能不能被日常用的 Agent、IDE、聊天工具自动读到。
2. **写入要顺手，最好是副产品。** 知识库多半死于没人写、内容变旧。从对话、PR、复盘里自动提炼候选，人只负责审核，比专门写文档更容易坚持。
3. **先服务一个高频场景。** 如新人上手、反复被问的问题、某个模块的开发；先让人尝到省时的甜头再扩。
4. **让「用了」看得见。** 答案标出来源条目；纠正时顺手写回知识库；盯一两个指标，如被 Agent 引用次数、重复提问是否减少。

## 自动沉淀型 skill 为什么「无感」

存和取都在后台发生，用户看不到它帮了忙，就会觉得它不存在。要在两个时刻让它被看见：存的时候和用上的时候。

- **用上时点名（优先级最高）。** 用到一条沉淀时说一句「按你上次记的约定，这里用 pnpm」，并附条目来源。
- **存的时候冒一行。** 任务结束时提示「记下了 2 条：……」，可一键撤销或修改。
- **定期回顾。** 每周汇总记了几条、被用了几次、避开了哪些重复问题。
- **开头给钩子。** 新会话或进入某模块时主动列出相关的 1–3 条记忆。
- **前后对比演示。** 同一问题在有无记忆时各跑一次并排展示。

## 把感知和反馈做成同一个动作

用户看到「记忆起作用」的那一刻，顺手就能反馈。

- 反馈挂在提示上，一键完成：👍 对 / ✏️ 改一下 / 🗑 不该记。
- 问具体的（「这条还准吗」），不问笼统的（「好用吗」）。
- 把用户的纠正当成最好的反馈：问一句「要不要更新成新规则」，直接写回。
- 记录沉默信号：被注入却总被推翻、或从未被用到的条目，是降权或删除候选。
- 让用户看到反馈的结果，例如「已按你上次的修改更新」。

## 结论与下一步

- 最小可行做法：在「用上时」的提示后加 ✏️ 修改入口，并统计每条记忆的使用次数和被推翻次数。
- 对 edges 的启示：edges 的「对话 → 候选 → PR 审核」解决了写入顺手；读取侧还缺「用上时点名」和使用统计。
- 未决：是否把「用上时说出来」写进相关记忆 skill 的提示词，用户尚未决定。
