# 4070ts 开机自动登录与远程控制


> 家里那台 Windows 台式机一重启就停在登录界面，远程工具全都连不上。这篇记录怎么查到原因、怎么让它开机就能被远程用上，以及随之而来的安全取舍。

## 背景

家里几台设备（Ubuntu 小主机 minigtr、NAS、Mac mini、装 RTX 4070 Ti Super 的 Windows 台式机 4070ts-win）通过一个交换机（集线器）连在一起，没有路由器。当晚先是担心交换机断电后各设备地址会不会变，接着想用 Tailscale 远程连上 4070ts-win，却发现它看上去“离线”，助手也没法远程把它叫起来。于是这场对话从“地址稳不稳”一路走到“Windows 重启后怎样做到无人值守也能远程使用”。

对话双方是用户与「IT资产管理」助手，时间为 2026-10-12 晚上（北京时间）。

## 主题

这场对话在办一件事：让家里的 Windows 台式机在断电、重启之后，不需要有人坐到跟前，也能被远程连上并执行命令；顺带把家庭有线网里各设备的地址固定下来，并想清楚“开机自动登录”带来的安全风险该怎么补。

- 难点一：Windows 重启后停在登录界面，很多程序（包括助手在这台机上的客户端、托盘里的各类软件）只有在用户登录后才会启动，所以远程看起来就是“离线”。
- 难点二：Windows 默认禁止回应 ping，单靠 ping 判断开没开机会误判；要看某个服务端口有没有回应才能确认。
- 难点三：系统自带的“自动登录”设置里，那个关键复选框在这台机器上被藏起来了，网上常见的“关掉仅允许 Windows Hello 登录”的办法在这个系统版本上并不存在开关。
- 难点四：自动登录意味着谁走到机器前都能直接进桌面，需要在“远程方便”和“本地安全”之间找平衡。
- 难点五：Tailscale 上线后一直走新加坡的中转服务器，延迟约 285～290 毫秒，没有建立直连，原因当晚未查清。

## 过程

### 21:12–21:14 交换机断电后地址会不会变

用户问交换机断电后各设备的地址会不会变。助手解释：交换机本身不分配地址。家里这套有线网没有路由器，是 minigtr（Ubuntu）通过有线口用 NetworkManager 的“共享”模式把网络分享出去，由它内置的 dnsmasq 给其他设备自动分配地址。所以：

- 只是交换机断电，一般地址不变；
- minigtr 重启，地址可能会变；
- minigtr 关着时，其他设备拿不到地址，只会给自己配一个 169.254 开头的临时地址。

助手给了两种固定地址的办法：一是在每台设备上手动设固定地址；二是在 minigtr 上做“按设备预留地址”，设备本身什么都不用改。用户选了后者，理由是不必逐台去改。

助手随后在 minigtr 的 NetworkManager 共享配置目录里新建了一份预留配置，为 NAS、Mac mini、4070ts-win 三台各写一条预留，沿用它们当前的地址；然后用一条命令把那条有线共享连接断开再连上，让配置生效。检查结果：各设备能 ping 通，配置目录确实被加载，NAS 挂载正常。

唯独 4070ts-win 不回应 ping（Windows 默认屏蔽），但它的远程桌面端口有回应——这反而说明它其实开着机，虽然 Tailscale 上显示离线。

### 21:16 用户要求“开启 Tailscale”

助手从局域网探测 4070ts-win：只有远程桌面端口（3389）开着；SSH（22）、WinRM（5985）、文件共享（445）都没开；助手在这台机上的客户端也离线。远程桌面需要 Windows 密码，助手不保存这个密码，所以没法远程替用户把 Tailscale 打开。

助手给出两个后续选项：在这台机上开启 OpenSSH 服务端，或者让助手客户端在这台机上常驻运行。

### 21:27 再次检查

用户自己去把 Tailscale 打开了。助手复查：Tailscale 已在线，但 ping 走的是新加坡的中转服务器，延迟约 285～290 毫秒，没有建立直连。

### 21:29 找原因：重启后卡在登录界面

双方讨论根本原因：Windows 重启后停在登录界面，助手客户端和各种托盘程序都要等用户登录后才会启动。Tailscale 的后台服务倒是可以在登录前就运行，但前提是打开它的“无人值守运行”（Run unattended）选项。

助手提了两个修法，用户两个都选：

1. 打开 Tailscale 的“无人值守运行”，让它不依赖登录也能在线；
2. 用 netplwiz 打开 Windows 开机自动登录，让需要登录后才启动的程序也能起来。

### 21:31–21:39 netplwiz 里找不到那个复选框

用户打开 netplwiz，却看不到「要使用本计算机，用户必须输入用户名和密码」这个复选框。

助手先建议去「设置 → 账户 → 登录选项」里关掉「仅允许 Windows Hello 登录」。但用户截图显示，这台机器的登录选项里只有 PIN、安全密钥、密码和“其他设置”，根本没有这个开关——助手之前的建议对这个系统版本是错的。

最终有效的办法：用管理员身份打开 PowerShell，执行

```
reg add "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\PasswordLess\Device" /v DevicePasswordLessBuildVersion /t REG_DWORD /d 0 /f
```

再打开 netplwiz，复选框出现了。取消勾选后，按提示输入两次**账户密码**（不是 PIN）。

期间助手解释：Windows Hello 指的是 PIN、指纹、人脸这一类登录方式；关掉“仅允许 Hello”只是额外允许用密码登录，PIN 照样能用。

### 21:41 重启验证

用户重启后，机器直接进入桌面。助手确认 Tailscale 在线（仍走中转），助手客户端也已连上（显示为这台机的本机名）。

### 21:42 担心“谁都能打开电脑”

用户担心自动登录后谁都能直接用这台电脑。助手解释：风险只在“有人能碰到机器”这一面；远程连接仍然需要各自的身份验证，自动登录不会让远程变得更容易被闯入。

补救办法：

- 离开时按 Win+L 锁屏，解锁需要 PIN；
- 把「离开后多久要求重新登录」从“从不”改成“每次”；
- 打开“动态锁”，配对手机蓝牙，人带着手机走远后自动锁屏；
- 或者干脆把 netplwiz 的复选框改回去：Tailscale 靠无人值守运行依然在线，但助手客户端就又得等登录后才启动。

助手推荐：在家里保留自动登录，配合锁屏和动态锁。

### 21:42–21:43 锁屏后还能不能远程干活

用户锁了屏，助手随即在 4070ts-win 上执行了一条命令，成功。结论：锁屏不会结束当前会话，命令行、文件操作、后台程序都照常运行；只有需要点鼠标的图形界面操作会被挡住。助手本身也不能在用户的电脑上点图形界面，只能执行命令和处理文件，所以锁屏对助手的工作没有影响。

### 21:44–21:45 用 iPhone 远程桌面连上

用户用 iPhone 上的远程桌面连进去，能看到桌面，而机器自己的显示器上却显示要输入密码。助手解释：远程桌面是用账户凭据登录后把会话画面传过来；Windows 同一时间只允许一个人交互使用，所以远程连着时，本地屏幕会被锁住。断开远程后，在本地用 PIN 解锁，之前打开的程序都还在。

## 结果

做成了：

- minigtr 上为 NAS、Mac mini、4070ts-win 做好了地址预留，minigtr 重启后地址也不会变；已验证生效。
- 4070ts-win 开机自动登录已打通，重启直接进桌面，Tailscale 和助手客户端都能自动上线；已重启验证。
- 确认锁屏不影响远程执行命令；确认 iPhone 远程桌面可用，以及它与本地屏幕的关系。

还剩：

- Tailscale 仍走新加坡中转，延迟约 285～290 毫秒，直连没建立，原因未查。
- Tailscale 的“无人值守运行”只是建议了，助手没有核实是否已打开。
- 4070ts-win 上的 OpenSSH 服务端没有开启。
- 锁屏策略（“每次”重新登录、动态锁）是建议，当晚未确认是否已设置。

没有回退。

## 所学

- 判断 Windows 机器开没开机，不要只看 ping，也不要只看 Tailscale 状态；去探它某个已知开着的服务端口（比如远程桌面）更可靠。
- “远程连不上”很多时候不是网络问题，而是机器停在登录界面，需要登录后才启动的程序都没起来。要分清哪些程序是系统服务（登录前就能跑），哪些是用户程序（登录后才跑）。
- 固定地址的两种做法里，选在分配地址的那台机器上做预留，好处是集中管理、各设备不用改；代价是一切依赖 minigtr 开着。逐台设固定地址则不依赖 minigtr，但要逐台改、以后换网也要逐台改回，所以没选。
- 让机器无人值守在线有两条路，可以叠加：只开 Tailscale 无人值守运行，能保证网络可达，但助手客户端仍要等登录；开自动登录，所有程序都能起来，但本地安全变弱。两个都做，是为了即使以后关掉自动登录，Tailscale 也还在线。
- netplwiz 复选框消失的原因，是系统开启了“无密码设备”策略。网上流传的“关掉仅允许 Windows Hello”开关在部分版本上不存在，此时改注册表那一项才有效。这次助手第一次给的建议就是错的，以后遇到要先确认用户界面上真有那个开关。
- 自动登录的风险只在本地：碰得到机器的人能进桌面。远程仍各自认证。锁屏不影响后台和命令行工作，所以“自动登录 + 及时锁屏”能兼顾两头。
- 远程桌面会占用唯一的交互会话，本地屏幕因此被锁；这是正常现象，不是被人入侵。

## 行动指南

### 主题行动指南

#### 背景

一台家用 Windows 电脑需要随时被远程使用（执行命令、传文件、远程桌面），但它可能断电或重启，旁边常常没人。

#### 核心问题

Windows 重启后停在登录界面，依赖用户登录的程序不会启动，远程看上去就是离线；而开自动登录又会降低本地安全。

#### 核心解决方案

1. 先确认机器到底开没开：探一个已知开着的服务端口，而不是只看 ping。
2. 让远程网络工具以“系统服务、登录前即运行”的方式工作（例如 Tailscale 的无人值守运行）。这是底线，即使不自动登录也能保证网络可达。
3. 如果还需要登录后才启动的程序（如助手客户端）常驻，就打开 Windows 自动登录。可选项：不开自动登录、每次远程桌面进去手动登录——没选，是因为助手不保存密码，无法自己完成。
4. 用锁屏把本地风险补回来：离开即锁屏、离开后每次都要求重新登录、打开动态锁。可选项：干脆不开自动登录——没选，是因为会让登录后才启动的程序失效。
5. 如果设备地址依赖某台机器分配，在那台机器上做按设备的地址预留，避免它重启后地址变化。可选项：逐台设固定地址——没选，是因为要逐台修改、维护麻烦。
6. 重启一次，从远程逐项验证。

#### 验收标准

- 机器重启后，无需任何人到场，即可在远程网络里看到它在线。
- 需要常驻的客户端在重启后自动连上。
- 锁屏状态下，远程执行命令仍然成功。
- 本地离开后屏幕会自动或手动锁住，解锁需要 PIN 或密码。
- 各设备地址在分配地址的机器重启后保持不变。

### 细节与其他

#### 若 netplwiz 里没有「要使用本计算机，用户必须输入用户名和密码」复选框

则：先看「设置 → 账户 → 登录选项」里有没有「仅允许 Windows Hello 登录」，有就关掉。没有这个开关（如本次 4070ts-win），就用管理员 PowerShell 执行：

```
reg add "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\PasswordLess\Device" /v DevicePasswordLessBuildVersion /t REG_DWORD /d 0 /f
```

然后重新打开 netplwiz，取消勾选，输入两次账户密码（不是 PIN）。

#### 若 Windows 机器 ping 不通

则：不要直接认定它关机了。Windows 默认不回应 ping，去探它的远程桌面端口（3389）等服务端口；有回应就说明开着。

#### 若 Tailscale 显示离线但机器其实开着

则：多半是停在登录界面、Tailscale 没以无人值守方式运行。在 Tailscale 设置里打开“无人值守运行”（Run unattended），或打开自动登录。

#### 若担心自动登录后别人能直接用电脑

则：离开按 Win+L；把「离开后多久要求重新登录」设为“每次”；用手机蓝牙配对开启动态锁。实在不放心就把 netplwiz 复选框勾回去，代价是助手客户端要等登录后才上线。

#### 若锁屏后需要助手在这台机上干活

则：照常进行。锁屏不结束会话，命令行、文件、后台程序都不受影响；只有图形界面点按会被挡，而助手本来也只做命令和文件。

#### 若用远程桌面连上后本地显示器要求输密码

则：这是正常的。Windows 同一时间只允许一个交互会话，远程占着时本地被锁。断开后在本地用 PIN 解锁，程序都还在。

#### 若家里有线网各设备地址需要固定（minigtr 负责分配地址的情况）

则：在 minigtr 的 NetworkManager 共享配置目录（dnsmasq-shared.d）里加一份预留配置，每台设备一条按网卡地址的预留，然后把那条有线共享连接断开再连上让它生效。验证：各设备能互通、配置被加载、NAS 挂载正常。注意 minigtr 关机时其他设备会拿到 169.254 开头的临时地址。

#### 若 Tailscale 一直走中转、延迟很高

则：当晚没有排查，作为遗留项。当前表现是走新加坡中转，延迟约 285～290 毫秒。

#### 若想让助手不经远程桌面就能远程管理 4070ts-win

则：可选在这台机上开启 OpenSSH 服务端；当晚提出了但没有开启。另一条路是助手客户端常驻，自动登录后已经实现。

## 补充说明

- 涉及设备：minigtr（Ubuntu 小主机，负责家里有线网的地址分配）、NAS、Mac mini、4070ts-win（装 RTX 4070 Ti Super 的 Windows 台式机）。公开版本已去掉所有地址、账户、网卡地址和机器编号。
- 端口对照：3389 远程桌面（开）、22 SSH（关）、5985 WinRM（关）、445 文件共享（关），为当晚 21:16 时 4070ts-win 的状态。
