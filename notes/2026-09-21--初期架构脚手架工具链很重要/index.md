# 项目初期：框架、脚手架、工具链很重要

来源：peng cheng（2026-09-21，MacBook Pro）。

## 结论

项目在**初期**就把框架、脚手架、工具链设计好，很重要。

## Why（据口述）

- **反例：** CLI 之前没有架构，越写越乱。
- **正例：** 深入完善架构之后跑了这么久，CLI 的架构也相对清晰，说明初期（或尽早）把骨架立住，能在长期演进里扛住扩展。

## How to apply

- 新模块 / 新 CLI 面：先定目录分层、入口契约、扩展点，再堆命令与业务。
- 已乱的代码：优先补架构边界（而不是继续在平铺上加命令），再谈功能。
- 交叉：edges CLI 多命令架构、脚手架/框架封装相关 backlog 与 ADR（若有）。

## 边界

- 这是工程体感笔记，不是某次具体重构任务单。
