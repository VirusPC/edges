# 2026-09-25--Mac mini 仅手机开启 ChatGPT Remote 与远程桌面

【背景】

人在外面，只有手机，想在家里的 Mac mini 上打开 ChatGPT，并准备开启其 Remote 能力。机器已登记为本机执行节点，助手能跑命令、截屏，但不能像人一样直接看见锁屏后的完整桌面操作（除非先解锁）。同时希望机器尽量不睡、不锁屏，方便以后远控。

【过程】

1. 用本机执行在 Mac mini 上打开了 ChatGPT 应用；当时并未登录，也没有代开 Remote。
2. 截屏发现机器停在登录锁屏（用户头像 +「输入密码」），ChatGPT 进程其实还在跑，但界面与设置都点不到。
3. 讨论「只有手机怎么操作」：可行路径是手机开 mesh VPN 后，用远程桌面客户端连回家解锁；大众产品里 Chrome Remote Desktop / TeamViewer / AnyDesk 更流行，Mac + 手机 + 自建隧道场景里 Jump Desktop 与 Screens 更贴。
4. 电源侧其实早已接近「不睡」：系统睡眠与关闭显示器多为永不；真正让人卡住的是「屏保/关屏后需要密码」（当时约 1 小时，后来命令行状态一度变成「立即」）。
5. 用户同意用管理员密码开远程能力：密码走安全输入框（不要贴在聊天里）。密钥在助手侧环境里不稳定，后来改从本机已保存的密钥卡取出使用（仍不落明文到笔记）。
6. 用管理员权限执行 Apple 远程管理 kickstart：远程管理已激活，相关代理在监听；经典屏幕共享守护进程曾启动失败，但远程管理通道可用。解锁键入密码后桌面恢复，可见 Codex/ChatGPT 已在前台且像是已登录。
7. 用户要求「禁止锁屏和休眠」：睡眠/关屏/磁盘睡眠与 SleepDisabled 已核对为关闭睡眠；「需要密码」在「系统设置 → 锁定屏幕」里仍显示为「立即」，命令行 `sysadminctl -screenLock off` 回报成功但状态对不上，需在设置弹窗里改成「永不」（辅助功能能扫到该弹出式按钮）。整理笔记时该 UI 点击因设置窗口状态变化未完成。
8. 同日另线：Artifacts 公网示例改域名与 CLI 固定 UA 的仓库 PR 已合入 main（与本次远控平行，记一笔便于对账）。

【所学】

- 「本机执行能跑命令」不等于「能操作图形界面」：锁屏会切断 UI 自动化与 Remote 开关，但进程与 Shell 往往仍在。
- 不睡和不锁屏是两件事：能源策略管睡眠/关屏；「需要密码」管的是醒来是否要重新认证。只关睡眠仍可能被密码锁挡住。
- 远控产品要按场景选，不要只问「最流行」：大众装机量 ≠ Mac + 手机 + mesh 隧道下最好用。
- 管理员密码绝不能发在聊天里；安全输入框的环境变量可能只在刚提交后的短窗口可用，持久化密钥卡更稳，用完要删临时文件。
- 新版 macOS 上 `sysadminctl -screenLock` 与「系统设置 → 锁定屏幕」可能不一致，以设置界面实际下拉值为准。

【行动指南】

- 若人在外面、Mac 已锁屏、只有手机：先连上家里机器所在的 mesh VPN；再用 Jump Desktop 或 Screens（或已装好的其他远控）连 Mac，在锁屏上输入开机密码；连上后若弹出「允许屏幕共享」，不在旁边时可让已登记的本机执行助手代点「允许」。
- 若要长期方便远控与代操作：在「系统设置 → 锁定屏幕」把「不活跃时关闭显示器」保持「永不」，并把「屏幕保护程序启动或显示器关闭后需要密码」改成「永不」；改完用 `pmset -g` 确认 sleep/displaysleep 为 0 且存在 SleepDisabled。接受代价是实体接触或远控会话可直接进入已登录桌面。
- 若要开 ChatGPT Remote：先确认桌面已解锁且 ChatGPT 已登录，再在应用内打开 Remote；锁屏状态下只 `open -a ChatGPT` 不够。
- 若助手要代跑 `sudo` / 远程管理：用安全输入或本机密钥卡，禁止把密码贴进聊天；操作后删除桌面与临时目录中的口令文件。
- 若再问「哪个远控最好/最流行」：先问约束（是否已有 mesh、是否只要 iPhone→Mac、能否先装 Host）；无 Host 且已开远程管理时优先 Jump/Screens；要大众方案再提 Chrome Remote Desktop 等。
