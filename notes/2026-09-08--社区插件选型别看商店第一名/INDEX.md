# 社区插件：商店第一名不一定该装，坏了也不要就地 fork

> 日期: 2026-09-08
> 来源: 换 Obsidian 隐藏文件插件时被纠正的几次判断

【讨论主题】
第三方插件不好用时，怎么选替代、怎么修，以及怎么读商店上的「热门」和「做了三年」。

【主要结论】
(事实与共识)

- 商店搜索第一名、下载量高，经常是**名字撞了**旧热门插件，不是维护更好。看 GitHub 星、最近有没有推送、issue/PR 有没有人回。
- 「这个项目做了 N 年」要拆开：仓库创建时间和**现在这个名字**从哪天开始。改名、抢 id，都会让页面上的 Created / 下载量说的不是你以为的那件事。
- 社区插件坏了，默认换维护中的替代或提上游。不要在本地拷贝里改它的打包文件——一更新就没了，也没问过该不该 fork。
- 表面上同一个「不显示」，底下可能是两条机制。修其中一条的补丁，不会自动修好另一条。

【认知更新】
(洞察与 Edge 雏形)

- 插件生态里，**名字是流量，仓库才是产品**。后发的可以占到搜索词，先做的可能被迫改名。
- 时间线类断言（「三年了」）出口前，对一下创建日期和改名记录，不要把目录页的 Created 当成品牌史。
- 给第三方打补丁是最后手段，而且要先问。就地 fork 看起来快，后面没法跟着上游走。

【行动指南】
(决策与后续动作)

- 再装社区插件：先看仓库活跃度，再看商店下载。
- 再修第三方插件：先查它自己的 issue/PR 和有没有仍在维护的替代，不要先改 vendored 源码。
- 说「这个东西很老/很新」之前，分开核对仓库年龄和名称年龄。

【补充说明】
(其他重要细节或备注)

这次的具体例子：Obsidian 显示点文件。商店里的 Show Hidden Files 占了旧名字，真正做了三年的那份改名叫 Unhide。漏显示里，嵌套点目录和「软链指向仓库里已有目录」是两件事。
