**背景：**
此前用户已提出：Edges 的 Skill 不要按细碎能力堆很多份，而要按模块收敛，每个模块对应一个 Skill，方便发现与维护。2026-10-27 讨论对外推广时，用户再次提出先重新梳理 Skills、方便大家接入，因此把原任务纳入推广准备主任务，沿用本卡，不另建同义任务。

本卡负责 Skill 组织与接入说明的调整；新用户完整接入体验由关联验收子任务验证。具体模块映射、命名和迁移处理在实施前细化。

- 主任务：[Edges 对外推广准备：实验、Skills 与场景案例](<../../../_default/backlog/2026-10-27--Edges-对外推广准备实验Skills-与场景案例/INDEX.md>)

**目标：**
Edges 对外、随包装发的 Skill 按模块划分，一模块一个 Skill，外部 Agent 能发现并执行相关能力。

**动作：**
- 盘点现有 Skill 的职责、触发条件与相互引用，形成按模块收敛的映射。
- 按确认映射调整 Skill 与必要说明，保留原有方法和边界的可追溯归属。
- 按仓库既有规则维护版本、变更记录和分发验证，并交给接入验收任务复核。

**完成标准：**
- [ ] 确认范围内的模块均有清晰的主 Skill 入口，原有职责与引用没有因合并而丢失。
- [ ] 接入、发现与执行说明和实际能力一致，完成所需的分发验证。
