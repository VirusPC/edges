定期审视 Edges 根目录及相关子作用域，从真实使用中识别可复用的系统二模块，并将确认后的共性沉淀为通用规范；当前只记录规范，暂不启用自动运行。

**Why:** 用户在递归目录设计中指出，现有目录本身能暴露值得推广的维护能力，例如 Tasks 可以提供跨作用域通用的维护任务管理模块。根目录 review 应帮助系统从实践中改善自己的组织与规范，而不只检查目录是否整齐。用户明确选择先记录通用规范，暂不启用自动运行。

**How to apply:** 依照 [README 的架构复盘规范](../../../README.md#架构复盘)，先盘点目录的实际职责、所属作用域与维护对象，再检查领域工作与自身维护是否混淆。识别通用模块时以真实用例为依据，说明适用范围、状态归属与共享能力边界，保留局部特性；不能仅按目录名推广，也不能把所有 Task 内容直接定义为系统二。产出目录职责表、问题和规范候选，允许保持现状；经确认的共性进入通用规范，迁移或协议修改另行落实，不因 review 自动执行，也不预建各层完整模块目录。
