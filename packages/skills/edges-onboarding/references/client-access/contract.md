# 接入核验契约

默认可写。每一层都要有人能看见的证据；Agent 只说「我加载了」不算通过。第 2 层（规则加载）与第 3 层（技能发现）分开验收。只有第 7 层是 Git 同步：所有接入都必须验收；某一层（含 Git）失败时记入报告，**不阻塞**其他层继续。

同名技能出现两个版本时：记下两边版本与路径，继续后面各层；不设权威、不强制同步。

未在目标客户端跑通下列步骤前，不得宣称该客户端「已支持」。

| 层 | 测试输入（在目标客户端发） | 通过的证据 | 不算通过 |
| --- | --- | --- | --- |
| 1 打开 / 绑定 | 「报告你当前的工作目录或项目根。」 | 路径是大脑仓库根，或客户端界面显示该路径 | 只说「已打开」 |
| 2 规则加载 | 不给路径，问一条只写在大脑 `AGENTS.md` 的约定 | 答出约定并给出路径或段落；或工具记录显示读了该文件 | 答案来自常识；说「我会遵守」 |
| 3 技能发现 | 列出 edges 技能，再点名唤起一个（Codex 用 `$edges`） | 列表里有；唤起后有读取该 `SKILL.md` 的记录 | 只凭名字描述功能 |
| 4 读 | 读一条已有笔记，给出相对路径和标题 | 路径存在，内容一致 | 编造路径 |
| 5 写 | 记一条临时 idea「接入测试-\<客户端\>-\<日期\>」 | `git status` 看到新文件 | 只在对话里写 |
| 6 跨会话 | 新会话读回那条 idea | 复述与文件一致 | 依赖上一会话记忆 |
| 7 Git 同步 | 提交并推送；另一份 clone pull 后读回 | 另一份 clone 看到同一条 | 只提交未推送 |

测完删除测试 idea，再提交推送。
