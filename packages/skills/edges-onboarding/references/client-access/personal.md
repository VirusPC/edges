# personal：Grok Bot 等 personal agent

首期重点：**Grok Bot**。Muse、Dot 等步骤待核验，未核验前不得写成已支持。

## Grok Bot 的接入模型

Grok Bot **没有「绑定客户端工作区」的概念**。不要要求它打开或绑定某个目录，也不要把「目录在共享电脑上」说成某个 Bot 专属或已绑定。

接入方式是：

1. 从**所有 Bot 共用的共享长期记忆**检索大脑仓库身份（例如远端仓库地址）与本地路径。
2. 按该路径先读 `AGENTS.md`，再按仓库规则访问材料。

共享长期记忆只是入口索引，不替代仓库规则；不为每个 Bot 各存一份独立配置。多个 Bot 访问的是同一个大脑，写入遵守并发约定（同一 checkout 内由 CLI 写锁防并发，多个写者可各用 worktree）和 Git 同步约定。

## 环境事实（Grok Bot）

- 同一用户的 Bot 共用一台云电脑（box）与同一文件系统；桌面各自独立。【环境】
- Grok Bot 的技能目录与大脑仓库里的 `.agents/skills` 是两套存放；clone 完成不等于技能已装上或版本一致。【环境】
- 尚无证据表明 Grok Bot 会在每个新会话自动读取共享记忆或大脑 `AGENTS.md`。【待试 · E1】

## 步骤

1. **定位大脑**：先检索共享长期记忆里的大脑仓库身份与本地路径。
   - 检索到且路径有效：使用该路径。
   - 路径失效：按仓库身份在可用候选中重新定位（例如核对各 clone 的 `origin`）；仍找不到再问用户。
   - 检索不到：按 onboarding「接入已有大脑」规则问用户。
   - 不猜路径，不重建大脑。
2. **写入共享长期记忆**：只在用户确认大脑位置后，写一条「个人大脑：仓库身份 + 本地绝对路径」。只作定位，不抄规则正文；不要写入未经确认的路径。
3. **技能**：使用已有 edges 技能，或按环境安装；大脑仓库与用户级全局安装皆可，不设权威。同名两个版本时记下两边版本与路径并继续（见 [contract.md](contract.md)）。
4. **规则入口**：被加载的 edges 技能按共享记忆中的路径先读 `<路径>/AGENTS.md`，再按仓库规则访问。技能正文只在被加载时执行；闲聊不会触发。
5. **核验**：按 [contract.md](contract.md) 跑七层；第 1 层对 Grok Bot 不适用，按该文件的说明给出可见证据。任一层失败记入报告，不挡其他层。

## 限制（必须告知用户）

- 未证实宿主会在每个新会话自动读取共享记忆或仓库文件。
- 记忆按需检索，技能按需加载；两者都不能保证「每次新会话一定读到 AGENTS.md」。

## 最小实验（验收时执行，标结果）

- **E1** 规则加载：新会话不提示路径，问一条只写在大脑 `AGENTS.md` 的约定。
- **E2** 技能发现：问 edges 技能版本，对照技能目录里的 `SKILL.md`。
- **E3** 跨 Bot：Bot A 写入并推送临时 idea；Bot B pull 后读回。
- **E4** 技能更新：大脑仓库技能升版后，检查 Grok 侧技能目录是否仍是旧版，记录所需同步步骤。
