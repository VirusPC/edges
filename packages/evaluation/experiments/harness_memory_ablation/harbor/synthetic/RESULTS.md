# 合成实验结论：区分了检索成本，召回率仍有天花板

在这套已冻结的合成场景中，**scoped 与 root 的 recall@5 均为 100%，分层没有显示召回优势；scoped 的平均总 token 少 35.75%，未缓存输入少 37.05%，Agent 时延短 15.87%**。因此这版数据具有资源开销方面的区分度，在当前模型和 180 秒预算下没有区分两组的检索质量。不能把这一结果写成真实场景整体收益已被证明。

正式 test 为 32 题 × 3 条件 × 3 次，共 **288/288 成功、零失败**；固定 12 路并发，整批 **28.31 分钟**，累计 **22,357,944 token**（含缓存输入，不含 dev）。此前 8 题的 24 次 dev 仅做执行与计量验收，没有据其分数修改测试题、gold、seed 或并发。

## 这次检验了什么

这套数据让作用域、覆盖关系和时间条件明确，加入大量同名与过期规则，扩大了目录发现的开销差异；同时保留跨域、根层及无关问题作为控制。局部题的词法基线本身就可满分，跨域和全局题存在词法与结构 oracle 的差距，但 gpt-6.1-sol 在本轮预算内仍全部检索命中。**离线基线能区分构念，不等于模型质量一定被区分。**

root 与 scoped 得到同一批正文、scope 和时间元信息；差异同时包含放置位置与发现索引。本轮支持的是这套具体导航协议在受控合成场景中的资源差异，不能单独归因于目录深度，也不是与所有经过检索过滤优化的扁平方案比较。工具轮次较少与资源降低同时出现，但没有通过额外消融验证机制；scoped 的平均正文暴露记忆数反而略高（6.84 对 6.30），不能解释成简单的“少读文件”。

此前[真实历史问题实验](../../../../reports/2026-11-09-harbor-memory-ablation.md)有 31 题，明确非根作用域仅 6 题；整体 recall、token 和时延差异区间均跨零。新合成集明确作用域更多、语料更大且 gold 更短，是另一种受控分布；本次结果不替代或改写真实实验结论，也没有把两批题混合计算。

所有实体与事实均由程序生成；dev/test 实体隔离，但共享模板和解析规则，不代表未知任务模板或真实任务总体的泛化。仅使用一个模型别名、一个配置和一次固定矩阵；提供方缓存没有隔离，总 token 包括缓存输入，不是按价格计算的费用。12 路并发下的原生 Agent 时延含共享资源与提供方调度影响，不能等同独立执行时延或纯文件系统耗时。

若后续目标是区分检索质量，需要另立更严格预算或更复杂任务的协议及新数据版本，保留本版作为成本诊断；不能在看过本次 test 后修改本版，再继续称其为未见测试。
