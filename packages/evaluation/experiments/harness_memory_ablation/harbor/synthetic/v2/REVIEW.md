# v2 数据形成与语义复核

数据作者与两名审阅 Agent 分工：一名审阅 12 dev，另一名审阅 36 test。审阅者先只看题面、时间、任务起点和记忆正文，保存独立预测与歧义记录的摘要后，才打开作者 gold。没有调用被评测模型获取成绩。这里是 Agent 审阅，不是人类专家共识；相同模型家族、共同说明与作者分布仍可能造成相关盲点。

## 冻结前的修订

1. 初始局部候选的结构化尾注暴露了操作名、适用字段及当前/无关分类，并存在受众表述冲突。完整 candidate01 删除这种尾注，保留正常记录与生效日期；修正请求者和受众的区分、题面提前解释别名的提示，以及负例正文直接宣布不相关的问题。
2. candidate01 的 dev 盲审有 10 题可确定的集合与作者一致，另 2 道短是非题在解盲前被判定为必要性或条件边界不足。test 盲预测与作者有 3 处集合差异，都是实际适用的带教旁支被作者排除；另有 2 题带教边界存在歧义。解盲后追加的必要性复核单独留档，不能算成最初的盲预测。
3. candidate02 将 8 道条件题自然改为解释完整的本轮安排，避免一条否定证据已经足够回答是非题、却要求三条全部命中。对应旁支明确限定消防撤离桌面推演，使用不同操作和目的，不能再凭隐藏的 `phase` 标签排除实际业务带教。两名审阅者确认三份证据各有独特必要信息。此阶段已知作者 gold，称为修订复核。
4. 必要性复核还发现 3 道 test 的后续操作不属于当前短请求：损耗材料不必包含采购授权，寄样替代说明不必包含之后的发货争议，当前订餐安排不必包含锁定后停领。candidate03 保留全部题面和正文，只将这 3 题的必要证据从 3 条改为 2 条。生成器允许场景声明 `required_units`，再由 oracle 展开依赖；其他现行记录可成为相关但当前不必要的近邻，不能默认全部计入 gold。

这些修订发生在所有 v2 模型试跑之前。没有根据分数改题、挑 seed 或要求某个实验条件胜出。candidate01/02/03、差异表、初始盲预测、解盲比较及修订复核原件保存在 Git 忽略的 `local/support/`；公开的摘要收据见 [review-summary.json](review-summary.json)。旧候选不作为已通过的数据版本使用。

## 审阅边界

审阅检查当前请求是否自包含、每条 gold 是否贡献不可替代的信息、近邻为何不适用，以及全库有无等价替代证据。固定 gold 集合无法表达多组等价充分证据；本版通过收窄必要性或明确请求范围处理已发现问题，不以“同主题”或“可能有用”代替必需性。

结构 oracle 仅证明所声明场景内部自洽。其条件翻转、时间界线、依赖及显式需求测试不能替代自然语言理解，也不能证明真实用户分布覆盖或模型区分度。初始自洽测试全部通过而语义复核仍发现问题，正说明两种验证必须分开。

数据中的 `reference_answer` 由必要记忆的决定段组成，未合入全部理由与边界段；它是便于追溯的摘录，不能充当完整答案金标。尤其历史“为什么”的解释可能在记忆正文其他段落。本轮不据此计算答案正确率。

所有 48 个实体场景共享 336 条候选记忆；dev/test 分开请求实体、会话和具体蓝图，但不是隔离的知识库。测试请求未被执行，不表示其实体记忆从未出现在开发试跑的候选库中。案例、蓝图和记忆条数均不能当作独立真实用户或独立生成机制数。其余适用范围见 [COVERAGE.md](COVERAGE.md)。
