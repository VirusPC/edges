# v2 test 未满召回的 trace 分析

**本次未满召回混合了三种情况：看到子层索引后未继续读取、在根层命中后结束，以及已读齐 gold 但最终选择与回答范围缩窄。不能将它们统称为检索没有找到文件。** 语义复核仅确认档案改名是无争议的必要规则遗漏；成果墙与食盒仍有必要性范围歧义。

分析对象为 [冻结 test](TEST_RESULTS.md)中全部 4 次正例未满召回，涉及 3 个场景，均在 scoped；另对照同三题其余 14 次有记忆条件下的满召回执行。全部执行本身成功；none 的结构性零召回不作为检索故障。这里只分析可见工具调用、返回内容、最终 ID 与答案，不推断隐藏思维。没有重跑模型或修改数据、gold、提示和原分。

## 先区分测量的阶段

当前 [评分实现](../../metrics.py#L167)中，`evidence_recall_at_5`、`marker_recall_at_5` 和 `content_recall_at_5` 都先与最终 `selected_memory_ids` 相交。因此 evidence recall 低，不必然表示正文从未进入工具返回。

事后另计算 `|gold ∩ observed_memory_ids| / |gold|`，仍先平均每题三次重复，再按 30 道正例等权。这个量只表示正文暴露，不证明完整阅读、理解或使用，也不替换冻结主指标。

| scoped 的阶段分解 | 数值 |
| --- | ---: |
| 正例题 / trial | 30 / 90 |
| 仅按正文暴露计算的覆盖率（事后诊断） | 98.89% |
| 冻结的最终选择 recall@5 | 97.78% |
| 正文未暴露对应的损失 | 1.11 个百分点 |
| 正文已暴露、最终未选择对应的损失 | 1.11 个百分点 |

两部分各占本轮 2.22 pp 算术损失的一半；这是按 gold 大小归一化后的分解，不是语义错误率。root 在这两个量上均为 100%。完整计数、18 次对照、前缀一致性检查与 trace 定位见 [trace-analysis.json](trace-analysis.json)。

| --- | ---: | ---: | ---: | --- |
| 档案改名 / 119 | 2/3 | 2/3 | 2 / 27.61 秒 | 已看到子层 gold 标题和链接，未读叶子正文即结束 |
| 成果墙 / 295 | 1/3 | 1/3 | 1 / 18.64 秒 | 只读根层记录，未继续发现子层 |
| 食盒 / 324 | 2/2 | 1/2 | 3 / 24.17 秒 | 正文齐全，最终 ID 与回答仅覆盖较窄范围 |

四次均正常结束，未触发 180 秒时限；最终只选 1–2 个 ID，未达到 5 个上限。关键工具输出未见截断，不能把这些差异归因为超时或没有 ID 容量。

## 档案改名：索引已经看到，叶子没有展开

问题：“把绒溪档案室的扫描件批量换成统一命名，目录位置先保持原样。”三条 gold 分别要求改名前预览/碰撞检查/确认、旧新名称与内容摘要留痕以便回退，以及只处理登记原件并排除缩略图、缓存和上传中临时文件。

低分 `trial-000119` 的轨迹：

1. `codex.txt:L6` 已发现当前 `AGENTS.md` 与 `workbench/AGENTS.md`。
2. `L8` 同时读取这两个索引。子层索引完整列出遗漏的《隐藏工作文件的界线》标题与链接；同一命令随后只读取根/当前层的四份正文，没有读取该 workbench 叶子。
3. `L9` 直接结束，只选预览与回退两条。答案没有已有的文件范围筛选规则；“批次范围未知”不能替代按登记清单筛选、排除临时件的约定。

同题 scoped repeat 3（`276`）在相近的第二次读取后，`L10` 继续读取 workbench 两份正文，达到 3/3；repeat 2（`63`）先遇到两处文件路径错误，随后修正并补读子层，也达到 3/3。这里仅说读取范围相近，119 与 276 的完整前两次命令/输出并非逐字节相同。

三个 root 对照（`263/90/226`）都先按对象名检索扁平索引，再批量读取六份同对象正文，包含全部 gold。**可确定的断点在“已暴露索引候选 → 读取该正文”。** 标题没有直接写“批量改名”、规则位于更窄的 workbench，可能影响继续读取的判断，但尚无控制变量实验确定原因。

还需保留适用范围边界：部分成功回答将该规则表述为“若涉及 workbench”。这说明路径与业务范围的解释也值得澄清；不过低分轨迹连正文都未读取，尚未完成基于正文的适用性判断。

## 成果墙：根层有答案线索，但没有继续向下发现

问题：“绛禾夜学堂这期成果墙还做成绩排行吗？请沿用上次定下的展示办法。”三条 gold 涵盖停用排名、自愿进步卡与授权细则，以及撤换/归还/电子副本再利用范围。

`trial-000295` 的唯一工具调用（`L6`）读取根层三份正文，只有《公开进度排行的停用决定》属于 gold；另外两份是带教与物料记录。输出完整、exit 0。`L7` 随即回答不排行、自愿分享一次进步、按提交时间轮换，只选择该一条 gold，没有发现子层进步卡和更深层撤换规则。

两个成功 scoped（`137/32`）的第一次命令及输出与 295 **逐字节相同**。它们随后执行 `rg -n '绛禾' workspaces/*/AGENTS.md`，找到目标子层，再逐层读取索引与正文，总计五次工具调用并选齐 gold。三个 root（`174/274/198`）在一处索引检索到同实体七条标题，批读五或六份正文，均选齐。

根索引实际被注入了用户上下文，但有 144 条记忆链接和 48 条子域链接。目标子域的说明只有：

```text
Scope workspaces/27d361203a — memory and narrower scopes under workspaces/27d361203a
```

该入口没有“绛禾夜学堂”等业务说明，两条缺失 gold 的明确标题要到下一层/再下一层才出现。这来自 [scoped 子域索引生成方式](../../run.py#L192)，不是正文缺失。root 的扁平索引则把所有同对象记忆标题放在一起。

**观察是“根层命中后结束”；“缺少语义说明的子域索引使继续检索更难”只是有依据的待验证解释。** 另外两次 scoped 成功说明材料可达，不能由一次低分证明分层必然失败。

语义上，如果任务问排名决定及替代展示形式，现有回答已有支持；如果要求完整展示生命周期，则缺两条。冻结提示要求“简述适用规则”，没有明确要求完整授权与撤换流程，因此保留 1/3 原分，但不无条件判定完整回答错误。

## 食盒：读齐了，最终选择与回答却变窄

问题：“青砾食盒库又有人建议默认续下一周的食盒，当时为何没采用，这轮订盒怎么安排？”两条 gold 分别是本人主动重新确认、不回复不生成订单，以及周四午后锁定、锁定前修改/撤回、锁定后候补与余量确认。

低分 `292/324` 和成功 scoped `108` 的**前三条命令及返回内容逐字节相同**：先读根层三份正文，按“青砾”检索子层索引，再读子层索引、现行锁定规则与早期试办规则。第三次输出（`L10`）为 1,830 字符，完整包含缺失 gold《备料数量的每周锁定点》的正文、日期与 marker，没有截断。

随后路径分开：

- `292/324` 在 `L11` 直接回答，只选默认续订撤回的一条。答案解释重新确认与个人周订范围，但没有周四锁定、修改/撤回、候补或余量确认。不是只漏填 ID、答案其实已经覆盖。
- `108` 继续读 workbench 索引和下层正文，再选齐两条 gold，并加入交接背景；答案扩展到订盒、锁定及交接流程。
- 三个 root（`93/50/262`）先按对象检索扁平索引，再一次并读六份相关正文，都选齐两条 gold 并回答锁定规则。

**这两次的发现与正文暴露阶段已成功，断点在最终选择/回答范围。** 额外探索是否促使成功回答扩展到完整流程，尚不能由 trace 证明。该问题也允许围绕“为何不用默认续订、替代机制是什么”作较窄解释；gold 选择较完整的订购流程范围，所以保留必要性范围歧义。

本例两次低分分别用了约 7.53 万 token，成功 scoped 约 12.96 万；较少探索、较窄回答和较低用量共同出现。这个同题观察不能证明普遍的成本—质量因果关系，也不能将节省全部解释为无损优化。

## 能得出的判断与下一步可检验项

本轮应分别描述正文发现、最终证据选择、答案事实覆盖及 gold 的必要性范围。当前某些名为 evidence/marker/content recall 的字段仍依赖最终选择，无法单独定位发现阶段。

这三个案例中，root 的成功路径都倾向先聚合同对象跨层标题，再批量读正文；scoped 多了一次“是否继续展开下层”的选择。但分层同时改变目录与发现索引，特别是本适配器采用 hash 子域和泛化说明，不能将全部差异归因于目录层级本身。

后续若单独立项验证，可优先考虑：

1. **指标分阶段**：另列正文暴露覆盖、最终选择覆盖和人工/语义规则覆盖；避免用一个 recall 字段代替全链路。
2. **索引内容消融**：在正文和预算相同的条件下，对比当前泛化子域说明与带业务语义的说明，验证根层终止是否减少。
3. **退出前覆盖检查**：从请求的动作、对象、范围和时间约束检查未读候选、已读但未选的必要规则；不要强制选满五条或无差别读所有材料。
4. **澄清任务与 gold**：区分历史决定/替代方案问答和完整执行前计划，并区分必要约束、可选背景、允许的等价充分证据。新协议另冻版本，不回改本次结果。

这些是由 trace 提出的后续假设，并未在本轮实现或运行验证。现有原分、协议、数据和语义裁决保持不变。

## 证据定位与复核范围

[trace-analysis.json](trace-analysis.json)记录每个对照 trial 的相对原始日志路径、SHA-256、工具完成行号、最终答复行号、已暴露/选中 ID、成本及前缀一致性。完整日志继续保留在原测试运行的 Git 忽略归档；公开分析不导出宿主路径、原始运行上下文或整份原生输出。

三位独立 AI Agent 分别审阅一个场景及其全部有记忆重复；这不是人类审阅共识，也不是新的独立样本。事后分解与原 [测试统计](reports/test-v2/report.json)核对一致，未生成“去掉歧义题后的修正分数”。
