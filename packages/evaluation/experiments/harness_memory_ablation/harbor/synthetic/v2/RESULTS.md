# 自然请求补充集 v2：开发诊断结果

**已补充 48 道纯虚构问题、336 条记忆；本次只执行 12 dev × 3 条件 × 1 次，共 36 次，零运行失败。36 test 保持冻结且未执行。** 本页是开发诊断，不是正式测试或真实世界收益证明，与真实历史数据及合成 v1 分别报告。

观察到 1 个有效的正例漏检场景，存在满分正例，但未达到预先声明的“至少 2 个独立正例场景非满召回”工程门槛。两个有记忆条件并非全部满分；现有证据仍不足以宣称稳定区分度或某种目录方案更好。门槛、题目和分数均未在观察结果后修改。

确认的漏检发生在一个表单改版请求：scoped 选中 1/3 必要记忆，另两条既未被选择，也未在已完成工具输出中暴露；回答没有给出电话号码遮盖和原字段/空值语义的具体约定。独立审阅确认这些是当前任务所需，已有一条正文不能替代它们。这是 1 个场景的观察，不能通过计算两条遗漏或重复 trial 扩大独立样本数。

## 严格集合指标暴露了协议边界

预先声明的附加诊断仍按原 gold 输出：[quality.json](reports/quality-v2/quality.json)中，集合精确匹配为 scoped 6/12、root 9/12；按实际选择数计算的 precision 分别为 74.58%、81.25%；gold 外选择分别为 8 次、4 次。两道空 gold 负例在两个有记忆条件下都选择了记忆，冻结的“负例误选率”为 100%。**这些是相对固定 gold 的算术值，不能直接解释为真实语义错误率或方案优劣。**

原因是 gold 定义为当前任务的必要证据，而冻结提示允许选择“与问题相关”的记忆，并没有限定最小必要集合。独立审阅在隐藏组名的情况下检查全部 24 个有记忆 trial，以及 9 个非精确集合的回答：12 次 gold 外选择均被用于正确说明历史、时间或适用范围，没有观察到将其错误施加为当前强制规则。

两道负例尤其说明这一点：取消过的闪光试验可以为柔和灯光方案提供历史背景；物料规则中“不覆盖文案”的范围说明可以用来解释为什么不增加流程。无必须遵守的专属约束，不等于没有相关事实。未来草案或旧办法也可能被正确引用来说明当前不能采用，不能仅凭记录未生效或不在 gold 就判定答案误用。

本轮不修改冻结数据、提示、分数或测试题，也不将这些回答复核变成新的答案正确率。结果材料将此列为运行后发现的标注/输出契约边界。正式使用下一版本前，应先统一“必要证据”“允许引用的相关背景”与负例定义，再重新审阅和冻结；不能沿用本次 strict precision/exact 数字证明能力差异。

## 用量、验证与材料

36 次运行的原生累计用量为 **3,589,187 tokens**：输入 3,569,779，其中缓存输入 2,812,288；未缓存输入 757,491；输出 19,408。缓存输入占总 token 78.35%。这不包含数据编写、主会话和审阅 Agent 的用量，也不是计费金额；提供方缓存未隔离。

129 项离线测试通过，生成产物独立重建逐字节一致。运行后的 2,232 项完整性、评分、原生计量、报告与资源检查零差异；协议时间早于模型执行，24 项冻结输入均匹配。36 份原生日志及 152 次 shell 命令另行做语义审阅。资源观测有采样缺口，不能据此宣称完整捕获峰值或不存在 OOM；具体证据及边界见 [VALIDATION.md](VALIDATION.md)。

数据设计、候选修订和调用模型前的审阅见 [REVIEW.md](REVIEW.md)，覆盖依据见 [COVERAGE.md](COVERAGE.md)。预运行审阅未发现阻断，不意味着运行后不会暴露新的协议问题。所有原生日志、候选版本及复核原件在实验的 Git 忽略区归档，公开报告只包含虚构数据、数值与方法说明。
