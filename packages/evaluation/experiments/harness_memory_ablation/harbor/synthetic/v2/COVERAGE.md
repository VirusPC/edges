# 补充合成集 v2：覆盖依据与验收边界

本补充集服务于“中文项目工作请求发生后，Agent 能否找到执行前需要的既有记忆”。它覆盖请求理解、证据关联、适用范围、历史决策和无关记忆排除，不测代码修改、发布、真实操作完成率或长期记忆写入。这里的覆盖是限定任务空间内的诊断覆盖，不是全部 Agent 工作的代表性抽样。

## 覆盖主张怎样建立

先说明任务范围，再给场景分类、取样依据、覆盖矩阵及未覆盖项。[HELM](https://crfm.stanford.edu/2022/11/17/helm.html)将选择的场景放进更大的分类体系，并明确遗漏；本集借用这一论证方式，不借用其数据或分数。

对每类请求，再检查能否识别错误机制，而不只检查一道题有没有答对。[CheckList](https://aclanthology.org/2020.acl-main.442/)将能力与最小功能、保持标签不变的扰动及有方向的变化交叉组织。本集据此检查同义改写、无关信息加入，以及适用条件改变后的证据变化。这些检查不是新增独立测试样本。

来源真实也不自动意味着覆盖广泛。例如 [SWE-bench 原始版本](https://www.swebench.com/original.html)明确从 12 个 Python 仓库的 issue/PR 构造任务，并用执行测试判断解决情况。本集同样披露来源边界，不将单一用户或少量模板称为完整目标总体。

## 真实请求提供哪些依据

本次来源画像仅分析既有真实数据的 **11 道开发题**，不读取真实 test 题面和逐题模型得分。v2 在知晓已公布的 v1 总体结果后设计，不能作为对 v1 假设的独立确认。来源是既有目的性筛选样本，分类由 AI 完成；它不是有代表性的用户调查，也没有估计真实场景总体频率。已发表的旧 test 结果仍不能作为新合成集的独立外部验证。

画像包含 8 道执行前检索、2 道记忆解释/比较、1 道普通知识负例；8 道从共同根开始，3 道只给仓库级上下文，没有深层目录题。Gold 中位数为 3、最大为 11，4 题超过 5。反复出现的特征是简短追句、多重意图、内容去向、外部动作边界，以及历史设计或迁移约束，未直接列出要查的记忆主题。

生成器只使用经审核的抽象特征，所有实体、事实、问题、记忆和标识重新虚构。私密原问、来源标识、路径及逐题画像不进入公开数据；生成程序不读取原始真实题或真实记忆。可公开的是聚合来源说明与合成题的逐题覆盖标签。

## 预先确定的补充矩阵

六类分别安排 2 道 dev、6 道 test，共 12 dev、36 test。配额用于保证诊断可见度，不表示这些类型在真实工作中各占六分之一。家族不是互斥的心理能力，一道题可以带多个难点标签。

| 主场景 | 观察依据或补充目的 | 必须由题目与正文支持的检索机制 |
| --- | --- | --- |
| implicit_workflow | 执行请求需要调用未在题面逐项列出的约定 | 从目标行动推导相关的流程和前置约束 |
| boundary_routing | 内容去向与外部动作边界 | 区分写到哪里、可做哪些动作、哪些约定只适用于别处 |
| historical_decision | 历史取舍、被纠正做法与迁移约束 | 识别仍有效的决定，分清旧方案与否定它的理由 |
| conditional_override | 对范围和变更的定向压力检验 | 条件、时间和受众不同导致规则适用性改变 |
| multihop_plan | 多意图请求的证据组合 | 经身份/依赖桥接找到不同来源的必要约束 |
| negative_near_miss | 为无关记忆排除增加诊断样本 | 创作请求与实务记忆的词面/业务近邻；不声称覆盖常识问答或已验证为困难负例 |

计划 43 题标为 `source_informed`，借用抽象请求特征但不宣称对应原题或代表发生频率；5 道深层起点题标为 `targeted_stress`，其中 dev 1、test 4。根/仓库级/深层起点在 dev 为 8/3/1，在 test 为 24/8/4；报告须同时列出起点与角色分层，不能将全 48 题都称作真实分布的复现。每题记录请求形式、意图显式性、起点类别、必要证据数量、冲突类型、语言形式及生成蓝图归属。正文审阅再确认标签与实际题意相符。

所有维度的笛卡尔积并不都可行，也没有在本轮穷举。覆盖表至少区分单维是否出现、重要交互是否出现、每格独立蓝图数和该格未解决的审阅问题；不能只凭各单维都出现过就声称组合覆盖完整。小格子的结果用于定位后续缺口，不据 1–2 题得出稳健子群优势。

## 区分度的验收

数据质量先于模型分差。每题须自包含到足以确定任务对象；短句可以自然，不能靠缺失上文让 gold 不可判定。必要证据、可选背景和无关记忆必须分清；非空 gold 要有正文依据，不以“可能有用”把所有相关材料都计为必要。固定 gold ID 集合不能表达多个等价充分证据集合，因此需检查每条 gold 是否贡献不可替代的必要事实；出现替代正文时不能为凑 @5 任挑一条，也不能强求模型读两份等价正文才算正确，应修订虚构场景使证据职责清楚或标为当前协议不适配。负例须逐项解释近似记忆为何不适用。

先做结构验证、独立语义审阅和离线词法诊断，再执行 dev。离线检索失败只说明该基线的局限，不是 Agent 的区分度证据。开发模型观察同时报告每题与每类的召回、证据命中、误选和成本，注明是否发生天花板或地板；一个显著均值差也不能替代题目效度。

主要质量指标仍是正例 selected/evidence recall@5。附加诊断在执行前声明：所选集合精确匹配、具有正文证据的集合精确匹配、按实际选中条数计算的 precision、额外选中数量。具有正文证据的集合精确匹配要求最终选择恰好等于 gold，且每条 gold 的正文均被返回过；允许探索中读取额外背景，不要求全部已读集合等于 gold。空选时 precision 为 N/A，负例正确弃选通过集合精确匹配表达；执行失败的质量为缺失。附加指标不替换主要指标，也不把正文暴露称为答案正确率。

开发工程诊断要求先确认完整执行，再对两种有记忆条件隐藏组名复核：若至少两个独立正例场景出现有效的非满分召回，同时存在可完整检索的正例，才记录“观察到质量测量空间”。错误须来自遗漏/误适用，而非坏 gold、缺上文、格式或运行失败。这是小规模诊断门槛，不是统计功效证明，也不是根据分差方向挑题的规则。

开发诊断不设 scoped 必须胜出的门槛。若两种有记忆条件仍全部命中，结论必须是当前配置下检索质量未被区分；不能只用成本下降宣布质量目标完成，也不能事后删题、重选 seed 或改正式集 gold 来制造优势。若发现语义缺陷，保留旧候选与变更理由；改动后另冻版本，不能复用已观察分数作为未见测试。

本轮计划只执行 12 dev × 3 条件 × 1 次，即 36 次模型试跑，复用既有 Harbor/Codex 版本、模型、180 秒预算与 12 路并发。它用于诊断数据，不提供正式效应估计；36 test 先冻结，未执行时不写测试分数。两条件正文、元信息、可见记忆集合和执行预算一致；不削弱 root 的发现入口，也不以更低预算单独限制某一条件。

## 独立性与尚未覆盖的部分

设计要求 Dev/test 分离实体、来源和具体任务蓝图，落地后须以蓝图簇及语义审阅确认，不能仅凭不同 ID 断言隔离。共享能力分类与作者设计规则仍限制泛化。换实体名或措辞产生的复本、同一场景的扰动、重复模型执行都不能作为新的独立场景数量。未来使用测试结果设计的下一版，也不再是对本版未见场景的验证。

核心补充题控制必要证据不超过 @5 容量，不能通过裁掉原本必要的 gold 达成这一点。真实请求中存在超过 5 条必要记忆，这部分是明确缺口；后续如加入，应单独报告可达上限或改用适合证据集合的指标，不把检索预算导致的不可达满分伪装成困难。

本集仍不覆盖多人群/多语言的真实使用比例、完整业务工作区、长期在线记忆产生与消费、用户澄清交互、开放世界证据缺失或端到端任务成功。尚不能提供“覆盖了真实任务的某个百分比”的结论，也没有以 48 题这个数量证明统计功效足够。

根起点题仍有可解析的目标对象，不能把“从根开始”直接等同真实记录里无法定位工作范围的情况。负例目前侧重创作请求，未完整复现真实开发画像中的普通知识问答。版本、带教和行政近邻使用共享的构造方式，语料条数不等于独立规则机制的数量。

覆盖性需从逐题矩阵、不同来源和任务蓝图数量、独审问题记录、各类结果及新增未见来源的验证持续累积。后续扩充应优先补已知空白和新失效机制，不只往已覆盖模板里增加更多实体。
