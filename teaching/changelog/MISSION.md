# Mission: Changelog

## Why
要为自己的项目维护一份清晰、可持续的 `CHANGELOG.md`，让同事和未来的自己一眼看出每个版本改了什么、该不该升级。

## Success looks like
- 能按约定格式为一次真实发布写出完整 changelog 条目
- 能区分 Added / Changed / Fixed / Deprecated / Removed / Security
- 知道 changelog 和 git commit、release notes 各自管什么

## Constraints
- 面向自己的项目实践，以写为主、读为辅
- 教学用中文；术语保留常见英文（如 Keep a Changelog）

## Out of scope
- 完整 semver 策略设计（可点到为止）
- Conventional Commits 全套工作流（除非后面 mission 扩展）
- 营销向 release notes 文案
