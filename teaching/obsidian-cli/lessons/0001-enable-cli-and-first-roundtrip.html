启用 Obsidian CLI，跑通第一次读写

本课目标（一次小小的胜利）：升级 Obsidian → 启用 CLI → 在终端里读出并追加一条笔记。完成后，你的终端（也就是任何命令行 AI Agent）就拥有了你笔记库的入口。

为什么值得 5 分钟

你的 mission 是让 ZCode 这类 Agent 直接操作笔记库。在此之前，Agent 只能把 vault 当普通文件夹改 markdown 文件——可行，但绕过了 Obsidian：索引、插件、链接解析都不知情。CLI 是 Obsidian 官方给 Agent 留的正门：它向正在运行的桌面应用发指令，读、搜、写都经过 Obsidian 本身（官方文档、产品页）。

一个关键认知：CLI 不是独立程序，它是「遥控器」——Obsidian 桌面应用必须开着。（dev.to 概览）

第 1 步：升级到 1.12.4 或更高

你现在是 1.11.7——那是 CLI 还需要 Catalyst 付费许可证的内测版。1.12.4 起 CLI 对所有用户（含免费）开放。

Obsidian.app → 菜单栏 → Check for updates（或设置 → 通用 → 检查更新）
升级完成后确认：/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' /Applications/Obsidian.app/Contents/Info.plist
应输出 ≥ 1.12.4

第 2 步：启用 CLI

设置 → 通用（General）→ 命令行界面 / Command line interface → 启用。Obsidian 会把 obsidian 命令装入你的 PATH。

# 验证：新开一个终端窗口
which obsidian     # 应输出路径
obsidian help      # 列出全部命令，这份列表永远是最新文档

第 3 步：第一次读写闭环

# 读：按名字定位，像 wikilink 一样，不需要路径和扩展名
obsidian read file="某篇现有笔记"

# 写：往每日笔记追加一条待办
obsidian daily:append content="- [ ] 跑通 Obsidian CLI 第一课 ✅"

# 验证：再读回来
obsidian daily:read

如果 daily:read 能看到你刚追加的那行，闭环已通：终端 → Obsidian → 你的笔记。

恭喜。从这一刻起，任何能执行 shell 命令的 Agent（ZCode、Claude Code、n8n 脚本）都能用同一组命令操作你的知识库。第 2 课我们把这套命令交给 Agent 实战。

检验一下（先凭记忆答，再试命令）

1. 你关掉了 Obsidian 桌面应用，只留终端。此时 obsidian read 会怎样？

2. 笔记在 projects/ideas/next.md，哪种定位方式最稳？

3. 想让创建的笔记不弹出窗口打扰你，加什么？
