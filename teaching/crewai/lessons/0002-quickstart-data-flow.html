朗读 Quickstart：topic 怎么进 Crew，report 怎么回 Flow

Narrate the official Quickstart Flow: main.py steps + crew.jsonc kickoff, without installing.

本课唯一目标：不装、不跑，也能对着官方 Quickstart 讲清楚——

  1. prepare_topic → run_research → summarize 各自干什么、靠什么触发；
  2. topic 从 self.state 怎样进 crew.kickoff(inputs=…)，报告又怎样回到 self.state.report 与 output/report.md。

第 1 课已建立 Agent / Task / Crew / Flow 四层心智模型；本课把它落到官方 Quickstart 的真实文件上。片段仍不是作业——读懂数据往哪走即可。

1. Quickstart 在搭什么

官方 Quickstart 原话：你会创建一个 Flow——先设定研究主题，再跑一个只有一个 Agent（带网页搜索的 researcher）的 Crew，最后在磁盘上得到一份 markdown 报告。 并重申：Flows are the recommended way to structure production apps——Flow 管 state 与执行顺序，Agent 在 crew 那一步里干活。

脚手架命令是 crewai create flow latest-ai-flow（本课不要求你执行）；生成物大致是：

  • src/latest_ai_flow/main.py — Flow 类与三个步骤；
  • src/latest_ai_flow/crews/content_crew/ — 内嵌 Crew：crew.jsonc、agents/researcher.jsonc、加载器 content_crew.py。
和第 1 课图 1 的对照：Quickstart 的 Crew 只有一个 Task，没有 context 接力；本课重点在 Flow ↔ Crew 的边界，不是 Task ↔ Task。

2. main.py：三步 + 两个 state 字段

官方用 Pydantic 定义结构化 state，再写一个 Flow[ResearchFlowState] （Quickstart · Define the Flow in main.py；state 概念见 Flows · State Management）。

步骤装饰器做什么动到的 state
prepare_topic @start() 入口：默认把主题写成 "AI Agents"（若有 trigger payload 则读其中的 topic） 写入 self.state.topic
run_research @listen(prepare_topic) 上一步结束后触发：把 topic 交给 Crew，等结果 写入 self.state.report = result.raw
summarize @listen(run_research) Crew 跑完后触发：打印报告路径（收尾） 只读（打印路径，不改 state）

顺序完全由装饰器串起来：@start 先跑；每个 @listen(前一步) 等前一步“产出输出”后再跑 （Flows · Getting Started）。 官方小结也写成同一条链：prepare_topic → run_research → summarize；state（topic、report）住在 Flow 上 （How this run fits together）。

3. 那一脚 kickoff：inputs 进、report 出

数据跨过 Flow / Crew 边界的地方，就在 run_research 这一行：

三句话串起来（官方三点摘要的展开）：

  1. 进：self.state.topic → kickoff_content_crew(inputs={"topic": …}) → 与 load_crew 读到的 default_inputs 合并后交给 crew.kickoff，填进 Agent / Task 里的 {topic} 占位符。
  2. 做：Crew 只有一个 Task：researcher 用 SerperDevTool 搜网，写出结构化报告。
  3. 出：Task 的 output_file 把报告落到 output/report.md；同时 result.raw 被写进 self.state.report，供后续 Flow 步骤使用。
和第 1 课对照：Crew 内部 Task 之间靠 context；Flow 步骤之间靠 @listen + self.state。跨过边界时，必须在那一步显式 kickoff(inputs=…) 并自己把 result 写回 state——框架不会自动把 state 整包塞进 Crew。

4. kickoff 时真正用到的 JSONC 零件

官方强调命名必须对齐：agents: ["researcher"] 会加载 agents/researcher.jsonc；Task 的 agent: "researcher" 把任务派给同名 Agent （Naming consistency）。

和本课目标相关的字段，只需要盯这几处：

  • {topic} 出现在 Agent 的 role/goal 与 Task 的 description——靠 kickoff 的 inputs 填；
  • agents: ["researcher"] + agent: "researcher" —— 名字对齐文件；
  • output_file: "output/report.md" + markdown: true —— 磁盘产物；
  • process: "sequential" —— 只有一个 Task，顺序执行也只跑这一条；
  • 没有 context（没有第二个 Task 可接力）；本页示例的 crew.jsonc 也没有顶层 inputs 默认值——主题完全由 Flow 的 kickoff(inputs=…) 灌入。

官方 Quickstart 最终搭出的是什么？

  1. 两个 Agent 协作且不放进任何 Flow 的独立 Crew
  2. 带 state 的 Flow 里嵌一个单 Agent Crew 出报告
  3. 只用 Agent.kickoff 且不定义任何 Task 的脚本
  4. 先写 classic YAML Crew 再手工改写成 Flow 教程
Quickstart 开篇：创建一个 Flow，设定主题，跑一个单 Agent 的 crew，得到磁盘上的 markdown 报告。见 Quickstart。

ResearchFlowState 里官方声明了哪两个字段？

  1. topic 与 report
  2. query 与 answer
  3. agent 与 output
  4. inputs 与 context
Pydantic 模型只有 topic: str = "" 和 report: str = ""。见 Define the Flow in main.py。

三个 Flow 步骤的触发顺序是？

  1. summarize → prepare_topic → run_research
  2. run_research → summarize → prepare_topic
  3. prepare_topic → run_research → summarize
  4. prepare_topic → summarize → run_research
@start 的 prepare_topic 先跑；run_research 监听它；summarize 再监听 run_research。见 How this run fits together。

topic 是怎样从 Flow 进入 Crew 的？

  1. 把主题写进 researcher 的 backstory 固定字符串
  2. 让下游 Task 用 context 列表自动去上游拉取主题
  3. 让 hierarchical 经理在分派时把主题自动代注入
  4. 在监听步骤调用 kickoff 并把 topic 当作 inputs
kickoff_content_crew(inputs={"topic": self.state.topic})，再与 load_crew 的 default_inputs 合并后交给 crew.kickoff。见 main.py 与 content_crew.py。

报告回到 Flow / 磁盘的路径，官方描述是？

  1. 报告只进 state，磁盘上的文件还得自己手动另存
  2. 任务写入报告文件，同时把原始结果回写到 state
  3. 收尾步骤自己 open 文件，把正文直接写入磁盘
  4. 持久化装饰器在流程重启之后自动去生成报告文件
官方两点并行：Task 的 output_file 把报告落到 output/report.md；run_research 把 result.raw 赋给 self.state.report。summarize 只打印路径。见 How this run fits together。

agents: ["researcher"] 在命名约定下会加载哪个文件？

  1. agents/researcher.jsonc
  2. config/researcher.yaml
  3. tools/researcher.jsonc
  4. crews/researcher.json
Naming consistency：agents: ["researcher"] loads agents/researcher.jsonc。见 Naming consistency。
