# Project Memory Ask

只检索当前项目的文件记忆，不写入。

## 结构

`AGENTS.md` 是每个目录的记忆入口，里面有两类链接：指向**本层记忆入口**的，和指向**下层**记忆目录 `AGENTS.md` 的。下层按记忆层级算，一条链接可能跨好几层目录。

一份 `AGENTS.md` 管它所在的目录连同整棵子树，越深越窄，下层是补充而不是覆盖。所以**一个文件相关的记忆，就是从记忆根到它所在目录这条链上的每一层**，叠加着看。

本层记忆再按类型分成几份入口，每份只列该类型的记忆文件——所以 `AGENTS.md` 到任一条记忆固定两跳。**每一跳都按链接后面那句说明挑，那句话就是判据**：入口后面写的是这份收什么，条目后面写的是这条讲什么。别按文件名猜，也别因为只有几份就全打开。

**按你实际读到的内容走。** 有几份入口、叫什么名字、记忆目录叫什么，都随实现版本变，产物里写的才是准的；冻结的只有「入口逐层套、到记忆文件固定两跳、每项都带一句说明」这个形状（[`PROTOCOL.md`](../project-memory-init/references/PROTOCOL.md)）。看不到本套结构就当这个项目没建记忆。

记忆文件里 `description` 一定有，就是条目后面那句；`name` / `updatedAt` 有则可用，没有就退回文件名、别按时间筛。

## 怎么查

- 用户提问时就查，不用等他说「搜索」。本轮已经查过、或者他只是让你按指定文案改字，跳过。
- **先定这次的工作范围**：用户点名的路径、当前在改的文件、上一轮动过的目录都算；只给了模块名或功能名就先定位到目录。然后取这几个目录各自那条祖先链上的记忆层，取并集——需要的多半已经在上下文里。不要从记忆根开始逐层猜，也不要打开工作范围外的兄弟层。范围实在定不出来，就只用记忆根那层。
- 先读索引，再按说明挑要打开的正文，不要因为索引小就把它列的条目文件全拉进来。
- 关键词自己从问题里提炼，不要照抄原句；复合问题拆开分别查。也可以对 `AGENTS.md` 链到的那个记忆目录直接跑 `rg -n -i <关键词>`。
- 先正面回答问题，答案末尾再列出这次真正参考过的记忆文件相对路径。什么都没查到就直说项目记忆里没有，然后用已有上下文继续，不要顺手去建。
