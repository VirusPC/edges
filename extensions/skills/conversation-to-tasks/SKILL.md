把对话里「谁下一步做什么、怎样算做完」整理成可贴进看板的任务草稿。

本技能 **只整理成文，不落库**。写入看板是另一步（例如之后调用 `edges tasks create` / `update`）。这与 `conversation-to-notes` 对称：笔记技能也不负责把笔记写进仓库。

正文主结构：**背景 → 目标 → 完成标准**；**动作**为可选项。

- **背景** 给人读：重点写 **产生这个任务的对话过程**——当时在谈什么、怎么落到要开这张卡、中间改过什么主意；并带上必要的现状、约束、关联。读完应能回到当时语境，而不是只看见几条出处标签。
- **目标** 写做成后的方向（短）。
- **完成标准** 写可核对的验收条件；这是后续 `/goal` 或循环工程的核心输入。
- **动作**（可选）：对话里已经谈清「怎么做」时再写；没有就省略，由执行方派发后再拆。

不写执行流水。

## 和另外两角怎么分

同一段对话可能拆出三类产物，不要揉成一张：

| 技能 | 回答的问题 | 产物 |
| --- | --- | --- |
| `conversation-to-notes` | 这次对话澄清了什么？ | 复盘四栏笔记 |
| `project-memory-remember` | 以后还该记住什么？ | 耐久结论（结论 → 为何 → 做法） |
| `conversation-to-tasks`（本技能） | 谁接下来做什么、怎样算完？ | 任务草稿（背景 → 目标 → 完成标准；动作可选） |

拿不准时：没有可指派的下一步、也没有完成标准 → 不要硬开任务，改走笔记或记忆。

## 什么时候用

- 对话里已经出现可接力的下一步，需要写成看板任务的形状。
- 需要把「怎么谈出这张卡」写进背景，方便人读懂语境；并把可验收条件单独写成完成标准。

## 什么时候不用

- 只要复盘或沉淀记忆 → 用 `conversation-to-notes` / `project-memory-remember`。
- 要把草稿写入 `knowledge/tasks/` → 不在本技能里做，交给落库步骤。

## 输入

- 原始对话（或足够完整的摘要）
- 可选：已知相关拉取请求、笔记路径、已有任务标识

## 步骤

1. **抽取工作项。** 从对话里列出可行动项；一条对话可以整理出多条、一条，或零条。若实质是笔记或耐久结论，改派对应技能，不要硬开任务。
2. **只读去重（可选）。** 用 `edges tasks list` / `edges tasks get <标识>` 查看开放任务。若已有任务覆盖同一意图，在输出里建议更新该条，不要近义新建。
3. **写正文。** 背景、目标、完成标准三栏必填；动作为可选。
   - **背景：** 给人读，核心是 **产生本任务的对话过程**。用几句连贯叙述写清：当时在讨论什么、谁提出了什么、中间如何收窄或改口、为什么最后要开这张卡。再补上必要的现状与可核对事实、预期收益或价值动机（如有）、约束与非目标、关联（对话 / 拉取请求 / 笔记 / 兄弟卡）。不要只丢「出自某某」的标签句；也不要把尚待实现的步骤清单写进背景。
   - **目标：** 做成后要达到的方向，一两句即可。写「做成什么样」，不写步骤；预期收益放背景（除非收益本身就是可测成功指标，那时写入完成标准）。
   - **完成标准：** 可勾选、可核对的验收条件。优先能被命令、检查或明确观察证伪的条目。这是循环工程与 `/goal` 最需要的部分。
   - **动作（可选）：** 仅当对话里已经明确「准备怎么做」时才写——关键步骤、建议路径。没有谈清就整栏省略，不要为了凑栏而编步骤；也不要用动作清单代替完成标准。
4. **建议归属。** 用 `edges tasks project list` 选已有项目，不要自造项目短名（除非先问人）。默认状态为待办（`backlog`）。对话未点名负责人则不写负责人。
5. **只交草稿。** 输出标题、简介建议、正文、建议的项目与状态；可以说明「若落库大致会是哪条路径」，但 **不要写盘**，也不要调用 `create` / `update` / `status`。若需导出 `/goal` 一句契约，用「目标 + 完成标准」，必要时补上背景里的约束与边界。

## 正文模板

```markdown
**背景：**
（先写产生本任务的对话过程：当时在谈什么、怎么落到要开这张卡、中间改过什么主意；用连贯短句，让没参与对话的人也能读懂。）
- 相关现状或已有约束（可核对）
- 预期收益或价值动机（如有）
- 非目标：…
- 关联：对话 / 拉取请求 / 笔记 / 兄弟卡 …

**目标：**
做成后要达到的方向（一两句；不写步骤）

**完成标准：**
- [ ] 可核对条件一（优先能用命令或明确观察验证）
- [ ] 可核对条件二
- [ ] …

**动作：**（可选；对话未谈清做法时整栏省略）
- …
```

开头如需总述，可在栏目前加一句「解决什么 + 做成后怎样」，但不要用它代替完成标准。

## 约束

- 输出使用中文；栏名与说明都用中文，不要中英混写栏名。
- 写给人审阅，用白话完整句。
- 不添加对话里没有的新需求。
- 背景必须能让人回到「怎么谈出这张卡」；不要只有出处标签、没有过程。
- 背景给人读；目标给方向；完成标准给验收；动作可选且不能顶替完成标准。
- 禁止手改 `knowledge/tasks/`；禁止在本技能流程里调用写盘命令（`create` / `update` / `status`）。
- `list` / `get` / `project list` 仅用于去重与选项目。
- 不要把复盘四栏或记忆结论塞进任务，顶替背景。
- 不写执行流水（流水只进旁路日志，不进任务正文）。
