从对话整理任务草稿。**只成文，不落库**（写入看板是另一步）。正文：**背景 → 目标 → 完成标准**（必填）；**动作**可选。

## 步骤

1. **判是不是任务。** 对话里是否已有可接力的下一步？若实质是复盘或耐久结论，改派对应技能，停在这里。一条对话可以整理出多条、一条，或零条。
2. **只读去重（可选）。** 用 `edges tasks list` / `get` 看开放任务。同一意图已有卡 → 在输出里建议更新该条，不要近义新建。
3. **必填门闩。** 自检背景、目标、完成标准是否都能从对话里有依据地写出。任一不足 → **先提问**（可一次问多栏，但问题要具体），等用户想清楚再继续；不要用「无」占位，也不要替人编。动作是可选栏，缺了不必追问。
4. **按模板成文。** 写出标题、简介建议与正文；字段怎么写见下方「各栏要点」与模板。再用 `edges tasks project list` 建议已有项目（不要自造短名，除非先问人）；默认状态待办（`backlog`）；未点名负责人则不写。
5. **只交草稿。** 交标题、简介、正文、建议的项目与状态；可说明「若落库大致会是哪条路径」，但 **不要写盘**，也不调用 `create` / `update` / `status`。若需导出 `/goal` 一句契约，用「目标 + 完成标准」，必要时补上背景里的约束。

## 各栏要点

- **背景：** 给人读。核心是 **产生本任务的对话过程**（当时在谈什么、怎么落到开这张卡、中间改过什么主意），再用短句补现状、约束、预期收益、非目标、关联。不要只有出处标签；不要把待做步骤清单塞进背景。
- **目标：** 做成后的方向，一两句。写「做成什么样」，不写步骤。预期收益放背景（除非收益本身就是可测成功指标 → 写入完成标准）。
- **完成标准：** 可勾选、可核对的验收条件；优先能被命令、检查或明确观察证伪。这是循环工程与 `/goal` 的核心输入。
- **动作（可选）：** 对话里已谈清「怎么做」时再写。没有就整栏省略；不要编步骤，也不要用动作顶替完成标准。

## 正文模板

```markdown
**背景：**
（先写产生本任务的对话过程：当时在谈什么、怎么落到要开这张卡、中间改过什么主意；用连贯短句，让没参与对话的人也能读懂。）
- 相关现状或已有约束（可核对）
- 预期收益或价值动机（如有）
- 非目标：…
- 关联：对话 / 拉取请求 / 笔记 / 兄弟卡 …

**目标：**
做成后要达到的方向（一两句；不写步骤）

**完成标准：**
- [ ] 可核对条件一（优先能用命令或明确观察验证）
- [ ] 可核对条件二
- [ ] …

**动作：**（可选；对话未谈清做法时整栏省略）
- …
```

开头如需总述，可在栏目前加一句「解决什么 + 做成后怎样」，但不要用它代替完成标准。

## 约束

- 输出用中文；栏名与说明都用中文，不要中英混写栏名。
- 写给人审阅，白话完整句；不添加对话里没有的新需求。
- 必填三项依据不足时先提问；可选「动作」缺了不必追问。
- 背景须能回到「怎么谈出这张卡」；目标给方向；完成标准给验收；动作不能顶替完成标准。
- 禁止手改 `knowledge/tasks/`；禁止调用写盘命令（`create` / `update` / `status`）。`list` / `get` / `project list` 仅用于去重与选项目。
- 不要把复盘四栏或记忆结论塞进任务顶替背景；不写执行流水。
