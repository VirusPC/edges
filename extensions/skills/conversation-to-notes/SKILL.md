将原始对话整理为结构清晰的中文复盘笔记。
文件名：`YYYY-MM-DD--主题简述.md`。
术语与已定决策见同目录 [CONTEXT.md](./CONTEXT.md) 与 [docs/adr/](./docs/adr/)。

## When to Use

用户说「整理对话 / 总结这次对话 / 整理成笔记」等时：先完成本 skill 正文，再入库 `knowledge/notes/`（私密 → `edges-private`）。

## Inputs

- 原始对话全文（或足够完整的摘录）

## Instructions

1. 识别核心主题；一场对话多主题时可写 **总览笔记 + 各主题笔记**，在补充说明里互相链接。
2. 文件名：`YYYY-MM-DD--主题简述.md`（用户本地时区当天，除非对话明确对应另一天）。
3. 全文用 Markdown 标题分层（`##` / `###` / `####`），**不要**再用【背景】等方括号栏名。
4. **背景**：为何开这场、意图与议题（不是过程流水，也不是判断升华）。
5. **过程**：时间线；小节标题带具体时刻或时间段；少评价。无时刻写「时刻不详」，不得改成纯主题归类。禁止把过程同义改写塞进所学。
6. **所学**：
   - **学习类对话**：知识点总结与边界判断。
   - **行动类对话**：内容优先放行动指南；所学可极短或写「无」。
   - **技术类笔记**（主题是技术问题、机制、排障、架构等）：必须讲清**技术难点**——难在哪里、为什么难、当时如何绕过或仍未解决；可放在所学，或写进主题行动指南的「核心问题」。不得只写步骤清单而跳过难点。
   - 不写按钮步骤，不复述过程，不把问题/方案堆在这里冒充行动指南。
7. **行动指南**（必须分层）：
   - **主题行动指南**（可泛化，不绑主机名/网段/脚本路径）：
     - `#### 背景`
     - `#### 核心问题`
     - `#### 核心解决方案`（编号步骤，可执行）
     - `#### 验收标准`（清单；当作以后当真任务执行时的完成判定）
   - **细节与其他**：每个点一个 `#### 若…` 小标题；正文写「则…」；复杂用列表。主机名、路径、账号、网段只出现在这一层。
8. **补充说明**：琐碎信息、对照表、参考链接（每条附说明）；可链接其它 note。
9. 白话完整句；禁止自创黑话、口头禅小标题、未解释的自创缩写。真实产品/协议名可保留。
10. 不在本 skill 里「升为 Edge」。
11. 输出必须为中文。
12. **入库**（灵活，不强制单一通道）：
    - 路径：`knowledge/notes/YYYY-MM-DD--主题简述.md`
    - 仓：`VirusPC/edges`（私密 → `edges-private`）
    - 文档类笔记：已授权助手可直接 commit/push（含 PR 分支），commit 带 `Co-authored-by: <本助手名> <grok-bot@users.noreply.github.com>`
    - 大范围代码改动仍走 Cursor cloud agent
    - 公开库先脱敏（无 Tailscale `100.x`、凭证、授权链接等）
13. 旧笔记不强制回写。
14. 落盘前可对照 edges 项目记忆（如 `project_conversation_notes_plain_rich_human_review`）；冲突以本 skill + CONTEXT/ADR 为准。

## Constraints

- 不添加原记录中不存在的新观点。
- 结构完整；某节确实无内容可写「无」。
- 禁止旧栏名：主要结论、认知更新、Facts–Insights–Actions、单独【相关链接】、方括号四栏名。
- 主题行动指南必须可泛化；验收标准必须可当任务完成判定。
- **技术类笔记必须讲清技术难点**（难在哪、为何难、如何处理或未解）；只列操作步骤不算讲清。
- 忌「记完四栏」交差；人看不懂就加长改写后再入库。

## Limitations

- 依赖输入文本提供足够语境。
