**背景：**
2026-11-10 在给简历写 Edges 项目介绍时，先复盘了 Harbor 记忆消融实验的读取端结果，再讨论分层记忆的适用边界。用户指出：分层记忆在模块划分清晰且相对固定的大仓业务开发中有检索优势，但在常常新增模块与项目的个人大脑场景，优势可能变弱；分层相当于把检索复杂度前移到沉淀环节，用写入成本换读取效率。对话还确认，现有实验只量化了读取端（token、用时、工具调用、召回），没有量化沉淀端（写入时的分类判断、归属错误率、结构变化后的迁移与维护成本）。因此单独开卡，评估沉淀环节的差异。
- 相关现状：合成 v1 在多作用域、强干扰的受控测试中，scoped 与 root 召回均为 100%，scoped 总 token −35.75%、Agent 用时 −15.87%、工具调用 −36.50%；v2 自然请求召回 97.78% vs 100%，未缓存输入 −22.76%，总 token 基本持平；真实历史请求（来自个人大脑）31 题仅 6 道落在非根作用域，整体优势尚未确立。详见关联笔记。
- 预期收益：补上沉淀端成本后，可以判断分层记忆的净收益，避免只根据读取端数字外推适用场景。
- 非目标：不重做已完成的读取端消融，也不改简历文案。
- 关联：同 Project 笔记 [分层记忆的适用边界：复杂度前移到沉淀环节](../../../notes/2026-11-10--分层记忆的适用边界复杂度前移到沉淀环节/INDEX.md)；读取端报告 `packages/evaluation/experiments/harness_memory_ablation/harbor/` 与 `packages/evaluation/reports/2026-11-09-harbor-memory-ablation.md`；既有卡「Memory 消融实验正式报告」。

**目标：**
量化分层记忆与根目录平铺在沉淀（写入）环节的成本差异，并与已有读取端收益合起来，判断两种组织方式在「结构稳定的大仓」与「频繁新增模块的个人大脑」两类场景下的净收益。

**动作：**（候选，对话里提出但尚未敲定实验设计）
- 设计写入侧任务：给定一条新经验，让 Agent 决定落到哪个作用域并写入
- 对比 scoped 与 root 的写入 token、用时、归属正确率
- 模拟模块新增或重组后的迁移成本
- 在结构稳定与结构频繁变化两类场景分别测
