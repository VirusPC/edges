**背景：**

为 Edges README 建立维护 Project 时，发现 notes/projects 的创建落点与其他模块不一致，随后通过 [PR #91](https://github.com/VirusPC/edges/pull/91) 统一了默认 `.edges/` 与 `--super` 的定位，并删除重复扫描。继续讨论给各模块的 `create` 增加 `--path` 时，又发现已有 get/update/delete 对显式路径的限制各不相同：有的限定所选模块，有的允许受管仓库内其他位置，有的依赖固定目录层级。

讨论曾提出让 `--path` 覆盖默认模块目录，但用户追问它与 delete 等操作是否一致后，进一步明确目标：各模块行为一致的前提下，尽可能受控，再保留兜底方法。因此不能把“有路径参数”直接等同于“允许任意位置”，也不能只让 create 放开而导致后续查询、修改或删除无法处理。

本次先记录高优任务，不继续实现。跨目录允许范围、兜底入口形式和具体参数优先级尚未定稿。

**目标：**

统一各模块的路径输入、默认定位与读写边界，让适用的本地节点 create 支持显式指定路径，并与 get/update/delete 的规则一致。常规操作尽可能受控，同时保留清晰、显式的兜底方法；路径解析与校验尽量复用公共函数，消除模块特例与重复机制。

**动作：**

- 核对各模块现有 create/get/update/delete 的定位与约束，区分默认行为、显式路径和兜底行为；上传资源等不同语义的命令单独说明。
- 后续细化并确认默认边界、兜底适用条件及参数语义，再实施；不把此前“任意目录覆盖”候选当成已批准方案。
- 按确认后的契约复用公共定位与校验函数，同步相关读写入口、帮助文档和回归验证，避免创建成功却无法继续操作。

具体完成标准留待后续细化。
