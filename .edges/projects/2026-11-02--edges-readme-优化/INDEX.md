# Edges README 优化

## 背景

2026-11-02，用户提出建立专门项目，持续优化 Edges 框架的根 README。将后续发现的问题、文案与配图方案、审阅反馈和验证记录归到同一项目，便于跨会话接续。

## 目标

让第一次访问 Edges 的读者能清楚理解它是什么、为什么值得用、怎样通过 Agent 开始使用；准确表达框架当前能力与设计取舍，并让文字、配图、用例和导航保持一致。

## 范围

- 主要对象：[框架根 README](../../../README.md)及其[配图](../../../docs/assets/readme/)。
- 重点关注定位与价值表达、阅读顺序、术语解释、模块用例、接入指引和文档导航。
- 需要补充细节时，链接对应能力文档、CONTEXT 或 ADR；内容调整涉及这些文档时保持一致。
- 框架能力开发、独立推广文章与全仓文档重写另行安排，不由 README 优化自动扩展。

## 已有约定

本项目维护 Edges 框架自身，归入框架的 `.edges/projects/`，由本层 harness 索引发现。

以[根 README 方向记忆](../../../.edges/memory/projects/project_root_readme_direction/INDEX.md)中的当前有效决定为依据，后续新决定继续维护原记忆，避免本项目复制出另一套规范。

当前需优先延续的方向：

- 先说明嵌入项目骨架、以文件目录为作用域的 harness，再介绍按需跨仓复用；Git 管理版本，不定义 harness 粒度。
- 正文围绕「这是什么，能帮我做什么」「为什么值得用」「怎么开始」，细节按需展开，上手通过 Agent 接入。
- 延续已有五张配图及已确认的表达约定；具体改图需求单独说明。
- 通用框架定位与 Personal Harness 案例区分清楚；能力现状与规划分开，效果主张有依据。

## 推进方式

1. 阅读最新 README 与方向记忆，按读者理解、价值表达、图文一致、接入路径整理首轮问题清单。
2. 按影响排序，逐项记录问题、拟改内容与理由，形成可审阅的文案或配图方案。
3. 分批修改并用 PR 审阅；验证链接、图片、折叠内容与接入说明。
4. 把反馈与已确认取舍归回项目及原有记忆，保留后续待办。

## 每轮验收

- 读者能从前部内容回答用途、价值和开始方式，重点不被实现细节淹没。
- 定位、术语、模块职责与当前实现及已确认方向一致，不把计划写成现状。
- 文字、图示、案例互相补充，必要细节有可达的文档入口。
- 链接与图片有效，GitHub 渲染可读；实际变更经过用户审阅。
