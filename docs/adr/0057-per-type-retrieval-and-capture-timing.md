# 硬约束按材料类型分写检索与沉淀时机

2026-11-26 用户确认第四轮 grill：选择按类型各写一条时机句，并补充不同类型应该详细写检索和沉淀时机。本 ADR 取代 [ADR 0056](0056-reinit-snippets-and-uniform-timing.md) 第 3 点的统一时机句。0056 第 1、2 点仍然有效。

**Status:** accepted（尚未实现）

**Amended by** [ADR 0058](0058-module-naming-and-capture-initiation.md)（硬约束片段的点名层、审批闸门写法与沉淀发起方已定；六类官方呈现顺序以 0058 为准）

**Supersedes in part:** [ADR 0056](0056-reinit-snippets-and-uniform-timing.md) 第 3 点

## Decision

1. **按类型各写一条时机句。** 系统入口 `AGENTS.md` 的 `edges-constraints` 区块内，每初始化一个官方材料类型（Memory、Notes、Skills、Tasks、Routines、Projects），就增补该类型自己的官方片段。每个片段必须分别写清该类型的检索时机和沉淀时机（何时查、何时写），并点名经 `edges` 执行。不再使用 ADR 0056 第 3 点的「一条统一、不分类型的时机句」作为唯一种子。

2. **保留 ADR 0056 第 1、2 点。** 已初始化的仓库再跑无参 `edges init`，必须补装新进入默认集且尚未安装的模块。同一 `edges-constraints` 区块内，只增补缺失的、或仍等于官方原文的片段；不覆盖用户改过的句子，也不改区块外文字。不为每个模块拆独立的硬约束区块。

3. **共性原则仍适用。** 这些原则写进每一类片段，或作为各片段共同遵守的前提，二者皆可：按当前任务相关性检索已初始化的材料；本轮查过且输入未变则不重复；沉淀遵守该类型既有创建与审批规则；识别候选不是自动落盘授权；未初始化的类型不写入本层硬约束。

## Considered Options

- **A. 一句共用不枚举类型：** 否决。时机不够具体。
- **B. 枚举类型，并在装模块时改写同一句：** 否决。改写用户文本有风险，而且仍然不分类型细写检索时机与沉淀时机。

## Consequences

- 六类全装时，硬约束片段会更长，也可能重复措辞。接受这一代价。
- 各类型具体的检索时机与沉淀时机措辞留待下一轮 grill 确定。本 ADR 不定具体条文。
- 本 ADR 只取代 ADR 0056 第 3 点。0056 第 1、2 点不变。0056 曾否决「按已初始化类型逐条写时机与审批」；其中「不按类型写时机」不再有效。创建与审批仍遵守该类型既有规则，本 ADR 不改那些规则。
- 尚未实现。模板正文与各类型具体条文不在本次文档提交里。
