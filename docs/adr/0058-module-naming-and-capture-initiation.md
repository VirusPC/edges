# 六类硬约束片段的点名层与沉淀发起

2026-11-26 用户确认第五轮 grill。本 ADR 补全 [ADR 0057](0057-per-type-retrieval-and-capture-timing.md) 留下的各类型具体条文：点名到模块层，入口不点审批闸门，并定沉淀由谁发起。

**Status:** accepted（尚未实现）

**Amends:** [ADR 0057](0057-per-type-retrieval-and-capture-timing.md)

## Decision

1. **入口不点各类审批闸门。** 六类硬约束片段都只写「按既有创建与审批规则」，不在入口片段里点出各类审批闸门。例如不写任务「确认前不写盘 / 进 main 走 PR」，也不写例程「维护记录不等于获准配置外部平台」。细则仍在各模块文档里。

2. **点名到模块层。** 片段点名到 `edges <模块>`，例如 `edges tasks`。不只写 `edges`，也不写到具体子命令。

3. **managed 技能先提议，同意后再写。** managed 技能由 agent 提议，用户同意后才写。这比现行 remember 对 managed 技能的主动写收紧。实现时技能并入 `edges`，须同步改技能正文。

4. **笔记、项目、例程可提议一次。** 识别出候选时可提议一次，用户同意才写。不采用「只在用户要求时才写」。主动性仍然重要。

## 官方种子片段

以下是六类官方种子片段的推荐原文，作为设计约定。实现时若仅是抄写润色可微调，但规则不得变。六条都必须包含「识别出候选不等于获准落盘」。沉淀那半句都用「按既有创建与审批规则」，不点具体闸门。

**Memory：**
提问或动手前，从记忆根到相关目录逐层用 `edges memory` 查；本轮查过且输入未变，或只改文案，则不重复。用户要求记住、纠正你、给出约定，或结论已验证时，按既有创建与审批规则沉淀；识别出候选不等于获准落盘。个人偏好和密钥只进 `user` 类型；不检索就会做错事的规则写进硬约束区块本身，不另建记忆文件。

**Notes：**
话题可能已有笔记时，先用 `edges notes` 查；已有同主题的则更新原笔记。识别出应整理或应记的候选时，可提议一次，用户同意后才按既有创建与审批规则沉淀；识别出候选不等于获准落盘。

**Tasks：**
用户提到待办、进度或下一步，或要新开任务时，先用 `edges tasks` 查；已有同一意图的卡就沿用。可以成文提议开卡，背景和目标必须有对话依据；按既有创建与审批规则沉淀，识别出候选不等于获准落盘。

**Projects：**
给任务、笔记等选所属主题前，先用 `edges projects` 查已有 Project，有合适的就归入，没有合适的就不硬归。识别出应新建或应调整归类的候选时，可提议一次，用户同意后才按既有创建与审批规则沉淀；识别出候选不等于获准落盘。

**Skills：**
动手前先用 `edges skills` 查本层 managed 技能，有就按它做；`referenced` 只做索引，不改正文。同一串步骤做过第二遍时，可提议沉淀为 managed 技能，用户同意后才按既有创建与审批规则写入；沉淀的是流程，结论走记忆。识别出候选不等于获准落盘。

**Routines：**
提到定时、周期或例行工作，或要新建、改动例程前，先用 `edges routines` 查已有记录；同一职责已有就更新。识别出应创建或应修改的候选时，可提议一次，用户同意后才按既有创建与审批规则沉淀；识别出候选不等于获准落盘。

## Considered Options

- **入口只给任务和例程点出审批闸门：** 否决。六类都只写「按既有创建与审批规则」。
- **六类都在入口点出审批闸门：** 否决。细则留在各模块文档，不写进硬约束片段。
- **笔记、项目、例程不提议，只在用户要求时才写：** 否决。主动性仍然重要。

## Consequences

- 入口不复述各类审批细则。
- 实现时 skill 正文须同步 managed 技能的提议制。技能并入 `edges` 时一起改，不在本次文档提交里改技能正文。
- 「提议一次」指同一候选在当前任务中最多提议一次，用户已回绝则不再提。这约束笔记、项目、例程片段里的那一句。
