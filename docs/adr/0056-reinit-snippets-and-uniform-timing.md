# 存量默认集补装、硬约束官方片段与统一时机句

2026-11-26 用户确认第三轮 grill，三题均保持推荐项。本 ADR 补全 ADR 0055 留下的存量升级、硬约束写入方式和官方种子句式。

**Status:** Partially superseded by [ADR 0057](0057-per-type-retrieval-and-capture-timing.md)（第 3 点）

**Amends:** [ADR 0055](0055-layered-init-hard-cut-and-reach.md)

## Decision

1. **存量补装新默认模块。** 应用层默认集扩大后，已初始化的仓库再跑无参 `edges init`，必须补装新进入默认集、且尚未安装的模块。例如默认集纳入 routines 之后再跑一次，应创建 routines 材料。这与现行无参 init 遍历默认集并为其中每个模块落盘的行为一致，不把默认集理解成「只对全新仓库生效」。硬约束正文按第 2 条处理，不因补装而整块覆盖。已有仓库若要维持更小的模块集，须显式只初始化所列模块，而不是再跑无参 `edges init`。

2. **同一硬约束区块内按官方片段增补。** 系统入口 `AGENTS.md` 仍使用一个 `edges-constraints` 区块。装一个模块时，只向该区块增补缺失的、或仍等于官方种子的受管片段；用户改过的句子和区块外正文一律不动。不为每个模块拆独立的硬约束区块。也不再沿用「区块已存在就整块不动、因此无法给已改过的入口补一句」的整块粒度。

3. **官方种子用一条统一时机句，并点名走 `edges`。** 检索与沉淀时机写在硬约束里，不以 skill 的 description 为唯一依据。种子是一条统一时机句，点名走 `edges` 做已初始化官方材料的发现与沉淀；不写已切断的旧技能名，不把各类型创建与审批细则写进入口。未初始化的类型不写进本层硬约束。拟议种子大意如下，实现时可在不改变上述规则的前提下微调措辞：

   提问或动手前，按当前任务相关性发现已初始化的官方材料；本轮查过且输入未变则不重复。沉淀遵守该类型既有创建与审批规则；识别候选不是自动落盘授权。发现与沉淀走 `edges`。未初始化的类型不写进本层硬约束。

## Considered Options

- **默认集只作用于全新 init，已有仓库保持原模块直到显式 `edges <module> init`：** 否决。「默认全装」会只对新建仓库生效，存量永远缺 routines。
- **发现缺默认模块时只提示、不自动补装：** 否决。无参 init 应完成默认集，而不是改成只报警。
- **每个模块使用独立的硬约束区块：** 否决。入口会被拆成多块，增加系统入口格式负担。
- **保持现行整块粒度，已有区块不自动补句子：** 否决。作者仓和多数已改过的 AGENTS 将无法落实「装一个模块，才加对应的登记」。
- **按已初始化类型逐条写时机与审批：** 否决。各类型怎么审批已由 ADR 0054 规定沿用既有规则，不必在入口里复述。
- **只写「见 edges 技能」，不点名发现与沉淀：** 否决。与「时机必须写在 AGENTS.md」冲突，也违背入口要点名发现与沉淀的既有约定。

## Consequences

- ADR 0055 关于「默认集纳入 routines」的决定，由此补上存量升级路径。0055 关于「重跑 init 不覆盖已有硬约束正文」的决定，细化成：不整块覆盖；在同一区块内只增补仍官方的片段。
- 统一时机句与「按模块官方片段增补」如何拼在一起（一份不枚举类型的共用句，还是随已装模块改写列举句），不在本 ADR 范围内，留待下一轮。
- 尚未实现。模板正文、作者仓硬约束改写、bot 的 UpdateSkill 随实现进行，不在本次文档提交里。
