# 硬约束片段：共用主旨加按类型特殊点

2026-11-26 用户确认。本 ADR 修订 [ADR 0057](0057-per-type-retrieval-and-capture-timing.md) 与 [ADR 0058](0058-module-naming-and-capture-initiation.md) 中「每类一段完整片段、六段逐字重复共性句」的写法。

**Status:** accepted（尚未实现）

**Amends:** [ADR 0057](0057-per-type-retrieval-and-capture-timing.md)、[ADR 0058](0058-module-naming-and-capture-initiation.md)

## Decision

1. **共用主旨加按类型特殊点。** 硬约束区块由一段所有类型共用的主旨，加上各已初始化类型的一条特殊点组成。主旨只写一次。特殊点只写和主旨不同的地方。

2. **主旨在首次初始化时写入。** 第一次初始化任一官方材料类型时写入主旨，之后再装别的类型不改它。每初始化一个类型，补上该类型的特殊点。

3. **增补规则照旧。** [ADR 0056](0056-reinit-snippets-and-uniform-timing.md) 的增补规则适用于主旨和每条特殊点：只补缺失的，或仍与官方原文一致的；用户改过的句子和区块外的文字不覆盖。

4. **特殊点顺序。** 记忆、笔记、技能、任务、例程、项目。与 ADR 0058 第 5 点一致。

5. **共性只放在主旨。** 目录逐层查、走 `edges <模块>`、按相关性检索、本轮查过且输入未变不重复、沉淀守既有创建与审批规则、识别出候选不等于获准落盘，只放在主旨里，不再在每类重复。「逐层查」原先写在记忆片段里，现在改为所有类型的共同点。

6. **ADR 0058 的其余决定保持不变。** 入口不点审批闸门；点名到模块层；managed 技能先提议、同意后再写；笔记、项目、例程可以提议一次。0058 第 1–5 点仍然有效。0058 的六段原文不再是官方种子。

## 官方种子

以下原文直接采用。实现时若仅是抄写润色可微调，但规则不得变。

**主旨：**
材料放在本层 `.edges/` 下各类型的目录里，以 `.edges/README` 的登记为准，只认已经初始化的类型。读写都走 `edges` skill，按类型用 `edges <模块>`，不要手改受管理的目录和索引。提问或动手之前，按当前任务的相关性，从该类型的根目录到相关子目录逐层查；本轮已经查过、输入也没变，就不再重复查。沉淀遵守该类型既有的创建与审批规则；识别出候选不等于获准落盘。

**记忆：**
只改文案时不查。用户要求记住、纠正你、给出约定，或结论已经验证时才沉淀。个人偏好和密钥只进 `user`；不检索就会做错事的规则，直接写进硬约束区块。

**笔记：**
话题可能已经有笔记时先查；同一主题的就更新原笔记，不新开。识别出候选可以提议一次，用户同意了才写。

**技能：**
动手前先查本层的 managed 技能，有就照着做；`referenced` 只当索引，不改它的正文。同一串步骤做到第二遍时可以提议沉淀，用户同意了才写；沉淀的是流程，结论放进记忆。

**任务：**
提到待办、进度、下一步，或者要新开任务时先查；同一个意图已经有卡就沿用。可以写成文字提议开卡，背景和目标要有对话依据。

**例程：**
提到定时、周期或例行工作，或者要新建、改动例程时先查；同一职责已经有了就更新。识别出候选可以提议一次，用户同意了才写。

**项目：**
给任务、笔记选主题前先查；有合适的就归进去，没有就不硬归。识别出该新建或该调整归类的候选，可以提议一次，用户同意了才写。

## Considered Options

- **每类一段完整片段、共性句逐字重复：** 否决。这是 ADR 0058 的原写法。重复多、主旨不清。由本 ADR 替代。
- **一条统一时机句、不分类型：** 否决。这是 ADR 0056 第 3 点，已被 ADR 0057 否决。

## Consequences

- 官方种子改为一段主旨加六条特殊点。ADR 0058 的六段原文保留作当时记录，不再当作官方种子。
- 尚未实现。模板与 `AGENTS.md` 种子不在本次文档提交里改写。
