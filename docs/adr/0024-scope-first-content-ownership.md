# 递归节点与局部记忆归属

2026-10-04，用户要求重新确认此前的整体目录方案。本 ADR 从 `accepted` 改为 `proposed`：原方案已产生实现，但不能继续作为整套设计已获确认的依据。以下区分本次明确确认的原则与仍需重新讨论的细节。

## 已确认的修订依据

- **统一递归节点模型。** 以 Project Memory 为基础递归组织，不再以“独立目标、决策和验证责任”作为额外的节点资格门槛，也不把“作用域”和“模块”设为互斥节点类别。节点的具体识别规则仍待明确。
- **保留原有三块入口骨架。** 沿用“本层硬约束”“本层记忆”“下层记忆索引”及其本层规则、本层材料、递归下层入口的职责。下层入口可以跨物理目录层级引用。本层记忆如何承接 harness 扩展、具体章节是否改名，仍待讨论；不采用此前另提的五章节结构或“规则＋索引”结构。
- **子节点记忆保留原归属。** 子目录原有的 `.memory` 不应因布局升级而并入根节点。节点目录整体搬迁时，局部记忆随节点搬迁；跨层发现和复用通过引用实现。共享实现由根层维护，不等于局部上下文也必须集中到根层。

这些原则是重新审阅方案的依据，不代表完整替代方案已经确认，也不代表所有同名 `AGENTS.md` 的具体内容契约已经统一。

## 已撤回的推导

原方案及其实施中，下列判断不再作为后续设计或迁移依据：

- 以是否构成“独立责任作用域”决定一个原有节点能否保留局部记忆。
- 从“公共能力由根层维护”推导出 extensions、shared-extensions、notes、tasks、project-memory-init 的局部记忆应当上收根层。
- 通过“下层作用域”和“工作与模块入口”两类章节建立不同的节点身份，并据此撤除原来的本层与下层记忆索引。

此前逐项归属清单中的相应上收映射需要修订；不能继续用“已经逐项审过”或“测试通过”替代用户对归属的确认。

## 整体方案待重新确认

| 范围 | 需要明确的内容 |
|---|---|
| 节点与入口 | 统一节点如何识别；原层入口、类型入口和业务入口的关系；下层登记与跨节点引用的区别。 |
| 三块入口与 harness | 本层记忆如何承接维护材料；各模块和 type 的入口放在哪个区块；跨目录直达及按需建立的具体规则。 |
| 目录组织 | `.harness` 内部结构、推荐模块与局部扩展、Memory/Skills 类型布局，以及根目录调整的完整对应。 |
| 局部记忆恢复 | 按原节点核对被上收的正文、类型索引、人工说明和私有材料；原节点拆分等非一一映射情况单独明确，不能默认归根或复制多份。 |
| Tasks 与其他内容 | 领域工作和维护工作的具体落点、原 Tasks 节点自身记忆的归属、projects/teaching/evaluation/observation 等目录的迁移。 |
| 工具与迁移 | CLI 目标解析、init/ask/remember/doctor 的节点识别、索引生成、一次性迁移与恢复如何遵循重新确认的模型。 |

此前关于 `.harness`、managed/referenced、按需采用、工具约定路径和一次性迁移的讨论保留为复核材料。此次整体重审不表示这些选项已被全部否定，也不表示可据旧 ADR 的 accepted 状态跳过复核。

## 当前实现与本次文档修订的边界

[PR #161](https://github.com/VirusPC/edges/pull/161) 已按此前设计实现迁移，但仍包含本次被纠正的节点判断及局部记忆上收。迁移清单记录 43 条局部记忆从 5 个子目录并入根层，相关类型索引也被合并；这些文件尚未按新原则恢复。

[原实施计划](../superpowers/plans/2026-10-03-recursive-scope-layout.md)中的测试与完成记录只证明此前实现及其当时验收，不能证明满足本次纠正。本次修改的是决策状态和设计依据，不搬迁文件、不改变运行时，不据此宣告修复完成。

私有材料的保护、后续编辑的保留及 `knowledge/posts/` 的 AI 禁改约束继续适用。恢复方案需保留迁移前后依据，不能直接覆盖已经产生的新内容。
