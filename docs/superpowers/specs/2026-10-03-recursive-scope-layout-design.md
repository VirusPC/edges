# 递归作用域目录与迁移设计

日期：2026-10-03。状态：供整体审阅；尚未执行目录迁移或修改运行时。

## 目标与设计边界

以 Project Memory 的入口、索引和扩展机制为基础，使人和 Agent 能按作用域接手工作、保留记忆并维护自身。内容按所属作用域组织，领域工作与自身维护分开；通过引用形成 graph，公共实现保持单一真源。

本设计区分三件事：目录由谁拥有、在该作用域承担什么职责、其组织约定能否复用。一个可复用模块不因此成为每层必建目录，一个源码目录也不因此成为独立责任作用域。

已确认的取舍见 [ADR 0024](../../adr/0024-scope-first-content-ownership.md)。本方案对剩余布局细节采用以下具体落点供整体审阅：维护知识使用 `memory/`，技能使用 `skills/<type>/` 继续分类，容器总入口是否必经仍待确认；迁移 Skill 命名为 `project-memory-migrate`。

本次不拆 Git 仓库，不部署观测后端，不将所有模块改造成 Memory Type，不建立全局 JSON/YAML 类型注册表，也不启用定期目录 review 自动任务。

## 通用规则与按需扩展

通用部分规定作用域入口、硬约束、归属、索引与引用；各作用域选择需要的模块，并能登记自己的类型。Edges 当前实例的完整目录树不是通用模板。

以下是形状示意，未采用的模块不创建空目录：

```text
<scope>/
├── AGENTS.md
├── .edges/                     # 本作用域默认维护目录，按需要建立
│   ├── memory/<type>/          # 维护知识；类型开放
│   ├── skills/<type>/          # 技能容器下按类型组织，按需扩展
│   └── <维护模块>/             # 所选模块按自己的内容契约组织
└── <领域目录>/                 # 由本作用域的目标决定
```

- `AGENTS.md` 是人和 Agent 的入口，硬约束仍写在所属层入口的硬约束区块。
- `.edges/` 与其中的 `memory/` 是物理分组，不自动形成新的作用域，也不建立必经的中转入口。
- 仅在确有独立目标、决策和验证责任时再划分子作用域。记忆层保持稀疏，可以跨过普通目录。
- 领域任务位于所属作用域的 `tasks/`；维护该作用域的任务位于其 `.edges/tasks/`。Task Project 是看板分组，不自动成为项目作用域。
- 模块可以具有作用域特有的职责，也可以在实践中提炼成可复用规范。定期目录 review 负责识别这种共性，当前只执行规范，不自动运行。
- `CONTEXT.md`、`docs/adr/`、`docs/superpowers/` 和宿主固定入口保留约定位置，按所属职责引用接入。目录名本身不固定系统一或系统二角色。

### 维护记忆初始化

初始化显示少量推荐类型及用途，由用户选择，再创建所选目录和入口；可以通过既有类型登记机制追加自定义类型。推荐清单为：

| 展示项 | 现有类型标识 | 内容边界 |
|---|---|---|
| 上下文与决策 | `project` | 接手背景、理由与边界；硬约束仍在层入口，既有 ADR 引用原文 |
| 纠正与反馈 | `feedback` | 用户纠正、有效做法与禁止模式 |
| 参考资料 | `reference` | 外部资料及已有文档的指针 |
| 本地私有记忆 | `user` | 私有材料；正文和类型索引一并忽略提交 |

展示名不要求改变现有类型标识与条目前缀。Skills 作为可选容器独立于维护知识选项，继续向下分 type，具体推荐类型另行确定。迁移已有项目时不用新建推荐清单重置旧项目；按明确的容器/type 映射迁移，自定义类型身份保持。

## 入口、类型索引与模块发现

沿用 Project Memory 的硬约束、本层索引和下层索引区块，不因为物理目录变深而增加检索层级：

```text
作用域 AGENTS.md
  → .edges/memory/<type>/AGENTS.md
    → 该类条目
```

维护知识仍是两跳到正文。`memory/` 不另建必经索引，类型入口不承担独立作用域硬约束。技能同样在容器下继续分 type；推荐由作用域入口直接链接 `.edges/skills/<type>/AGENTS.md`，但是否保留必经的技能总入口尚待确认。类型划分不改变不同来源的维护边界，具体规则见下节。

物理分组调整不要求废掉现有 Skills 类型适配。自定义普通类型或 Skill 格式类型保持类型身份及独立命名空间，默认在 `.edges/memory/<原复数目录>/` 保留；不能仅因格式相同就自动归入技能容器。

在 Project Memory 受管区块外使用 `AGENTS.md` 的共享文件扩展点，列出本层工作与模块入口：领域任务、维护任务、评测、观测及原位文档。各模块继续维护自己的业务索引；模块入口不自动登记为记忆子层。Task 可以沿自己的 Task Project 索引继续查找，不受普通记忆两跳规则约束。

这批变更应主要落在 LAYOUT、路径解析、索引生成和模块接入中。不得用全局替换 `.memory` 的方式改造解析器：作用域定位、children 索引、外部技能真源、doctor 扫描和 Git ignore 都需按新布局适配。

CLI 的目标契约是先明确所操作的作用域，再明确模块及领域/维护用途。源码所在位置不作为操作目标。具体命令参数由既有 scope-first CLI 工作衔接；本次目录迁移交付必须保证新真源可被相应命令操作，不能迁完目录再留下仍向旧路径写入的调用。

### Skills：统一容器，按 type 继续组织

用户澄清：Skills 应像 Memory 一样继续向下分 type。因此 `skills/` 是与 `memory/` 并列的容器，不是将所有技能压成一个官方类型。上一版“取消下层分类、统一为一个 skills Type”的设计已撤回；具体 type 名称、分类依据及旧类型映射仍需细化。

```text
.edges/
├── memory/
│   └── <type>/
│       ├── AGENTS.md
│       └── <记忆正文>
└── skills/
    └── <type>/
        ├── AGENTS.md
        └── <name>/SKILL.md       # 本地受管正文；也可索引原位真源
```

容器不自动构成新的责任作用域。类型开放、按需建立；这里的 `<type>` 表示分类扩展点，不是必须创建的占位目录。来源和维护权限仍需单独判断，不能仅因某个条目放在技能分类索引里就授权改写原位正文。

#### 入口方案：待确认

此前提出“共用一份 AGENTS.md”，本次补充下分 type 后，需要明确共用入口处于哪一层：

| 方案 | 发现路径及取舍 |
|---|---|
| **作用域入口直接链接各 type（推荐，待确认）** | 作用域 `AGENTS.md` → `.edges/skills/<type>/AGENTS.md` → 正文；与 Memory 同构，保留两跳，容器不另设必经总入口 |
| Skills 总入口再链接各 type | 作用域 `AGENTS.md` → `.edges/skills/AGENTS.md` → `<type>/AGENTS.md` → 正文；保留一个技能总入口，但变成三跳，须明确调整技能导航契约 |

不能同时承诺必经的容器总入口、每 type 入口和固定两跳。推荐方案将“共用 AGENTS”解释为同一 type 共用一份索引，是否采用此解释仍待用户确认；不把它当成用户已经明确的原意。

#### 分类、来源与正文

本轮确认的是容器下面可扩展 type，尚未决定按来源、用途或其他领域语义分类，也未决定旧 `skills` / `agent_skills` 的新 type 名称。不要提前将 `local/installed`、`human/agent` 或一套用途分类写成默认类型集合。新建时按选择创建，已有自定义类型及其内容格式和权限继续保留；不能只因采用 Skill 格式就自动改挂到技能容器。

归入技能容器的本地技能目标形状为 `.edges/skills/<type>/<name>/SKILL.md`，完整保留 scripts、references、assets 等附属文件。原位接入技能的正文仍在 `.agents/skills/` 或其链接指向的共享真源，由相应 type 索引发现，不复制正文。

索引发现与宿主安装分别处理：本地方法尚未安装时仍可经入口阅读使用；需要宿主加载时走既有安装或链接机制。类型划分不自动改变安装目录，也不定义宿主对同名技能的覆盖优先级。

只汇总当前作用域明确接入的来源，不递归吸收子作用域或自动扫描全机技能。相同实际真源的多个安装别名不重复产生技能实体；同名但不同真源保留并消歧。正式类型归属与跨类型引用不能仅靠名称或来源推断，具体映射在类型方案确定后登记。

#### 工具与迁移边界

- 初始化登记所选 type 的入口；不生成具体技能占位，不隐式安装，也不为缺失的安装目录补建内容。
- 写入操作必须先确定作用域、技能 type 与本地受管目标；不能只给容器名就按同名索引猜测写入位置。具体 CLI 参数留到类型契约确定后设计，不沿用“一个 skills 类型、一个本地写入根”的旧假设。
- Project Memory 的正文写入仅限经实际路径验证的本地受管来源。符号链接不能授予额外权限；原位接入正文由原有维护机制处理。
- doctor 可按授权修复受管索引及本地受管内容，原位正文和安装链接仅诊断；不可读来源、断链与真正的空来源分别报告，不把不完整扫描算作成功。
- 迁移前明确旧类型到目标容器/type 的映射，保留正文、附属文件、来源权限和自定义类型；不再预设旧 agent_skills 类型直接消失。尚未确定的分类不自动迁移。
- 安装入口位置和外部真源保持原位。只有指向本次已迁本地正文的安装链接，可由迁移器按明确映射更新目标；不沿指向范围外的安装目录链接扩张写入。正常 init、remember、doctor 不获得修改安装链接的权限。
- 旧索引的人工说明、非受管内容及无法重新发现的引用须安置或列为冲突。迁移冲突按实际目标路径判断，不按同名技能判断；重复运行不覆盖新内容。

若采用推荐入口结构，可沿用 PROTOCOL 的层入口到类型入口再到正文的形状，LAYOUT 和解析器需区分容器、type 与内容来源。若选择必经 Skills 总入口，须同步明确协议与消费者的导航变化。实现前补齐类型登记、索引生成、写入定位、doctor、迁移器及相关 Skill 的适配，不能声称现有代码已经支持新层级。

验收应覆盖多 type 的入口与写入定位、自定义类型保留、不同 type 或来源同名、原位接入、别名、符号链接写入边界、子作用域隔离和迁移链接修复。具体默认 type 与入口取舍确认后再编写实施计划。

## 一键迁移与升级策略

### 兼容边界

本仓在目录切换时同步升级受影响的 CLI、Skill、脚本、生成与读取链路，公开命令使用方式尽量保持。新版常规运行只支持新布局，不运行时回退读取旧 `.memory`，不双写。

提供 `project-memory-migrate` Skill，由确定性脚本完成 Project Memory 布局转换。旧格式读取仅存在于迁移器；常规命令可以提示尚未迁移，但不能替用户静默迁移或继续按旧格式运行。

### 通用迁移 Skill 的职责

对用户明确指定范围内的实际记忆层操作，保留原作用域关系；不因文件夹层数创建新层，不沿跨作用域引用扩大写入范围，不进入另外的 Git 仓库或 submodule。

1. 扫描文件系统中的实际记忆层、登记类型、内容、附属文件和索引，包括 ignored/untracked 的用户材料。仅使用 `git ls-files` 不足以完成迁移。
2. 在写入前生成源到目标的完整映射，检查目标冲突、类型格式、链接和权限标志。确定性项目不逐项询问；无法可靠判断或存在不同内容冲突时，汇总问题后再执行，不能静默覆盖。
3. 先适配私有类型的忽略规则，再迁移内容与元数据。用户记忆的正文、类型索引和迁移中产生的私有副本均不进入公共版本历史或公开报告。
4. 本地技能按确认的 type 映射整目录迁移，包含 scripts、references、assets 等附属文件；旧技能索引按确定的入口结构重建，安装正文不改写。仅按明确映射修复指向本次已迁本地真源的安装链接，其余安装入口与外部真源保持。保留自定义类型的标识、格式、`index-only`、`gitignore` 等语义，不按推荐种子重新分类。
5. 按新路径重建受管索引和可确定的引用，保留硬约束、区块外正文及业务索引。自然语言中的历史示例、外部路径和职责归属不能通过盲目替换修改。
6. 验证正文完整、索引可达、引用正确、忽略有效和新工具可用；验证完成后清理已迁移的旧真源。保留本次操作的恢复依据，重复运行应无操作或恢复尚未完成的步骤，不覆盖迁移后新增内容。

正常无冲突的迁移在一次调用中完成预检、转换和校验。冲突中断时不将新旧混合状态报告为迁移成功。此前已有的自定义记忆类型全部保留；新建时的推荐选项不应用来重置旧数据。

### Edges 实例迁移的职责

通用 Skill 不内置 `knowledge/tasks`、`teaching`、`evaluation` 等业务目录。Edges 的迁移计划调用通用转换能力，并另外完成：

- 审阅任务与局部维护记录的归属映射，按已确认职责分流；相同正文不复制成多份任务，聚合视图引用真源。
- 搬迁项目与教学工作区，适配课页、Topics、附件以及部署源路径；公开 `/teaching/` 与 `/tasks/` 入口继续由发布层提供。
- 迁移根评测与观测，适配 `.gitmodules`、评测仓根定位、忽略规则及报告引用。现有 LoCoMo 结果仍只是对应评测链路的证据，不因目录调整提高其结论强度。
- 检查所有可修改文档和代码的路径依赖。受保护的 `knowledge/posts/` 仅读取以发现链接影响；如无法在其外部解决引用问题，列为待人工处理的阻断，不自动修改文章。
- 校验实际目标工作树中的私有材料。共享 Git 提交不代表每个工作树的 ignored 用户记忆已迁移；各本地实例仍需运行对应迁移。

本机实施遵守独立 worktree 约束。迁移期间不混入其他任务的修改，不通过强制覆盖解决冲突。

## 交付与验收

实施按依赖分为：新布局和索引能力、选择式初始化、通用迁移 Skill、业务命令与发布适配、Edges 实例迁移。目录切换前相关工具必须能够完成新路径的读写。

验收覆盖：

- 普通类型、自定义普通/Skill 格式类型、只读类型及递归用户记忆的转换不丢失内容或属性。
- 层入口硬约束、类型入口、业务索引和真正的子层关系保留；维护知识仍保持两跳。
- 原位接入技能正文零改写；指向已迁本地真源的安装链接保持可用。技能类型索引正确处理分类、别名、同名不同源和写入边界。用户记忆及索引始终被忽略；再次迁移无重复变更，冲突不覆盖，失败可恢复。
- 根领域任务、根维护任务和子作用域任务写入各自真源；Task 与 Run 的关联保持。
- 新工具仅支持新布局，旧路径不会被常规写入重新创建。
- 教学与任务发布链、相关构建和评测路径通过针对性验证；`knowledge/posts/` 无变更。

技能入口取舍、具体类型映射及整体审阅确认后编写分步实施计划。当前文档记录设计与交付要求，不表示迁移 Skill 或新目录运行时已经实现。
