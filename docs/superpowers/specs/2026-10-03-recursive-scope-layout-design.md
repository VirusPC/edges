# 递归作用域目录与迁移设计

日期：2026-10-03。状态：供整体审阅；尚未执行目录迁移或修改运行时。

## 目标与设计边界

以 Project Memory 的入口、索引和扩展机制为基础，使人和 Agent 能按作用域接手工作、保留记忆并维护自身。内容按所属作用域组织，领域工作与自身维护分开；通过引用形成 graph，公共实现保持单一真源。

本设计区分三件事：目录由谁拥有、在该作用域承担什么职责、其组织约定能否复用。一个可复用模块不因此成为每层必建目录，一个源码目录也不因此成为独立责任作用域。

已确认的取舍见 [ADR 0024](../../adr/0024-scope-first-content-ownership.md)。本方案对剩余布局细节采用以下具体落点供整体审阅：维护知识使用 `memory/`，技能统一使用 `skills/AGENTS.md` 发现本地方法与原位接入技能；迁移 Skill 命名为 `project-memory-migrate`。

本次不拆 Git 仓库，不部署观测后端，不将所有模块改造成 Memory Type，不建立全局 JSON/YAML 类型注册表，也不启用定期目录 review 自动任务。

## 通用规则与按需扩展

通用部分规定作用域入口、硬约束、归属、索引与引用；各作用域选择需要的模块，并能登记自己的类型。Edges 当前实例的完整目录树不是通用模板。

以下是形状示意，未采用的模块不创建空目录：

```text
<scope>/
├── AGENTS.md
├── .edges/                     # 本作用域默认维护目录，按需要建立
│   ├── memory/<type>/          # 维护知识；类型开放
│   ├── skills/                 # AGENTS.md 统一索引；<name>/ 存本地受管方法
│   └── <维护模块>/             # 所选模块按自己的内容契约组织
└── <领域目录>/                 # 由本作用域的目标决定
```

- `AGENTS.md` 是人和 Agent 的入口，硬约束仍写在所属层入口的硬约束区块。
- `.edges/` 与其中的 `memory/` 是物理分组，不自动形成新的作用域，也不建立必经的中转入口。
- 仅在确有独立目标、决策和验证责任时再划分子作用域。记忆层保持稀疏，可以跨过普通目录。
- 领域任务位于所属作用域的 `tasks/`；维护该作用域的任务位于其 `.edges/tasks/`。Task Project 是看板分组，不自动成为项目作用域。
- 模块可以具有作用域特有的职责，也可以在实践中提炼成可复用规范。定期目录 review 负责识别这种共性，当前只执行规范，不自动运行。
- `CONTEXT.md`、`docs/adr/`、`docs/superpowers/` 和宿主固定入口保留约定位置，按所属职责引用接入。目录名本身不固定系统一或系统二角色。

### 维护记忆初始化

初始化显示少量推荐类型及用途，由用户选择，再创建所选目录和入口；可以通过既有类型登记机制追加自定义类型。推荐清单为：

| 展示项 | 现有类型标识 | 内容边界 |
|---|---|---|
| 上下文与决策 | `project` | 接手背景、理由与边界；硬约束仍在层入口，既有 ADR 引用原文 |
| 纠正与反馈 | `feedback` | 用户纠正、有效做法与禁止模式 |
| 参考资料 | `reference` | 外部资料及已有文档的指针 |
| 本地私有记忆 | `user` | 私有材料；正文和类型索引一并忽略提交 |

展示名不要求改变现有类型标识与条目前缀。Skills 作为一个可选模块独立于维护知识选项，同时发现本地方法与原位接入技能。迁移已有项目时不用新建推荐清单重置旧项目；除本设计明确合并的官方 skills/agent_skills 外，其余既有类型身份保持。

## 入口、类型索引与模块发现

沿用 Project Memory 的硬约束、本层索引和下层索引区块，不因为物理目录变深而增加检索层级：

```text
作用域 AGENTS.md
  → .edges/memory/<type>/AGENTS.md
    → 该类条目
```

维护知识仍是两跳到正文。`memory/` 不另建必经索引，类型入口不承担独立作用域硬约束。技能统一为一个官方 `skills` 类型和一份 `.edges/skills/AGENTS.md`，直接链接本地受管方法与原位接入正文，保留不同来源的维护边界；具体规则见下节。

物理分组调整不要求废掉现有 Skills 类型适配。自定义普通类型或 Skill 格式类型保持类型身份及独立命名空间，默认在 `.edges/memory/<原复数目录>/` 保留；不能仅因格式相同就合并到官方 `skills`。

在 Project Memory 受管区块外使用 `AGENTS.md` 的共享文件扩展点，列出本层工作与模块入口：领域任务、维护任务、评测、观测及原位文档。各模块继续维护自己的业务索引；模块入口不自动登记为记忆子层。Task 可以沿自己的 Task Project 索引继续查找，不受普通记忆两跳规则约束。

这批变更应主要落在 LAYOUT、路径解析、索引生成和模块接入中。不得用全局替换 `.memory` 的方式改造解析器：作用域定位、children 索引、外部技能真源、doctor 扫描和 Git ignore 都需按新布局适配。

CLI 的目标契约是先明确所操作的作用域，再明确模块及领域/维护用途。源码所在位置不作为操作目标。具体命令参数由既有 scope-first CLI 工作衔接；本次目录迁移交付必须保证新真源可被相应命令操作，不能迁完目录再留下仍向旧路径写入的调用。

### Skills：统一类型与入口，保留正文来源

用户提出并同意继续细化 `skills` 与 `agent_skills` 共用一份 `AGENTS.md` 的方向。合并后使用一个官方 `skills` 类型；来源和维护权限不再通过两个类型表达。以下为合并方案，尚未实现。

```text
<scope>/AGENTS.md
  → .edges/skills/AGENTS.md
    → .edges/skills/<name>/SKILL.md     本地受管正文
    → .agents/skills/<name>/SKILL.md    原位接入正文或链接
```

`.edges/skills/` 同时存放统一索引和本地受管正文；只接入已有技能时，可以仅有索引，不预建空 Skill。`.agents/skills/` 保留宿主发现与安装约定，可以存放实体或链接。两者不按人写、Agent 写或是否第三方划分，而按正文由哪个机制维护划分。

| 方案 | 取舍 |
|---|---|
| **统一索引，正文保留来源（采用）** | 找技能只需一个入口；本地方法可沉淀，原位技能仍由原来的机制维护；需要多来源索引与写入约束 |
| 保留两个类型和入口 | 延续现实现，但使用者必须先理解来源才能选入口，重复表达同一种能力 |
| 全部正文搬到同一目录 | 物理位置更少，但会改变宿主安装约定或把所有本地沉淀都纳入宿主安装目录，超出此次合并目标 |

#### 索引与作用域

同一受管条目区块内按“本地受管方法”“原位接入技能”分组。每项仍为正文链接及用途说明；同名时补充来源，别名可附在同一项。来源说明由工具生成，正文继续采用现有 Agent Skills 格式，不要求改写已接入技能的 frontmatter。

- 只汇总当前作用域已接入的来源：本地受管目录与本层 `.agents/skills/`；不递归吸收子作用域的 Skill，也不自动扫描全机或祖先的安装目录。作用域链接明确接入的共享技能可以索引，但引用不扩大写入范围。
- 层入口只有一行技能入口，仍为“层入口 → 类型入口 → 正文”两跳。取消独立 `.edges/agent_skills/`；不增加 `.edges/AGENTS.md` 作为必经中转。
- 同一实际真源的多个安装或符号链接别名合为一项；优先链接经验证的本地受管真源，否则保留本层接入路径。索引存储可移植的相对链接，不写入本机绝对路径。
- 同名但不同真源分别保留并标明来源，不默认覆盖或按正文相同合并。真源路径用于本次发现的去重，不新增全局 Skill ID 注册表。
- **索引可见与宿主安装是两件事。** 本地方法尚未安装时仍可经 `AGENTS.md` 阅读使用；索引不宣称宿主已加载它，不定义同名技能在宿主中的优先级。需要安装时走现有安装或链接机制，保持一份正文。

#### 工具与维护权限

Skills 具有一个本地受管写入根和一个原位接入发现根。来源与写入范围由工具的受控路径映射及解析后的实际路径判定；索引文案、技能名称或技能自己的 frontmatter 都不能授予写权限。

| 操作 | 合并后的最小契约 |
|---|---|
| 初始化 | 选择启用 Skills 时只登记一个入口，可同时发现本地方法和原位技能；不要求同时存在两种来源，不安装技能，不为缺失安装目录创建内容 |
| `remember --type skills` | 仅创建或更新本地受管正文，附属文件保持；不根据同名索引反向选择安装路径。只有原位技能同名时，报告匹配并要求明确是在创建独立本地方法还是使用原位维护流程，不静默复制 |
| `doctor` / 索引刷新 | 汇总两来源并修复受管索引；正文修复仅限已有授权的本地受管范围。原位正文的格式错误、断链与不可读项只报告，不改写、下载或补建。缺失项不保留为有效索引，非受管文字保留 |
| 原位技能维护 | 继续由其原有维护或安装机制处理；即使正文属于本仓，Project Memory 也不因能发现它就获得改写权限 |

写入前必须检查真实路径：本地路径若经符号链接通向受管范围之外，只能作为引用发现，不能借本地路径名授权写入。反之，安装链接指向本地受管真源时，可通过本地真源维护；索引只列一项并注明安装别名。

不可读来源应报告索引不完整，不能把未能读取的来源当成空目录后宣布刷新成功。断链、缺失项与真正的空来源分别处理；不要在重建受管区块时删除人工说明或其他模块内容。

#### 迁移与实现边界

旧 `.memory/skills/` 的本地正文及附属文件迁入 `.edges/skills/`；旧 `.memory/agent_skills/AGENTS.md` 的独立入口由统一索引替代。旧官方 `agent_skills` 类型在新版运行时退出，来源及只索引边界继续保留；仅迁移器识别旧类型，不增加旧命令别名或运行时回退。此合并是“保留既有类型身份”的明确例外，自定义普通、Skill 格式及 `index-only` 类型仍保持身份和原有权限。

安装入口路径和外部正文真源保持原位。若安装链接指向本次迁移的本地受管正文，迁移器先解析旧真源、登记源到目标映射，再在原入口更新链接目标，避免移动后断链；只在明确迁移范围内改此类链接。若安装目录本身链接到范围外，或链接归属无法确定，列为预检问题，不沿链接修改外部目录。正常 `init`、`remember`、`doctor` 不因此获得修改安装入口的权限。

统一索引根据实际来源重建，旧索引中的人工说明、非受管内容和无法重新发现的引用先逐项安置或列为冲突，不能直接删目录丢失内容。已知来源变更的引用随迁移清单更新；新版不保留旧独立索引充当兼容跳板。

迁移冲突按实际目标路径判断，同名安装技能位于不同真源不阻止本地方法迁移。内容无损与执行可用分别验证；技能脚本若硬编码旧路径，列为待适配项，由其真源维护流程处理，不能据文件搬迁成功宣称方法已验证可执行，也不能越过只读来源边界修改正文。

保持 PROTOCOL 的层级、共享文件与两跳发现模型；LAYOUT 说明官方 Skills 的多来源映射，类型解析、索引生成、写入定位、doctor 和迁移器同步适配。自定义类型无需全部升级为多来源，不为此次合并建设任意来源插件框架。相关 Skill 说明与测试同步更新，避免仍宣称官方类型必须有六种或所有类型只有一个内容根。

验收场景至少覆盖：只有原位技能、只有未安装的本地方法、两边同名不同源、安装链接指向本地真源、本地符号链接逃出写入范围、子作用域技能隔离，以及迁移时安装链接指向旧本地路径。前述场景均检查单一入口、真源无复制和权限不扩大；异常来源不能被当成完整成功。

## 一键迁移与升级策略

### 兼容边界

本仓在目录切换时同步升级受影响的 CLI、Skill、脚本、生成与读取链路，公开命令使用方式尽量保持。新版常规运行只支持新布局，不运行时回退读取旧 `.memory`，不双写。

提供 `project-memory-migrate` Skill，由确定性脚本完成 Project Memory 布局转换。旧格式读取仅存在于迁移器；常规命令可以提示尚未迁移，但不能替用户静默迁移或继续按旧格式运行。

### 通用迁移 Skill 的职责

对用户明确指定范围内的实际记忆层操作，保留原作用域关系；不因文件夹层数创建新层，不沿跨作用域引用扩大写入范围，不进入另外的 Git 仓库或 submodule。

1. 扫描文件系统中的实际记忆层、登记类型、内容、附属文件和索引，包括 ignored/untracked 的用户材料。仅使用 `git ls-files` 不足以完成迁移。
2. 在写入前生成源到目标的完整映射，检查目标冲突、类型格式、链接和权限标志。确定性项目不逐项询问；无法可靠判断或存在不同内容冲突时，汇总问题后再执行，不能静默覆盖。
3. 先适配私有类型的忽略规则，再迁移内容与元数据。用户记忆的正文、类型索引和迁移中产生的私有副本均不进入公共版本历史或公开报告。
4. 本地官方 Skills 整目录迁移，包含 scripts、references、assets 等附属文件；官方 skills/agent_skills 合并成一个索引，安装正文不改写。仅按明确映射修复指向本次已迁本地真源的安装链接，其余安装入口与外部真源保持。保留自定义类型的标识、格式、`index-only`、`gitignore` 等语义，不按推荐种子重新分类。
5. 按新路径重建受管索引和可确定的引用，保留硬约束、区块外正文及业务索引。自然语言中的历史示例、外部路径和职责归属不能通过盲目替换修改。
6. 验证正文完整、索引可达、引用正确、忽略有效和新工具可用；验证完成后清理已迁移的旧真源。保留本次操作的恢复依据，重复运行应无操作或恢复尚未完成的步骤，不覆盖迁移后新增内容。

正常无冲突的迁移在一次调用中完成预检、转换和校验。冲突中断时不将新旧混合状态报告为迁移成功。此前已有的自定义记忆类型全部保留；新建时的推荐选项不应用来重置旧数据。

### Edges 实例迁移的职责

通用 Skill 不内置 `knowledge/tasks`、`teaching`、`evaluation` 等业务目录。Edges 的迁移计划调用通用转换能力，并另外完成：

- 审阅任务与局部维护记录的归属映射，按已确认职责分流；相同正文不复制成多份任务，聚合视图引用真源。
- 搬迁项目与教学工作区，适配课页、Topics、附件以及部署源路径；公开 `/teaching/` 与 `/tasks/` 入口继续由发布层提供。
- 迁移根评测与观测，适配 `.gitmodules`、评测仓根定位、忽略规则及报告引用。现有 LoCoMo 结果仍只是对应评测链路的证据，不因目录调整提高其结论强度。
- 检查所有可修改文档和代码的路径依赖。受保护的 `knowledge/posts/` 仅读取以发现链接影响；如无法在其外部解决引用问题，列为待人工处理的阻断，不自动修改文章。
- 校验实际目标工作树中的私有材料。共享 Git 提交不代表每个工作树的 ignored 用户记忆已迁移；各本地实例仍需运行对应迁移。

本机实施遵守独立 worktree 约束。迁移期间不混入其他任务的修改，不通过强制覆盖解决冲突。

## 交付与验收

实施按依赖分为：新布局和索引能力、选择式初始化、通用迁移 Skill、业务命令与发布适配、Edges 实例迁移。目录切换前相关工具必须能够完成新路径的读写。

验收覆盖：

- 普通类型、自定义普通/Skill 格式类型、只读类型及递归用户记忆的转换不丢失内容或属性。
- 层入口硬约束、类型入口、业务索引和真正的子层关系保留；维护知识仍保持两跳。
- 原位接入技能正文零改写；指向已迁本地真源的安装链接保持可用。统一技能索引正确处理别名、同名不同源和写入边界。用户记忆及索引始终被忽略；再次迁移无重复变更，冲突不覆盖，失败可恢复。
- 根领域任务、根维护任务和子作用域任务写入各自真源；Task 与 Run 的关联保持。
- 新工具仅支持新布局，旧路径不会被常规写入重新创建。
- 教学与任务发布链、相关构建和评测路径通过针对性验证；`knowledge/posts/` 无变更。

整体审阅确认后编写分步实施计划。当前文档记录设计与交付要求，不表示迁移 Skill 或新目录运行时已经实现。
