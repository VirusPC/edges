# Lesson 1 故事线大纲

## 核心逻辑
- 故事来自开发 AI CR Agent 过程中的真实困惑，不是为章节配例子
- Part 1 用 `"请 review 这段代码"` 作贯穿示例，建立基础直觉，子节不强行挂 CR 场景
- Parts 2–5 每个 Part 开头锚定一个开发过程中真实遇到的问题，章节内容是解答
- 视角：全程"你"

---

## 开场白
*插入位置：核心主线图之后*

你搭了一个 AI CR 工具，在 PR 合并前自动 review 代码。

跑了一段时间之后，几件事让你想搞清楚——它为什么会漏掉某些 bug？它为什么对你们自己定义的 API 总是说错？它为什么每次都要等一下才开始出字，但追问却快了很多？

这节课就跟着这些问题，把大模型拆开来看清楚。

---

## 第一部分：模型架构
*开头钩子：先不急着回答那些问题。在搞清楚"为什么"之前，先跟着一条请求进模型走一遍。就用这一条：「请 review 这段代码」*

**1.1 统一范式** — 这条请求在模型眼里是一段待续写的文本，无需额外挂钩

**1.2 Tokenizer** — 用这条请求 + 代码片段展示 token 切分，建立 token = 计费单位的直觉

**1.3 Embedding** — 用同一条请求解释 token → 向量，无需强行联系 CR 场景

**1.4 Attention** — 用同一条请求示意 Q-K-V 打分。**Lost in Middle 自然挂钩**：直接解释了为什么长文件 review 会漏掉中间的 bug，不是刻意联系，是同一件事

**1.5 Transformer** — 把前面零件组装成完整架构，无需额外故事

---

## 第二部分：训练机制
*开头钩子：AI CR 上线没多久，你发现了一个规律——它对标准库的用法很准，但对你们自己定义的工具函数经常说错。为什么它"懂"有些代码，却对另一些一无所知？*

**2.1 预训练** — 它读过 GitHub、Stack Overflow，所以"见过"标准库；内部 API 不在训练数据里。知识截止日期也在这里解释

**2.2.1 CPT** — 为什么专门的 Coder 模型 review 更准：代码领域知识的深度不同

**2.2.2 SFT** — 它学会了"收到 review 请求 → 输出结构化结论"的行为。工具调用 SFT：AI CR 调用 linter、返回 JSON 也是这里训练出来的

**2.2.3 Alignment** — 你还注意到另一件事：review 结论总是"建议考虑是否……"，不敢直接说这是个 bug。Alignment Tax：过度对齐让模型变得瞻前顾后，这是机制，不是 prompt 能完全解决的

**2.2.4 工程视角 / 2.3** — 保持原有内容。2.3 的"15度夹角"自然对应：做 AI CR 工具，哪些投入不会被下一代模型内化

## 第三部分：推理机制
*开头钩子：还有一件事你一直没搞清楚——每次发出请求，都要等一下才开始出字；但同一个 PR 里追问，第二个问题明显快了。这不是网络抖动。*

**3.1 Prefill 与 Decode** — 等待首字 = Prefill 并行处理整个输入；流畅输出 = Decode 逐 token 生成。顺带解释 output token 为什么比 input 贵

**3.2 KV Cache 与 Prompt Cache** — 追问变快 = KV Cache 复用了上一条请求的计算。Prompt Cache：system prompt + 代码上下文缓存后，每条 review 只算新增部分

**3.3 加速与降本技术全景** — 读懂这张表，理解不同平台速度/价格差异的来源；私有化部署时的量化选择

---

## 第四部分：模型选型
*开头钩子：工具跑了一段时间，你开始认真想这个问题——现在用的模型是当时随手选的。专门的 Coder 模型和现在用的差在哪？有没有更合适、更划算的选择？*

**4.1 为什么不直接用最强模型** — CR 工具调用频率高，旗舰模型单价 × 调用量成本快速失控

**4.2 判断维度：选型看什么** — 对照六个维度，把 AI CR 的约束填进去

**4.3 实践三步** — 用 SWE-Bench / Aider Polyglot 缩小候选，再用真实 PR 实测

---

## 第五部分：参数配置
*开头钩子：模型选定了，但还有两件具体的事没解决——review 结论有时太模糊，有时又跑去讨论和当前 PR 无关的问题；开了推理模式之后，某几次账单比预期高出不少。这是参数的问题。*

**5.1 temperature** — 结论太模糊或太跑题，代码审查推荐区间 0.3–0.5

**5.2 max_tokens 与 stop** — review 被截断 = max_tokens 设小了；stop 防止模型 review 完后继续自问自答

**5.3 Thinking 模式** — 跨文件 bug 追踪值得开；简单格式检查是浪费。"账单高了" = 在不需要推理的场景开了 Thinking

**5.4 常见任务配置速查** — 给出 Code Review 场景的参数起点
