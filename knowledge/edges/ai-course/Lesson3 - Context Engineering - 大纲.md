

## 📚 核心框架

这份文档系统阐述了**上下文工程**的定义、方法与实践，分为以下主要部分：

### **第一部分：基础认知**
- **定义**：为多步骤任务动态筛选、打包、管理最相关信息
- **适用场景**：长任务、多工具、质量敏感的场景
- **能力边界**：能解决目标维持、过载控制、事实时效、安全隔离；不能解决模型能力、数据质量问题

### **第二部分：四件事（Write/Select/Compress/Isolate）**
| 动作 | 含义 | 目的 |
|------|------|------|
| **Write** | 把信息存到外部 | 控制上下文膨胀 |
| **Select** | 按需拉回必要信息 | 精准选择 |
| **Compress** | 缩短表示形式 | 降低token成本 |
| **Isolate** | 分域拼装，避免污染 | 防止冲突与注入 |

### **第三部分：上下文来源与层级**
- **7类来源**：System、Task、Conversation State、Retrieval、Tool Output、Memory、Codebase Index
- **5层优先级**：规则 > 目标 > 事实 > 偏好 > 历史
- **结构化表示**：用Context Contract而非字符串拼接

### **第四部分：上下文生命周期**
```
收集 → 存储 → 检索 → 组装 → 执行 → 观测 → 更新
```

### **第五部分：四类常见故障与对策**

| 故障 | 症状 | 对策 |
|------|------|------|
| **漂移(Drift)** | 注意力偏离目标 | 目标复述(Recitation)、验收标准置顶 |
| **腐烂(Rot)** | 旧信息失效仍被引用 | 事实表+TTL+Provenance标注 |
| **过载(Overload)** | 信息太多抓不到重点 | 预算控制、置顶关键信息 |
| **注入(Injection)** | 外部文本诱导违反约束 | Instruction/Data隔离、净化 |

### **第六部分：五大工程策略**

1. **卸载(Offload)**：把大块信息搬到文件/数据库，保留可回溯索引
2. **压缩(Compress)**：Compaction(可逆)优先，Summarization(不可逆)兜底
3. **隔离(Isolate)**：Global/Run/Step/Tool分层，Instruction/Data分区
4. **回滚与重试**：Checkpoint+改条件重试，保留失败证据
5. **设计模式**：提示链、路由、反思、工具使用、记忆管理

### **第七部分：代码实现**
- **最小ContextBuilder**：支持token预算、分层拼装、去重压缩、步骤隔离、失败回滚
- **JavaScript + Python双语实现**
