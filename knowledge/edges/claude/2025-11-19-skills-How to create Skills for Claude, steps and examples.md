
这篇文章主要介绍什么是 Claude 的 Skills，以及如何按步骤编写一个高质量的 SKILL.md，把通用助手变成在特定任务上的“专家”工具。[1]

## Skills 的作用与核心概念
- Skills 是一组自定义说明，用来扩展 Claude 在特定任务或领域中的能力，比如批量处理 PDF、生成财报、应用品牌规范等。[1]
- 它们可以把团队的流程和知识编码进 SKILL.md，从而标准化输出、减少反复解释，并支持更复杂的多步骤工作流。[1]

## 创建 Skill 的五个步骤
1. 明确问题与需求：先搞清楚技能解决的具体任务、触发条件、成功标准以及边界，比如“从 PDF 中提取财务表格并导出 CSV”。[1]
2. 命名：Skill 需要清晰的 **name**（如 pdf-editor、brand-guidelines），简短、用小写加连字符，方便识别。[1]
3. 描述 description：这是触发逻辑的关键部分，要从 Claude 视角写，强调能力、典型场景和不适用的情况，用具体动词、文件类型和用例，而不是含糊的“帮我处理文档”。[1]
4. 主体 instructions：用有层级的 Markdown 结构（概览、前置条件、步骤、示例、错误处理、限制），给出清晰流程和代码示例，并说明不能做什么及如何处理边缘情况，可用额外文件细化复杂流程。[1]
5. 上传：  
   - 在 Claude.ai 设置中添加自定义 Skill（需 Pro/Max/Team/Enterprise 且支持代码执行，且目前是个人级别）。[1]
   - 在 Claude Code 中，在项目根目录建 skills/ 目录，放置各 Skill 子文件夹及 SKILL.md，插件安装后会自动发现。[1]
   - 在开发者平台，通过 Skills API 调用 /v1/skills 接口上传 SKILL.md 文件。[1]

## 测试与迭代
- 在上线前要用真实场景测试，包括正常使用、边缘输入（缺失数据、异常格式、模糊指令）和超出范围的请求，看触发是否合理、输出是否稳定可用。[1]
- 重点检验：触发测试（何时被调用或不被调用）、功能测试（输出一致性、易用性、文档与行为是否一致），并根据真实使用情况持续调整描述和说明。[1]

## 编写 Skill 的通用最佳实践
- 从实际用例出发：只为高频且可复用的任务创建 Skill，比如已经做过至少 5 次、未来还会做 10 次以上的事情。[1]
- 在说明中写明成功标准，如报告应包含哪些章节、格式和校验步骤，让 Claude 能自检输出质量。[1]
- 善用官方的 skill-creator skill 和 GitHub Skills 仓库模板，辅助你问清需求、优化描述和结构。[1]

## 技能的触发、上下文与限制
- Claude 会用语义理解把用户请求和技能描述进行匹配，而不是简单关键词匹配，因此描述太模糊会导致触发不稳定或误触发。[1]
- 多个技能可以同时被调用来处理复杂任务；描述过于宽泛会乱触发，过于狭窄则会漏触发。[1]
- 为避免上下文过大，建议采用“菜单式”结构：SKILL.md 只概览各种子流程，具体细节拆分到多个引用文件，需要时再按路径加载。[1]

## 真实 Skill 示例（DOCX、品牌与前端）
- 文中给出了 docx 创建与编辑技能、品牌规范技能（明确颜色、字体、字号阈值等）、以及前端设计技能（强调大胆而一致的视觉方向和生产级代码）等示例。[1]
- 这些例子共同特点是：描述清晰具体、触发边界明确、结构严谨，并提供丰富的操作细节和好/坏示例，方便 Claude 按既定流程执行。[1]

## 组织内的共享与治理
- 目前 Claude.ai 上的 Skills 仍是个人级，文章建议各类团队用共享文档库集中存放技能规范，包含版本、变更记录和常见问题。[1]
- 对中大团队，推荐指定领域负责人、建立治理流程、定期评审和统一命名规范，并跟踪哪些技能创造了最大价值以便优先维护。[1]
