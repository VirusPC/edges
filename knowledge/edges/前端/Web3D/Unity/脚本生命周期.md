# 介绍
类似 React 类组件生命周期，脚本生命周期（Script lifecycle）描述了一些事件的触发时间和顺序。 

<font style="color:rgb(69, 84, 99);">Running a Unity script executes a number of event functions in a predetermined order. </font>

<font style="color:rgb(69, 84, 99);">This page describes those event functions and explains how they fit into the execution sequence.</font>

<font style="color:rgb(69, 84, 99);"></font>

## <font style="color:rgb(27, 34, 41);">First Scene load</font>
<font style="color:rgb(69, 84, 99);">These functions get called when a</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">scene</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">starts (once for each object in the scene).</font>

+ **<font style="color:rgb(69, 84, 99);">Awake:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">This function is always called before any Start functions and also just after a</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">prefab</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">is instantiated. (If a GameObject is inactive during start up Awake is not called until it is made active.)</font>
+ **<font style="color:rgb(69, 84, 99);">OnEnable:</font>**<font style="color:rgb(69, 84, 99);"> (only called if the Object is active): This function is called just after the object is enabled. This happens when a MonoBehaviour instance is created, such as when a level is loaded or a </font>**<font style="color:rgb(69, 84, 99);">GameObject</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);"> </font><font style="color:rgb(69, 84, 99);">with the script component is instantiated.</font>

<font style="color:rgb(69, 84, 99);">Note that for objects added to the scene, the Awake and OnEnable functions for</font><font style="color:rgb(69, 84, 99);"> </font>_<font style="color:rgb(69, 84, 99);">all</font>_<font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">scripts</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">will be called before Start, Update, etc are called for any of them. Naturally, this cannot be enforced when you instantiate an object during gameplay.</font>

<font style="color:rgb(69, 84, 99);">Awake 只调用一次，OnEnable可能调用多次。每次物体失活再激活时，就会触发OnEnable。</font>

## <font style="color:rgb(27, 34, 41);">Editor</font>
+ **<font style="color:rgb(69, 84, 99);">Reset:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Reset is called to initialize the script’s properties when it is first attached to an object and also when the</font><font style="color:rgb(69, 84, 99);"> </font>_<font style="color:rgb(69, 84, 99);">Reset</font>_<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">command is used.</font>
+ **<font style="color:rgb(69, 84, 99);">OnValidate:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">OnValidate is called whenever the script’s properties are set, including when an object is deserialized, which can occur at various times, such as when you open a scene in the Editor and after a domain reload.</font>

## <font style="color:rgb(27, 34, 41);">Before the first frame update</font>
+ **<font style="color:rgb(69, 84, 99);">Start:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Start is called before the first frame update only if the script instance is enabled.</font>

<font style="color:rgb(69, 84, 99);">For objects that are part of a scene asset, the Start function is called on all scripts before Update, etc is called for any of them. Naturally, this cannot be enforced when you instantiate an object during gameplay.</font>

## <font style="color:rgb(27, 34, 41);">In between frames</font>
+ **<font style="color:rgb(69, 84, 99);">OnApplicationPause:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">This is called at the end of the frame where the pause is detected, effectively between the normal frame updates. One extra frame will be issued after</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">OnApplicationPause</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">is called to allow the game to show graphics that indicate the paused state.</font>

## <font style="color:rgb(27, 34, 41);">Update Order</font>
<font style="color:rgb(69, 84, 99);">When you’re keeping track of game logic and interactions, animations,</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">camera</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">positions, etc., there are a few different events you can use. The common pattern is to perform most tasks inside the</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Update</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">function, but there are also other functions you can use.</font>

+ **<font style="color:rgb(69, 84, 99);">FixedUpdate:</font>**<font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">FixedUpdate</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">is often called more frequently than</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Update</font>**<font style="color:rgb(69, 84, 99);">. It can be called multiple times per frame, if the frame rate is low and it may not be called between frames at all if the frame rate is high. All physics calculations and updates occur immediately after</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">FixedUpdate</font>**<font style="color:rgb(69, 84, 99);">. When applying movement calculations inside</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">FixedUpdate</font>**<font style="color:rgb(69, 84, 99);">, you do not need to multiply your values by</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Time.deltaTime</font>**<font style="color:rgb(69, 84, 99);">. This is because</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">FixedUpdate</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">is called on a reliable timer, independent of the frame rate.</font>
+ **<font style="color:rgb(69, 84, 99);">Update:</font>**<font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Update</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">is called once per frame. It is the main workhorse function for frame updates.</font>
+ **<font style="color:rgb(69, 84, 99);">LateUpdate:</font>**<font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">LateUpdate</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">is called once per frame, after</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Update</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">has finished. Any calculations that are performed in</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Update</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">will have completed when</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">LateUpdate</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">begins. A common use for</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">LateUpdate</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">would be a following third-person camera. If you make your character move and turn inside</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Update</font>**<font style="color:rgb(69, 84, 99);">, you can perform all camera movement and rotation calculations in</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">LateUpdate</font>**<font style="color:rgb(69, 84, 99);">. This will ensure that the character has moved completely before the camera tracks its position.</font>

<font style="color:rgb(69, 84, 99);">In general, you should not rely on the order in which the same event function is invoked for different GameObjects — except when the order is explicitly documented or settable. (If you need a more fine-grained control of the player loop, you can use the</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">PlayerLoop API</font>](https://docs.unity3d.com/ScriptReference/LowLevel.PlayerLoop.html)<font style="color:rgb(69, 84, 99);">.)</font>

<font style="color:rgb(69, 84, 99);">You cannot specify the order in which an event function is called for different instances of the same MonoBehaviour subclass. For example, the</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Update</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">function of one MonoBehaviour might be called before or after the</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Update</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">function for the same MonoBehaviour on another GameObject — including its own parent or child GameObjects.</font>

<font style="color:rgb(69, 84, 99);">You can specify that the event functions of one MonoBehaviour subclass should be invoked before those of a different subclass (using the Script Execution Order panel of the Project Settings window). For example, if you had two scripts, EngineBehaviour and SteeringBehaviour, you could set the Script Execution Order such that EngineBehaviours always updates before SteeringBehaviours.</font>

## <font style="color:rgb(27, 34, 41);">Animation update loop</font>
<font style="color:rgb(69, 84, 99);">These functions and</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">Profiler</font>](https://docs.unity3d.com/Manual/Profiler.html)<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Markers are called when Unity evaluates the Animation system.</font>

+ **<font style="color:rgb(69, 84, 99);">OnStateMachineEnter:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">During the</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">State Machine Update</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">step, this callback is called on the first update frame when a controller’s state machine makes a transition that flows through an Entry state. It is not called for a transition to a</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">StateMachine</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">sub-state.  
  
</font><font style="color:rgb(69, 84, 99);">This callback occurs only if there is a controller component (for example,</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorController</font>](https://docs.unity3d.com/ScriptReference/Animations.AnimatorController.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">or</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorOverrideController</font>](https://docs.unity3d.com/ScriptReference/AnimatorOverrideController.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">or</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorControllerPlayable</font>](https://docs.unity3d.com/ScriptReference/Animations.AnimatorControllerPlayable.html)<font style="color:rgb(69, 84, 99);">) in the animation graph.  
  
</font>**<font style="color:rgb(69, 84, 99);">Note:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Adding this callback to a</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">StateMachineBehaviour</font>](https://docs.unity3d.com/ScriptReference/StateMachineBehaviour.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">component disables multithreaded</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">state machine</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">evaluation.</font>
+ **<font style="color:rgb(69, 84, 99);">OnStateMachineExit:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">During the</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">State Machine Update</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">step, this callback is called on the last update frame when a controller’s state machine makes a transition that flows through an Exit state. It is not called for a transition to a</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">StateMachine</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">sub-state.  
  
</font><font style="color:rgb(69, 84, 99);">This callback occurs only if there is a controller component (for example,</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorController</font>](https://docs.unity3d.com/ScriptReference/Animations.AnimatorController.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">or</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorOverrideController</font>](https://docs.unity3d.com/ScriptReference/AnimatorOverrideController.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">or</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorControllerPlayable</font>](https://docs.unity3d.com/ScriptReference/Animations.AnimatorControllerPlayable.html)<font style="color:rgb(69, 84, 99);">) in the animation graph.  
  
</font>**<font style="color:rgb(69, 84, 99);">Note:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Adding this callback to a</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">StateMachineBehaviour</font>](https://docs.unity3d.com/ScriptReference/StateMachineBehaviour.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">component disables multithreaded state machine evaluation.</font>
+ **<font style="color:rgb(69, 84, 99);">Fire</font>****<font style="color:rgb(69, 84, 99);"> </font>****<font style="color:rgb(69, 84, 99);">Animation Events</font>****<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font>****<font style="color:rgb(69, 84, 99);">:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Calls all animation events from all clips sampled between the time of the last update and the time of the current update.</font>
+ **<font style="color:rgb(69, 84, 99);">StateMachineBehaviour (OnStateEnter/OnStateUpdate/OnStateExit):</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">A layer can have up to 3 active states: current state, interrupted state, and next state. This function is called for each active state with a StateMachineBehaviour component that defines the</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">OnStateEnter</font>**<font style="color:rgb(69, 84, 99);">,</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">OnStateUpdate</font>**<font style="color:rgb(69, 84, 99);">, or</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">OnStateExit</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">callback.  
  
</font><font style="color:rgb(69, 84, 99);">The function is called for the current state first, then the interrupted state, and finally the next state.  
  
</font><font style="color:rgb(69, 84, 99);">This step occurs only if there is a controller component (for example,</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorController</font>](https://docs.unity3d.com/ScriptReference/Animations.AnimatorController.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">or</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorOverrideController</font>](https://docs.unity3d.com/ScriptReference/AnimatorOverrideController.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">or</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorControllerPlayable</font>](https://docs.unity3d.com/ScriptReference/Animations.AnimatorControllerPlayable.html)<font style="color:rgb(69, 84, 99);">) in the animation graph..</font>
+ **<font style="color:rgb(69, 84, 99);">OnAnimatorMove:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Every update frame, this is called once for each</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Animator component</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">to modify the</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Root Motion</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);">.</font>
+ **<font style="color:rgb(69, 84, 99);">StateMachineBehaviour(OnStateMove):</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">This is called on each active state with a</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">StateMachineBehaviour</font>](https://docs.unity3d.com/ScriptReference/StateMachineBehaviour.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">that defines this callback.</font>
+ **<font style="color:rgb(69, 84, 99);">OnAnimatorIK:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Sets up animation IK. This is called once for each Animator Controller layer with</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">IK pass</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">enabled.  
  
</font><font style="color:rgb(69, 84, 99);">This event executes only if you are using a Humanoid rig.</font>
+ **<font style="color:rgb(69, 84, 99);">StateMachineBehaviour(OnStateIK):</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">This is called on each active state with a</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">StateMachineBehaviour</font>](https://docs.unity3d.com/ScriptReference/StateMachineBehaviour.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">component that defines this callback on a layer with</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">IK pass</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">enabled.</font>
+ **<font style="color:rgb(69, 84, 99);">WriteProperties:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Writes all other animated properties to the Scene from the main thread.</font>

### <font style="color:rgb(27, 34, 41);">Useful profile markers</font>
<font style="color:rgb(69, 84, 99);">Some of the animation functions shown in the</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">Script Lifecycle Flowchart</font>](https://docs.unity3d.com/Manual/ExecutionOrder.html#ScriptLifecycleFlowchart)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">are not Event functions that you can call; they are internal functions called when Unity processes your animation.</font>

<font style="color:rgb(69, 84, 99);">These functions have</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Profiler Markers</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);">, so you can use the</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">Profiler</font>](https://docs.unity3d.com/Manual/Profiler.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">to see when in the frame Unity calls them. Knowing when Unity calls these functions can help you understand exactly when the Event functions you do call are executed.</font>

<font style="color:rgb(69, 84, 99);">For example, suppose you call</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">Animator.Play</font>](https://docs.unity3d.com/ScriptReference/Animator.Play.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">in the</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">FireAnimationEvents</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">callback. If you know that the</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">FireAnimationEvents</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">callback is fired only after the</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">State Machine Update</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">and</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Process Graph</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">functions execute, you can anticipate that your</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">animation clip</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">will play on the next frame, and not right away.</font>

+ **<font style="color:rgb(69, 84, 99);">State Machine Update:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">All state machines are evaluated at this step in the execution sequence. This step occurs only if there is a controller component (for example,</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorController</font>](https://docs.unity3d.com/ScriptReference/Animations.AnimatorController.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">or</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorOverrideController</font>](https://docs.unity3d.com/ScriptReference/AnimatorOverrideController.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">or</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">AnimatorControllerPlayable</font>](https://docs.unity3d.com/ScriptReference/Animations.AnimatorControllerPlayable.html)<font style="color:rgb(69, 84, 99);">) in the animation graph.  
  
</font>**<font style="color:rgb(69, 84, 99);">Note:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">State machine evaluation is normally multithreaded, but adding certain callbacks (for example</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">OnStateMachineEnter</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">and</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">OnStateMachineExit</font>**<font style="color:rgb(69, 84, 99);">) disables multithreading. See</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">Animation update loop</font>](https://docs.unity3d.com/Manual/ExecutionOrder.html#AnimationUpdateLoop)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">above for details.</font>
+ **<font style="color:rgb(69, 84, 99);">ProcessGraph:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Evaluates all animation graphs. This includes sampling all animation clips that need to be evaluated, and computing Root Motion.</font>
+ **<font style="color:rgb(69, 84, 99);">ProcessAnimation:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Blends the results of the animation graph.</font>
+ **<font style="color:rgb(69, 84, 99);">WriteTransforms:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Writes all animated transforms to the scene from a worker thread.  
  
</font><font style="color:rgb(69, 84, 99);">A Humanoid rig with multiple layers that have</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">IK pass</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">enabled can have multiple</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">WriteTransforms</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">passes (See the</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">Script Lifecycle Flowchart</font>](https://docs.unity3d.com/Manual/ExecutionOrder.html#ScriptLifecycleFlowchart)<font style="color:rgb(69, 84, 99);">.</font>

## <font style="color:rgb(27, 34, 41);">Rendering</font>
+ **<font style="color:rgb(69, 84, 99);">OnPreCull:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Called before the camera culls the scene. Culling determines which objects are visible to the camera. OnPreCull is called just before culling takes place.</font>
+ **<font style="color:rgb(69, 84, 99);">OnBecameVisible/OnBecameInvisible:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Called when an object becomes visible/invisible to any camera.</font>
+ **<font style="color:rgb(69, 84, 99);">OnWillRenderObject:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Called</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">once</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">for each camera if the object is visible.</font>
+ **<font style="color:rgb(69, 84, 99);">OnPreRender:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Called before the camera starts rendering the scene.</font>
+ **<font style="color:rgb(69, 84, 99);">OnRenderObject:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Called after all regular scene rendering is done. You can use</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">GL</font>](https://docs.unity3d.com/ScriptReference/GL.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">class or</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">Graphics.DrawMeshNow</font>](https://docs.unity3d.com/ScriptReference/Graphics.DrawMeshNow.html)<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">to draw custom geometry at this point.</font>
+ **<font style="color:rgb(69, 84, 99);">OnPostRender:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Called after a camera finishes rendering the scene.</font>
+ **<font style="color:rgb(69, 84, 99);">OnRenderImage:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Called after scene rendering is complete to allow</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">post-processing</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">of the image, see</font><font style="color:rgb(69, 84, 99);"> </font>[<font style="color:rgb(69, 84, 99);">Post-processing Effects</font>](https://docs.unity3d.com/Manual/PostProcessingOverview.html)<font style="color:rgb(69, 84, 99);">.</font>
+ **<font style="color:rgb(69, 84, 99);">OnGUI:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Called multiple times per frame in response to GUI events. The Layout and Repaint events are processed first, followed by a Layout and keyboard/mouse event for each input event.</font>
+ **<font style="color:rgb(69, 84, 99);">OnDrawGizmos</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Used for drawing</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Gizmos</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">in the</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">scene view</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">for visualisation purposes.</font>

**<font style="color:rgb(69, 84, 99);">Note:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">These callbacks only work with the Built-in</font><font style="color:rgb(69, 84, 99);"> </font>**<font style="color:rgb(69, 84, 99);">Render Pipeline</font>**<font style="color:rgb(68, 68, 68);background-color:rgb(204, 204, 204);">  
</font><font style="color:rgb(69, 84, 99);">.</font>

## <font style="color:rgb(27, 34, 41);">Coroutines</font>
<font style="color:rgb(69, 84, 99);">Normal coroutine updates are run after the Update function returns. A coroutine is a function that can suspend its execution (yield) until the given YieldInstruction finishes. Different uses of Coroutines:</font>

+ **<font style="color:rgb(69, 84, 99);">yield</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">The coroutine will continue after all Update functions have been called on the next frame.</font>
+ **<font style="color:rgb(69, 84, 99);">yield WaitForSeconds</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Continue after a specified time delay, after all Update functions have been called for the frame.</font>
+ **<font style="color:rgb(69, 84, 99);">yield WaitForFixedUpdate</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Continue after all FixedUpdate has been called on all scripts. If the coroutine yielded before FixedUpdate, then it resumes after FixedUpdate in the current frame.</font>
+ **<font style="color:rgb(69, 84, 99);">yield WWW</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Continue after a WWW download has completed.</font>
+ **<font style="color:rgb(69, 84, 99);">yield StartCoroutine</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">Chains the coroutine, and will wait for the MyFunc coroutine to complete first.</font>

## <font style="color:rgb(27, 34, 41);">When the Object is destroyed</font>
+ **<font style="color:rgb(69, 84, 99);">OnDestroy:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">This function is called after all frame updates for the last frame of the object’s existence (the object might be destroyed in response to Object.Destroy or at the closure of a scene).</font>

## <font style="color:rgb(27, 34, 41);">When quitting</font>
<font style="color:rgb(69, 84, 99);">These functions get called on all the active objects in your scene:</font>

+ **<font style="color:rgb(69, 84, 99);">OnApplicationQuit:</font>**<font style="color:rgb(69, 84, 99);"> </font><font style="color:rgb(69, 84, 99);">This function is called on all game objects before the application is quit. In the editor it is called when the user stops playmode.</font>
+ **<font style="color:rgb(69, 84, 99);">OnDisable:</font>**<font style="color:rgb(69, 84, 99);"> This function is called when the behaviour becomes disabled or inactive.</font>
