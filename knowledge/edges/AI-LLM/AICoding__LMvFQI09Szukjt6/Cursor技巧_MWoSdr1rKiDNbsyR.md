---

在 Cursor（尤其是结合 GPT-4 等强大模型）中，掌握有效的提示技巧可以显著提升生成的代码质量、准确性和实用性。以下是一些关键技巧：

## 🧠 一、 提供充分的上下文 (Context is King)

1. **明确语言和框架:**
   * 开头就指定编程语言、库、框架和版本号 (如果重要)。
   * *示例：* `// 用 Python 的 pandas 库 (v1.5.3) 读取 CSV 文件 'data.csv'，处理缺失值并用均值填充，然后保存到 'cleaned_data.csv'`
2. **描述具体功能需求:**
   * 清晰、详细地描述你希望代码**做什么**，而不是**怎么做**（除非你明确想指定算法）。
   * *示例：* `// 写一个 JavaScript 函数，接受一个对象数组和一个属性名，返回该属性值唯一的对象数组（去重）。`
   * *避免模糊：* `// 处理这个数据` ❌ -> `// 遍历这个用户数组，计算每个用户的年龄（当前日期减去 birthDate），并将结果添加到新数组 ages 中` ✅
3. **利用现有代码作为上下文:**
   * **高亮选中代码片段：** 这是最强大的方式之一。选中一段代码，然后让 Cursor 基于它进行修改、解释、重构、添加功能或修复错误。Cursor 能理解选中代码的上下文。
   * *示例 (选中代码后)：* `/fix 修复这里的索引越界错误` 或 `/edit 在这个循环里添加对空值的检查` 或 `解释这段 SQL 查询在做什么？`
   * **引用文件路径/类/函数名：** 如果需求涉及项目中的其他部分，提及其名称。
   * *示例：* `// 在文件 models.py 中 User 类的基础上，创建一个继承自 User 的 AdminUser 类，添加 is_super_admin 布尔字段和 override_permissions() 方法。`

## 🗣 二、 使用有效的交互和命令

4. **利用内置命令 (**`/`**):**
   * `/fix`: 让 Cursor 尝试自动修复选中代码中的错误或警告。提供错误信息更佳。
   * `/doc`: 为选中的代码生成文档注释 (docstring, JSDoc, 等)。
   * `/edit`: 提供自然语言指令修改选中的代码 (极其常用且强大)。指令要具体！
     * *示例 (选中函数后)：* `/edit 添加一个可选参数 timeout_ms，默认值 5000，并在函数体开始处检查如果参数不是数字则抛出 TypeError`
   * `/ask`: 直接向 AI 提问（不生成代码）。
   * `/new`: 创建一个新文件并生成代码。记得提供充分上下文。
   * `/test`: 为选中的代码生成单元测试。
5. **迭代式开发 (小步快跑):**
   * 不要期望一次提示就生成完美、完整的大型模块。先生成核心功能或一个函数。
   * 基于生成的代码，再给出下一个提示进行补充、修改或优化。
   * *示例：* 1. 生成一个基础函数 -> 2. `/edit 添加输入参数验证` -> 3. `/edit 添加错误处理和日志` -> 4. `/doc` -> 5. `/test`
6. **要求解释或澄清:**
   * 如果生成的代码你看不懂或者觉得奇怪，直接问：`解释一下这段生成的代码是如何工作的？` 或 `为什么这里使用 reduce 而不是 map？`
   * 如果需求可能被误解了，让 AI 复述你的需求：`根据我的要求，你认为我需要实现哪些关键点？` 确认无误后再生成。

## 🛠 三、 添加约束和要求 (提升质量)

7. **指定代码风格和规范:**
   * 要求遵循特定风格 (PEP 8, Google Style, Airbnb JS, 等)。
   * 要求添加特定类型的注释。
   * *示例：* `// 用 Python 写，遵循 PEP 8，添加类型注解 (Type Hints)，并为关键步骤添加行内注释。`
8. **要求处理边界情况和错误:**
   * 明确要求考虑空输入、无效参数、网络错误、数据不一致等情况。
   * 要求添加适当的错误处理 (try-catch, 返回错误码, 抛出异常等)。
   * *示例：* `// 函数需要处理输入列表为空的情况，以及当 divisor 为 0 时抛出 ZeroDivisionError 异常。`
9. **要求优化性能或可读性:**
   * 如果对性能有要求，明确说明：`// 优化这个循环，使其时间复杂度为 O(n)。`
   * 要求生成更易读或更简洁的代码：`// 重写这段代码使其更 Pythonic。` 或 `// 用更简洁的 ES6 语法重构这个函数。`
10. **禁止特定做法:**
    * 明确告诉 AI **不要**做什么。
    * *示例：* `// 不要使用全局变量。` 或 `// 不要修改原始输入数组，返回一个新数组。` 或 `// 避免使用 eval()。`

## 📝 四、 优化提示本身

11. **结构化你的提示:**
    * 像写需求文档一样组织提示。可以使用注释符号 (`//`, `#`, `/* */`) 分隔不同部分 (目标、输入、输出、约束、示例)。
    * *示例：*

```plain
# 目标：将 Markdown 表格转换为 CSV 字符串
# 输入：一个字符串，包含有效的 Markdown 表格（例如：| Header1 | Header2 |\n|--------|--------|\n| Cell1  | Cell2  |）
# 输出：一个 CSV 格式的字符串（例如：'Header1,Header2\nCell1,Cell2'）
# 要求：
#   - 正确处理包含逗号或引号的单元格内容（用双引号包裹，内部双引号转义为两个）
#   - 去除 Markdown 表格中的多余空格和管道符
#   - 不要使用外部库（仅标准库）
# 语言：Python
```

12. **提供输入/输出示例:**
    * 给出一两个具体的输入示例和你期望的输出结果。这极大地帮助 AI 理解你的格式要求。
    * *示例 (接上)：*

```plain
# 示例输入： "| Name  | Age |\n|-------|-----|\n| Alice | 30  |\n| Bob, 'The Builder' | 25 |"
# 期望输出： 'Name,Age\nAlice,30\n"Bob, \'The Builder\'",25'
```

13. **使用清晰简洁的语言:**
    * 避免歧义和复杂的句子。使用准确的术语。

## 🔍 五、 审查和验证 (至关重要！)

14. **永远不要盲目信任生成的代码:**
    * **仔细阅读：** 逐行理解 AI 生成的代码。它可能看起来合理但有逻辑错误、安全漏洞或性能问题。
    * **测试：** 务必编写或运行测试来验证代码的正确性（利用 `/test` 生成测试是一个好的起点，但也要自己补充）。
    * **检查边界条件：** 特别测试 AI 容易忽略的边界情况（空输入、极值、错误输入等）。
    * **安全审查：** 警惕 SQL 注入、XSS、命令注入等安全风险。AI 生成的代码可能不安全。
    * **性能评估：** 对于关键代码，评估其性能是否可接受。

## 📌 总结关键点

* **上下文为王：** 提供语言、框架、项目相关文件、选中代码片段等。
* **具体明确：** 清晰描述功能、输入、输出、约束、边界条件。
* **善用命令：** `/edit`, `/fix`, `/doc`, `/test` 是核心生产力工具。
* **迭代优化：** 小步快跑，逐步完善代码。
* **施加约束：** 要求风格、错误处理、性能、避免特定做法。
* **提供示例：** 输入输出示例能显著提升准确性。
* **严格审查：** 生成的代码必须经过人工仔细检查、测试和评估。

**把 Cursor 看作一个极其强大但需要精确引导的编程助手。** 你提供的提示越清晰、具体、上下文丰富，并辅以有效的交互和严格的审查，它生成的代码质量就会越高。🎯
