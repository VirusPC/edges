若 tasks 随代码仓库存放，应考虑同一仓库的多人协作场景：例如任务写入与任务领取需要区分作者等身份字段。

**Why:**
单人看板可以靠 git 作者凑合；多人同仓时，谁提的 task、谁领取执行、谁验收，必须在 frontmatter / Run log 里可区分，否则状态流转与审计会对不上人。

**How to apply:**
- 细聊时定：作者（写入）、领取人/assignee、验收人等字段（建议落在 `edges-task-*`），以及与 git commit 作者的关系。
- 与「记录仓 vs 执行仓分离」「tasks 配套 skill」一起设计权限与回写规则（谁能改状态、谁能追加 Run）。
- 仍保持指派制语义：领取不等于公开抢单，但多人场景下指派与自称领取的规则要写清。
