task 需要进一步的分组能力，形态有点像需求管理（epic / 主题 / 需求集，而不只是按 edges-tasks-status 分夹）。

**Why:**
现在看板只有状态维；条目一多，同主题的 task（memory、CLI、跨仓等）会散落在 backlog 里难以一起规划。分组/需求层能把「一批相关工作」收成可排期、可验收的集合。

**How to apply:**
- 细聊时定分组模型：目录再分层、frontmatter 标签（如 `edges-task-group` / epic）、还是独立「需求」对象指向多个 task。
- 与状态机正交：分组不等于状态；一个 group 内可有多条不同 `edges-tasks-status`。
- 对照需求管理常见概念（epic、story、主题）取舍命名，避免和 Multica Issue 层混淆。
- 与 tasks 配套 skill、多人协作字段一并设计查询与列表接口。
