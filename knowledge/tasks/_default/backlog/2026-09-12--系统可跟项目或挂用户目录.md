这套系统很通用：既可以跟随项目走，也可以放到用户目录。例如 tasks 完全可以作为用户级的东西。想象中：用户目录下挂很多项目，每个项目有 tasks、user、feedback 等。这个思考过程很像 **Claude Code auto memory 的扩展**——同一套形状既能贴在仓里，也能抬到 `$HOME`。

**Why:**
现在 tasks / project-memory / user type 多半钉在单个 git 仓上。若协议同构，同一套「树 + type」就能在仓根和用户主目录各挂一层：跨项目的待办、偏好、纠正不必塞进某一个公开仓，删仓也不带走人。peng cheng 觉得这条推理本身值得留（套娃 / 同构 / 用户级 vs 项目级）。

**How to apply:**
- 先分清两层宿主：repo-scoped（跟项目、可提交或 gitignore）vs user-scoped（`~/.…` 下挂多个项目节点）。
- 想象形态：`$HOME/<system>/projects/<name>/{tasks,user,feedback,…}`，与仓内 `.memory` / `knowledge/tasks` 同构，而不是另做一套产品。
- 对照 Claude Code auto memory：哪些该学（自动落盘、跟人走），哪些不要照搬（真源仍要可检查、可 git）。
- 交叉：`整仓与 .memory 同构`、已落地的 user-memory+gitignore（删仓不删人）、可扩展 type、树算法。
- 细聊 grill-with-docs 再定宿主路径与是否双写。
