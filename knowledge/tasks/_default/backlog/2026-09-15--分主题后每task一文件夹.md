task 按项目主题分开之后，从存储和组织上应为**每个 task 建对应文件夹**。文件夹内有入口文件，说明 name、description 等元信息，以及项目/任务描述。

**Why:**
现在一条 task 基本是单文件 + sidecar log；主题/产物一多会挤在同一 md。一 task 一目录后，入口管元信息与描述，附件、子笔记、run 材料可以同夹存放。与「task 进一步分组（类需求管理）」不同：那条是主题/epic 层目录；本条是**单条 task 的存储单元**。也和交互式主题聚类相关，但聚类定主题，本条定落盘形状。

**How to apply:**
- 细聊路径：主题夹之下是否 `…/<task-id>/README或入口.md` + `.{stem}.log.md`；状态维还是否用状态夹还是 frontmatter。
- 入口文件字段与现有 `edges-task-*` / project-memory 结论→Why→How 对齐。
- 迁移与 CLI `edges tasks` 路径约定一并改；依赖 `task 进一步分组`、主题聚类条目，勿单独硬迁。
