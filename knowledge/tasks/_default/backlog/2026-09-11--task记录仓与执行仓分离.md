应考虑：task 记录的地方，与 task 领取/执行的地方，可能不在同一个仓库。

**Why:**
看板与事实源可以在 edges（`knowledge/tasks/`），而真正改代码的仓往往是业务仓；若 skill / Cloud Agent 默认「记录仓 = 执行仓」，跨仓指派、回写状态、挂 PR 链接都会拧巴。

**How to apply:**
- 细聊时显式建模：record repo（tasks 所在）vs execution repo（领取后干活的仓），以及状态回写、sidecar Run log、PR/commit 引用如何跨仓关联。
- 与「tasks 配套 skill 统一 CRUD 与状态流转」一并设计，避免接口写死单仓路径。
- 指派制下：领取/执行发生在执行仓会话，但 Issue 状态仍以记录仓为准。
