# 2026-09-27--Win11管理员通道OpenSSH与手机远控

> **今晚为何重要**：前一日只设计了「当面一次 UAC → OpenSSH + GrokBot-Admin」；当晚把通道真正落地，并打通 iPhone 经 Tailscale 用 Windows App 看屏。人不在机旁时，聊天确认后即可触发 SYSTEM 任务，SSH 也能进机。

## 背景

- 前序：[支线笔记](./2026-09-26--支线-企业WiFi-Comet收藏夹-Win助手与OpenSSH-灯光启动项.md)写明管理员通道「设计了但未全部落地」；[全网 Tailscale SSH](./2026-09-26--全网Tailscale-SSH开通与4070ts改名.md)写明 Windows **无** Tailscale SSH 服务端，应改走 OpenSSH / RDP。
- 用户意图：「详细说下方案」→「来吧，我准备好了」→ 中途外出吃饭 → 用 iPhone 远控回机继续 → SSH 实测成功 →「整理份笔记」。
- 同场旁支：Windows 用激活码激活成功；ChatGPT 开机启动项复查（实际已自启）；iPhone Windows App 列表不跟 Mac 同步。

## 主题

这场在把 Windows 的「远程代跑 + 看屏」从口头方案落成可复用通道。分层、契约、验收和否决项见下一节「前置方案」；当晚怎么落地见「过程」。

## 前置方案

前置方案要回答的不是「今晚点了哪些按钮」，而是：**在动手装 OpenSSH / 建 GrokBot-Admin 之前，先把问题、分层、契约、验收和否决项定死**，避免装到一半才发现 Windows 不能照搬 Linux，或误以为「聊一句就能远程最高权限」。

### 要解决的两件事

人不在键盘前时，运维其实需要两种能力，二者不要混谈：

1. **进得去**：有一个远程命令行会话，能看状态、跑不需要反复抬 UAC 的命令，排障时像登一台普通 SSH 主机。
2. **提得起权**：装可选功能、改服务、写 `ProgramData`、注册以 SYSTEM 运行的计划任务等，需要管理员或 SYSTEM。若每次都弹 UAC，人不在机旁就做不了；若从不确认就静默 SYSTEM，则权限过大、不可接受。

在已加入同一私网组网的 Linux / NAS / Mac 上，长期约定是打开基于身份的远程登录（Tailscale SSH），用邻机实测，而不是把往 `authorized_keys` 塞公钥当作长期方案。Windows 官方**不提供**该远程登录服务端，不能执行与 Linux 相同的「一键打开」；因此本机必须另建通道：**本机 OpenSSH 负责进得去，约定任务运行器负责提得起权**；私网只负责「怎么到达这台机」，不代替本机服务。

### 为何必须拆成两层

| 层 | 名称 | 解决什么 | 故意不解决什么 |
|---|---|---|---|
| 一层 | OpenSSH Server（`sshd`） | 远程交互式 / 非交互式 shell；从其它已入私网设备登录本机账户 | 不保证每次管理员操作免 UAC；默认会话仍是登录用户权限，不是 SYSTEM |
| 二层 | `GrokBot-Admin` + `run-job.ps1` | 聊天确认后，按需以 SYSTEM 执行 `jobs\pending` 中的脚本并归档、写日志 | 不替代「第一次建通道」时的当面或远控 UAC；也不代替人看屏点确认 |

只装一层不够：

- **只有 SSH**：人能登录，但装组件、改服务仍频繁依赖 UAC；外出时通道半残。
- **只有任务运行器**：提权路径有了，但缺稳定的远程 shell，排障和临时命令不方便；且第一次注册 SYSTEM 任务本身仍要提权。

因此前置方案的产品结论是：**两层都要落地**；**第一次建通道必须人能点 UAC**（人在机前，或已能用远程桌面点同意）；**通道就绪之后，日常管理员操作仍要聊天确认再触发任务**，确认是规则不是客套。

### 一层：OpenSSH 的前置约定

**角色**：在 Windows 上提供与 Linux「能 SSH 上去」对等的入口；私网（如 Tailscale）只提供到达路径，**真正监听 SSH 端口的是本机 `sshd`**。

**安装策略**（按优先级，并写明失败怎么办）：

1. 优先用 Windows 可选功能 / 能力包装 OpenSSH Server。
2. 若能力包装长时间无进展、日志冻结、服务始终不出现：视为挂死，**不要无限干等**；改用包管理器路径（如 winget 的 OpenSSH Preview 或等价包）完成安装，再设 `sshd` 开机自启并启动。
3. 脚本若只在能力包「抛异常」后才走备选，对「挂死不抛异常」无效——前置上要求备选必须能被超时或人工切换触发。

**网络意图**：SSH 主要经私网使用，而不是把监听端口当作长期公网入口。落地初期防火墙可能仍偏宽，属过渡态；前置目标是「私网可达即可运维」，收窄规则与密钥化属于后置加固。

**认证意图**：第一夜允许用本机账户密码打通，验证「进得去」。长期应变更为密钥登录（并视需要禁用或限制密码），公开记录中不保存任何口令或私钥。

**与「全网 Tailscale SSH」笔记的衔接**：其它服务器侧统一基于身份的远程登录；Windows 明确记为「无该服务端 → OpenSSH / RDP」。本前置方案就是那条分支的落地设计，而不是另起一套互相矛盾的标准。

### 二层：GrokBot-Admin 的前置约定

**角色**：在已完成第一次提权之后，提供「聊天确认 → 最高权限跑一段约定脚本」的可重复路径。

**目录与文件契约**（示意，路径可落在 `C:\ProgramData\GrokBot\`）：

- `jobs\pending`：投放待执行的 `.ps1`（普通用户需有写入约定权限）。
- `jobs\done` / `jobs\failed`：成功或失败后的归档，避免重复执行同一文件。
- `scripts\run-job.ps1`：计划任务实际调用的运行器（执行策略、超时、日志、移动文件的逻辑集中在此）。
- `logs`：安装日志、DONE 标记、作业输出；便于人不在场时事后核对。
- 可选 `bin`、以及兼容旧入口的 shim（若存在，应指向同一运行器，避免两套逻辑）。

**操作契约**（顺序固定）：

1. 助手（或人）将脚本放入 `pending`。
2. **在聊天中向用户说明将要做什么并取得确认**。
3. 触发计划任务：`schtasks /Run /TN GrokBot-Admin`（任务须允许交互用户在不重复抬 UAC 的前提下启动——这是建任务时就要配好的）。
4. 任务以 **SYSTEM、最高权限** 运行 `run-job.ps1`：选取 pending 中约定的脚本（通常为最新），捕获输出，写入 logs，再移到 done 或 failed。
5. 助手根据日志向用户回报结果。

**权限边界（必须写进前置）**：能够向 `pending` 写入任意脚本、并且能够触发该任务的主体，实质上接近 **SYSTEM 级控制**。因此：

- 不设「自动确认」；外出时若无法确认，就等待，不静默跑危险作业。
- 运行器应限制只跑 pending 目录内脚本、写日志、归档；不把「删光 ProgramData」之类做成默认能力。
- 公开库只描述机制，不描述如何绕过确认。

**WLAN 等本机杂项**：若同一次安装脚本附带关闭网卡 Magic Packet 唤醒等，属于顺手硬化，**不是**两层通道的必要条件；失败不应阻断 SSH / 任务验收。

### 与「看屏」远控的分工

- **SSH + GrokBot-Admin**：给远程运维与助手自动化用。
- **远程桌面（如 iPhone 上的 Windows App）**：给人看完整桌面、在需要时点 UAC、处理图形界面。私网在线是前提；本机须已允许远程桌面。
- **Agent 自己的桌面自动化 / 浏览器协议**：与「Chrome 远程桌面」产品不是同一条路；本前置方案不以 Chrome 远程桌面为依赖。
- **跨设备主机列表**：个人自建 PC 的连接项通常保存在本机客户端，Mac 上连过一次**不会**自动出现在 iPhone；手机需自行「添加 PC」。卡在 Initializing 时，优先查手机私网客户端是否离线，再查本机远程桌面服务与端口。

有了手机远控之后，「第一次 UAC 必须当面」可以放宽为「人能通过远控点到同意」；**不能**放宽为「完全无人确认就建 SYSTEM 通道」。

### 一次性落地的验收清单

下列全部成立，才算前置方案落地完成（与是否写过长文无关）：

1. OpenSSH 服务存在，开机自启，约定端口在监听。
2. 计划任务 `GrokBot-Admin` 存在，配置为 SYSTEM / 最高权限 / 可按需运行，且约定用户可触发。
3. `run-job.ps1` 与 pending/done/failed/logs 目录就位；有可复查的安装日志或 DONE 标记。
4. 从另一台已加入同一私网的设备，能用本机账户 SSH 登录成功。
5. （强烈建议）手机或其它设备能经私网进入远程桌面，以便日后再次点 UAC。

未完成前：助手必须按「通道未就绪」行事——继续用一次性 UAC / RunAs，并明确告知用户，而不是假装管理员远程已可用。

### 明确不做的否决项

- 不使用破解、假 KMS、盗版激活等手段处理授权问题。
- 不把「往 authorized_keys 塞公钥」当作 Windows 侧长期替代私网 + OpenSSH 的主方案（与全网服务器侧口径一致：身份远程登录优先；Windows 则是 OpenSSH + 私网）。
- 不在目录与任务未就绪时，假设「聊天确认即可远程最高权限」。
- 不擅自重启主机（若用户约定有并行任务或禁止自动重启）。
- 不把 Chrome 远程桌面或其它第三方远控，写成 Agent 控机的主桥。

### 一句话定义

**前置方案 = Windows 不能用官方 Tailscale SSH 服务端 → 用本机 OpenSSH 解决「进得去」→ 用 GrokBot-Admin 解决「提得起权」→ 第一次建通道必须人能确认 UAC → 日常管理员操作必须聊天确认后再触发 SYSTEM 任务；远程桌面只给人看屏与点同意，不是助手的主控通道。**

## 所学

- Windows 远程代跑应拆成「命令行服务」与「提权任务运行器」两层；不能拿 Linux 的 Tailscale SSH 硬套。
- 能力包装挂死 ≠ 无网：要有**超时 / 备选安装路径**（winget），不能只等异常。
- 手机远控 Initializing：先查手机 Tailscale 是否在线，再查本机 RDP。
- 跨设备「已保存的 PC」对个人 RDP 往往不同步；不要假设 Mac 列表会到 iPhone。
- 管理员通道权限等同可触发 SYSTEM：落地后仍须聊天确认；22 对任意来源开放只适合过渡。

取舍补充：

- 激活：破解 / 假 KMS vs 正版密钥或组织 KMS——认合法路径；用户最终自备激活码。
- OpenSSH 安装：Windows 能力包 vs winget Preview——能力包优先但挂死后必须切 winget。
- 手机远控：Chrome 远程桌面 vs Windows App + Tailscale——已有 Tailscale 时认后者。
- Agent 控机：不依赖 Chrome 远程桌面。

## 行动指南

### 主题行动指南

#### 背景

一台常开的 Windows 需要「人不在键盘前也能运维」，且官方没有基于身份的 Tailscale SSH 服务端；另需偶尔用手机看屏。

#### 核心问题

如何在只当面（或远控能点）一次提权的前提下，得到可重复的：远程命令行、聊天确认后的管理员任务、以及手机私网远控。

#### 核心解决方案

按「前置方案」执行，不在这里再列一套：一次确认装上 OpenSSH 与 GrokBot-Admin；能力包挂死改走包管理器；日常管理员作业先聊天确认再触发；看屏走私网上的远程桌面。

#### 验收标准

与「前置方案」里「一次性落地的验收清单」相同。

### 细节与其他

#### 若再装管理员通道（本机约定）

则：

1. 目录：`C:\ProgramData\GrokBot\`（`scripts`、`jobs\pending|done|failed`、`logs`、`bin`）；运行器 `scripts\run-job.ps1`。
2. 任务名：`GrokBot-Admin`（SYSTEM、最高权限、按需）。
3. 触发：向 `jobs\pending\` 投放 `.ps1`，再 `schtasks /Run /TN GrokBot-Admin`（先聊天确认）。
4. 安装日志 / DONE：`C:\ProgramData\GrokBot\logs\admin-channel-install.txt` 与 `admin-channel-install.DONE`。
5. 能力包装挂死：停掉卡住的安装后，用 winget 安装 OpenSSH Preview（或等价包），再配置 `sshd` 自启并注册任务。可选项：只重试能力包——本次已证明会挂死，不优先。

#### 若用 iPhone Windows App 连本机

则：

1. 手机 Tailscale 须 Connected，节点在线。
2. App 内「添加 PC」，填 Tailscale 短名或私网地址；用户名用本机账户（可带 `计算机名\` 前缀）。
3. 密码用 Windows 登录密码；不要发到聊天。
4. 卡在 Initializing：先看手机 Tailscale 是否 offline，再查本机远程桌面服务与端口。可选项：Chrome 远程桌面——无私网时可用；已有 Tailscale 时不必再开一套。

#### 若 SSH 登录

则：从已加入同一 Tailscale 的机器 `ssh` 到该 Windows 短名或私网地址，用户名与本机账户一致。长期应改为密钥并收窄防火墙；当时未比较其它堡垒方案。

#### 若复查开机启动项「没起来」

则：先看用户启动文件夹快捷方式与当次登录后的进程启动时间，再查「启动应用」是否被禁用。本次 ChatGPT 实为已自启，窗口可能被遮挡。
