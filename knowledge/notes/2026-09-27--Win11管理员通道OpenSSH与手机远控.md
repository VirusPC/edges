# 2026-09-27--Win11管理员通道OpenSSH与手机远控

> **今晚为何重要**：前一日只设计了「当面一次 UAC → OpenSSH + GrokBot-Admin」；当晚把通道真正落地，并打通 iPhone 经 Tailscale 用 Windows App 看屏。人不在机旁时，聊天确认后即可触发 SYSTEM 任务，SSH 也能进机。

## 背景

- 主机：Windows 11 专业工作站版，已就地升级到 **25H2**（本机名仍为长名；Tailscale 短名此前定稿）。专用设备助手负责本机运维。
- 前序：[支线笔记](./2026-09-26--支线-企业WiFi-Comet收藏夹-Win助手与OpenSSH-灯光启动项.md)写明管理员通道「设计了但未全部落地」；[全网 Tailscale SSH](./2026-09-26--全网Tailscale-SSH开通与4070ts改名.md)写明 Windows **无** Tailscale SSH 服务端，应改走 OpenSSH / RDP。
- 用户意图：「详细说下方案」→「来吧，我准备好了」→ 中途外出吃饭 → 用 iPhone 远控回机继续 → SSH 实测成功 →「整理份笔记」。
- 同场旁支：Windows 用激活码激活成功；ChatGPT 开机启动项复查（实际已自启）；iPhone Windows App 列表不跟 Mac 同步。

## 主题

这场在把 Windows 的「远程代跑 + 看屏」从口头方案落成可复用通道：OpenSSH 服务端、SYSTEM 计划任务运行器、以及手机经私网连远程桌面；并厘清能力包装挂死时的备选与远控初始化失败的常见原因。

- 难点：Windows 不能 `tailscale set --ssh`，必须本机 OpenSSH；第一次提权仍须当面（或远控能点）UAC。
- 难点：`Add-WindowsCapability` 装 OpenSSH 可长时间无进度条且挂死；winget 备选若只在「抛异常」后才触发，会干等。
- 难点：iPhone Windows App 与 Mac 的主机列表不共享；卡在 Initializing 时常是手机 Tailscale 离线，不是本机 RDP 坏了。
- 难点：管理员通道等于「可写 pending 脚本 + 触发 SYSTEM 任务」——权限极大，须聊天确认，且 22 端口不宜裸对公网。

## 前置方案

当晚动手之前，这条通道还只是前一日的口头设计：人在机旁点一次 UAC，把「进得去」和「提得起权」一次装上，之后人不在键盘前也能运维。这一节把那份设计写开。它回答的是落地之前必须先认的结构，不是当晚的时间线；时间线仍在下一节。

### 进得去，和提得起权

要分开的是两件不同的事。进得去，是从另一台已经在同一私网里的机器得到一条远程命令行，能登录、能看状态、能跑登录账户权限下的命令。提得起权，是没有人坐在这台 Windows 前面的时候，仍然能做必须管理员或 SYSTEM 才能做的事，而且每一次都要先在聊天里确认。

Linux 上这两件事常常叠在 Tailscale SSH 里。节点在线之后执行 `tailscale set --ssh`，由 Tailscale 自己提供基于身份的 SSH 服务端；邻机用身份登录，需要提权时再走那台机器上已经有的 sudo。Windows 不能照搬。官方没有 Windows 版的 Tailscale SSH 服务端，`tailscale set --ssh` 在这里没有对应的被连端。私网只能把数据包送到这台机器，不能代替本机去听 SSH，更不能代替一次 Windows 提权。远程命令行必须落在本机 OpenSSH 上，提权必须另有一条 Windows 自己的管理员通道；看屏幕则走远程桌面，不用它来冒充 SSH。

### 为何拆成两层

两层各管一件事，也各有明确做不到的事。

OpenSSH Server 解决的是远程命令行：`sshd` 开机自启，在约定端口上听，同一私网里的机器用本机账户登录。它解决不了「人不在、又要最高权限」。Windows 的 SSH 会话落在登录账户上，管理员操作仍会碰到 UAC；没有人能点确认的时候，交互式提权就停在那里。只装 OpenSSH，远程能进，提权仍然依赖当场有人。

GrokBot-Admin 解决的是提权之后的重复执行：一个以 SYSTEM、最高权限、按需运行的计划任务，去跑事先放进约定目录的脚本。它解决不了「人已经离开、却还没有远程入口」。任务本身不会把脚本从聊天里变到磁盘上，也不会自己变成一条交互式 shell。只装这一层，人在机旁可以触发，人不在就连投放脚本的路径都没有。

所以两层都要在同一次当面安装里建好。远控已经能点到 UAC 时，那一次点击也可以算作当面。先有 OpenSSH，才有离开键盘之后的命令行；先有 GrokBot-Admin，这条命令行才不必每次再弹一次交互式 UAC。缺任意一层，另一层都接不上「人不在机旁」这个前提。

### 第一层：OpenSSH Server

安装顺序是能力包优先，挂死再换包管理器。首选 `Add-WindowsCapability` 安装 `OpenSSH.Server`，这是系统自带的组件路径。这一步可以长时间没有进度条，后台只有组件存储在干活，界面上常常看不到下载窗口。静默不等于失败，但这次已经证明它会真的挂住：日志停住，既没有 `sshd`，也没有后续任务。脚本若只在能力包抛出异常之后才去 winget，就处理不了「不报错、只是不再动」的挂死，会一直干等。因此约定是：长时间无进展就停掉卡住的安装，改用 winget 安装 OpenSSH Preview（或当时等价的包），再把 `sshd` 配成开机自启。只反复重试同一个能力包，不作为优先路径。

网络意图是私网为主。Tailscale 在这里只提供到达路径：此前定稿的短名，或私网地址，能把连接送到这台机器。听端口、做认证、拉起会话的是本机 `sshd`，不是 Tailscale。没有 `sshd` 在听，私网在线也登不进去。22 对任意来源开放只适合安装当夜的过渡，长期应收窄到仅私网可达的范围。公开笔记不写具体地址。

认证是过渡，不是终态。落地当夜沿用 Windows 默认的密码登录，账户就是本机账户，这样邻机可以立刻实测。这不是要长期保留密码登录。后续应改成仅密钥，并收紧防火墙。密钥材料和登录密码都不进这篇笔记，也不发到聊天。

### 第二层：GrokBot-Admin

目录约定在 `C:\ProgramData\GrokBot\`。其下分 `scripts`、`jobs\pending`、`jobs\done`、`jobs\failed`、`logs`、`bin`。运行器是 `scripts\run-job.ps1`。计划任务名叫 `GrokBot-Admin`，以 SYSTEM、最高权限、按需运行，不做成登录时自动乱跑的任务。安装过程的日志和完成标记放在 `logs\admin-channel-install.txt` 与 `admin-channel-install.DONE`。

操作契约是一条固定链，不能跳步。先把要跑的 `.ps1` 放进 `jobs\pending\`。然后在聊天里确认这次允许执行。确认之后才 `schtasks /Run /TN GrokBot-Admin`。任务拉起运行器，由 SYSTEM 执行 pending 里的作业，再按结果归档到 `done` 或 `failed`。没有聊天确认就触发，不算按这套方案操作。

权限边界要按最坏情况理解：能往 pending 里写脚本，并且能触发这个任务，就等于能以 SYSTEM 做事。通道落地并没有把权限变小。它只是把「每次都要人点 UAC」换成「每次都要聊天确认」。确认仍然必须发生；无确认的静默 SYSTEM 作业不在方案里。

### 看屏另算一条，不充当主桥

远程桌面和 Windows App 负责给人看屏幕、点 UAC，也负责在安装卡住或人已经离开键盘时把会话接回来。它不负责 Agent 的主通道。Agent 进命令行走 OpenSSH，做管理员作业走 GrokBot-Admin。看屏成功，不等于管理员通道已经可用；SSH 登录成功，也不等于手机上的桌面会话已经通。

这条看屏路径和 Chrome 远程桌面无关。已有 Tailscale 时，用 Windows App 添加这台 PC，走本机远程桌面即可，不必再挂一套另外的远控。Agent 客户端和这台机器之间的桥接同样不经过 Chrome 远程桌面。Mac 上保存过的主机列表不会自动出现在 iPhone 上；家庭自建的机器通常也不靠登录微软账户来同步列表，要在手机上单独添加。卡在 Initializing 时，先看手机这一侧的 Tailscale 是否在线，再查本机远程桌面服务和端口。

### 一次落地要验收什么，以及明确不做

同一次安装结束时，用清单验收，而不是用「脚本好像跑完了」代替。OpenSSH 服务在跑，并且开机自启，约定端口在听。`GrokBot-Admin` 处于可按需触发的就绪状态，`run-job.ps1` 和目录已经就位，安装完成标记已经写上。从另一台已加入同一私网的设备，用本机账户 SSH 登录成功。需要看屏时，手机私网在线，远程桌面能进桌面，而不是停在初始化。这几项都过，才算前一日设计的通道真正落地。

明确不做的有这些。不走破解，也不再装一套假的 KMS；激活只认用户自己的合法途径。通道还没建起来时，不假设聊天里说一句就能远程拿到最高权限。不在没有聊天确认的情况下静默跑 SYSTEM 作业。能力包挂死时不无限干等，也不把「只重试能力包」当成优先。不擅自重启；计算机名仍是长名，改名需要重启，此前已经约定不擅自做。不把 22 和 3389 对公网任意来源长期开放当成常态。不指望另一台电脑上的远程桌面列表自动同步到手机。已有私网时，不为了看屏再开一套 Chrome 远程桌面。

### 这套前置方案指什么

前置方案就是：当面或远控能点到的那一次 UAC，同时装上 OpenSSH 与 GrokBot-Admin；此后进机器用私网上的 SSH，提权用「投放、聊天确认、再触发」的 SYSTEM 任务，看屏幕用 Windows App 的远程桌面。三件事分工不同，都不能互相替代。

## 所学

- Windows 远程代跑应拆成「命令行服务」与「提权任务运行器」两层；不能拿 Linux 的 Tailscale SSH 硬套。
- 能力包装挂死 ≠ 无网：要有**超时 / 备选安装路径**（winget），不能只等异常。
- 手机远控 Initializing：先查手机 Tailscale 是否在线，再查本机 RDP。
- 跨设备「已保存的 PC」对个人 RDP 往往不同步；不要假设 Mac 列表会到 iPhone。
- 管理员通道权限等同可触发 SYSTEM：落地后仍须聊天确认；22 对任意来源开放只适合过渡。

取舍补充：

- 激活：破解 / 假 KMS vs 正版密钥或组织 KMS——认合法路径；用户最终自备激活码。
- OpenSSH 安装：Windows 能力包 vs winget Preview——能力包优先但挂死后必须切 winget。
- 手机远控：Chrome 远程桌面 vs Windows App + Tailscale——已有 Tailscale 时认后者。
- Agent 控机：不依赖 Chrome 远程桌面。

## 行动指南

### 主题行动指南

#### 背景

一台常开的 Windows 需要「人不在键盘前也能运维」，且官方没有基于身份的 Tailscale SSH 服务端；另需偶尔用手机看屏。

#### 核心问题

如何在只当面（或远控能点）一次提权的前提下，得到可重复的：远程命令行、聊天确认后的管理员任务、以及手机私网远控。

#### 核心解决方案

1. 当面或远控下完成一次性管理员安装：OpenSSH 服务端 + 约定目录下的 SYSTEM 计划任务运行器。不做：假设聊天一句即可远程最高权限却从未建过通道。
2. 能力包装若长时间无进展：超时后改用包管理器安装 OpenSSH，不要只等能力包异常。不做：无限干等无进度条的能力包。
3. 日常管理员操作：把脚本放入 pending，聊天确认后触发约定任务。不做：无确认静默跑 SYSTEM 作业。
4. 手机看屏：私网组网在线后，用系统远程桌面客户端「添加 PC」连接；本机先开远程桌面。不做：指望另一台电脑上的主机列表自动同步到手机。
5. 收紧访问：优先仅经私网使用 SSH/RDP；长期改为密钥登录并收窄防火墙。不做：长期把 22/3389 对公网任意来源开放当常态。

#### 验收标准

- OpenSSH 服务在跑且开机自启；约定端口在听。
- 约定名称的 SYSTEM 计划任务存在，且能按需触发运行器。
- 从另一台已加入同一私网的设备 SSH 登录成功。
- 手机私网在线时，远程桌面客户端能进入桌面（不长期卡在 Initializing）。

### 细节与其他

#### 若再装管理员通道（本机约定）

则：

1. 目录：`C:\ProgramData\GrokBot\`（`scripts`、`jobs\pending|done|failed`、`logs`、`bin`）；运行器 `scripts\run-job.ps1`。
2. 任务名：`GrokBot-Admin`（SYSTEM、最高权限、按需）。
3. 触发：向 `jobs\pending\` 投放 `.ps1`，再 `schtasks /Run /TN GrokBot-Admin`（先聊天确认）。
4. 安装日志 / DONE：`C:\ProgramData\GrokBot\logs\admin-channel-install.txt` 与 `admin-channel-install.DONE`。
5. 能力包装挂死：停掉卡住的安装后，用 winget 安装 OpenSSH Preview（或等价包），再配置 `sshd` 自启并注册任务。可选项：只重试能力包——本次已证明会挂死，不优先。

#### 若用 iPhone Windows App 连本机

则：

1. 手机 Tailscale 须 Connected，节点在线。
2. App 内「添加 PC」，填 Tailscale 短名或私网地址；用户名用本机账户（可带 `计算机名\` 前缀）。
3. 密码用 Windows 登录密码；不要发到聊天。
4. 卡在 Initializing：先看手机 Tailscale 是否 offline，再查本机远程桌面服务与端口。可选项：Chrome 远程桌面——无私网时可用；已有 Tailscale 时不必再开一套。

#### 若 SSH 登录

则：从已加入同一 Tailscale 的机器 `ssh` 到该 Windows 短名或私网地址，用户名与本机账户一致。长期应改为密钥并收窄防火墙；当时未比较其它堡垒方案。

#### 若复查开机启动项「没起来」

则：先看用户启动文件夹快捷方式与当次登录后的进程启动时间，再查「启动应用」是否被禁用。本次 ChatGPT 实为已自启，窗口可能被遮挡。
