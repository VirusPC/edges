# 2026-09-26--家庭实验室断电恢复与有线局域网总览

> 由当晚多助手实操整理。公开库已脱敏：不含 Tailscale 私网数字地址、授权链接、密码与 API token。完整含地址的台账在本地协作目录。本篇是总览，细节见各主题笔记。

## 背景

用户常开的一台 Linux 小主机当晚突然失联，原话是问「是不是掉线了」，随即说明「电源断了下，刚重新开机」。由此展开：不间断电源选型、默认进 Linux、一键恢复脚本、全网基于身份的远程登录、用交换机把多台机器收成同一有线局域网、NAS 共享在多端挂成磁盘、审计每台的 Tailscale 与隧道客户端、以及用手机/笔记本控 Windows 屏幕。用户后来说今晚这些事情非常重要，要求按主题写成可复盘的详细笔记。

## 主题

整晚在办一件事：给家庭实验室装上可重复的复电与基础设施主线——常开枢纽能回到约定系统并代跑恢复、各服务器侧能基于身份远程登录、有线同网且单网关定稿、共享存储当磁盘用、组网与隧道客户端可审计、屏幕远控可收藏。

- 难点：失联要先分清是助手灰还是整机死；「组网在线」不等于「基于身份的免密远程登录」，沙盒图形客户端还可能故意当不了被连端。
- 难点：「存储核心」和「网关 / DHCP 核心」不是同一个问题；有没有独立路由器必须先问清，否则拓扑会写错。
- 难点：共享存储的产品化靠子目录约定，不靠每新建一个共享就全网自动出盘符；人不在键盘前时，第一次提权仍要当面。

## 过程

### 19:43–20:16 复电与默认系统

确认是整机不在网而非只灰助手；指导固件菜单选 Linux、把盘内启动顺序改成 Linux 优先；写好运维恢复脚本并在远程登录打通后代跑；外网、共享盘、容器等项恢复为可用。讨论 UPS：要约半小时续航须看电池能量与 USB 通信自动关机，不能只看 VA 数字。脚本曾出现「已在网却被误判未入网」的假警报，当晚修好。

### 20:07–21:05 远程登录齐套

在 Linux 小主机、NAS、云主机、台式 Mac 上打开基于身份的远程登录；Mac 必须卸掉沙盒图形客户端改用系统级守护进程才能当「被连端」。NAS 曾误判在容器里，实际系统包已在跑；遇 Permission denied 不盲重试。Windows 新机不能当 Tailscale SSH 服务端，改为系统 OpenSSH / 远程桌面，并新建专用设备助手；显示名缩短为好记短名。

### 21:37–23:40 有线局域网定稿

用非管理型交换机把多机接到同一网段；用户明确没有独立路由器，靠常开小主机当网关与地址分配。澄清 NAS 自有有线网卡、无 Wi‑Fi；Windows「没连 Wi‑Fi 也能上」是因为网线经交换机走到小主机出口。此前助手曾偏 NAS 当「房子地基」、理想图也曾是「独立路由器 DHCP + 交换机旁挂」，最终按用户口径定稿为无独立路由器、枢纽兼任网关。

### 23:45–23:55 NAS 当磁盘

Windows 映射多盘符，Mac 挂到用户目录下 NAS 文件夹，Linux 写进开机自动挂载。讨论过浏览即用、开机自动挂、清单脚本、少建共享用子目录四种手段，用户选「先同步 photos + 少建共享」；约定以后优先在已有数据共享下用英文子目录作为全家共通入口。

### 00:01–00:05 客户端审计

表格式核对 Tailscale 与隧道客户端；给 Windows 补装隧道命令行（尚未登录开隧）；修好 Mac 卸图形版后命令行指错路径的问题。

### 00:08–00:36 屏幕远控

Mac 对 Mac 继续屏幕共享；对 Windows 用 Windows App / 远程桌面，并在专业版上启用远程桌面；账号用系统密码而非 PIN；关掉自动锁屏以免远控被打断。Ubuntu 桌面远控当晚只讨论未强制落地。

### 散点 支线

企业 Wi‑Fi 按 PEAP 策略配置，且约定 NAS 不上企业无线；密码共享库边界；Windows 更新与 Wi‑Fi 驱动；机箱灯与开机启动项等。详见支线主题笔记。

## 结果

做成了：

- 常开枢纽复电路径跑通：默认 Linux、恢复脚本可代跑、外网与共享挂载等检查通过。
- 四台服务器侧基于身份的远程登录齐套；Mac 换成非沙盒守护进程；Windows 定短名并改走 OpenSSH / 远程桌面。
- 交换机四机同网定稿；无独立路由器，常开枢纽兼任网关与地址分配。
- 三端把 NAS 共享当磁盘用；定下 `data/shared` 少建独立共享约定；photos 已补挂。
- Tailscale / cloudflared 审计表对齐；Windows 补装 cloudflared；Mac CLI 修好。
- Windows 远程桌面已启用，可用短名从 Mac 侧 Windows App 收藏。

还剩：

- UPS 只定选型原则，**未下单**。
- Windows 上 cloudflared **尚未 login / 开隧**。
- Mac 对 NAS 的挂载当时仍走组网触点（有线未通），属技术债，通线后应迁回局域网。
- Windows 管理员通道（OpenSSH + 约定任务运行器）**设计了但未全部落地**；系统大版本更新曾遇错误码，需重启后再试。
- Ubuntu 桌面远控未强制落地。

## 所学

- 失联要先分「助手灰」还是「整机死」；复电能力 = 默认系统正确 + 恢复流程 + 可远程代跑。
- 「网上」不等于「基于身份的免密远程登录」；图形沙盒客户端可能故意不提供被连端。
- 「存储核心」和「网关核心」不是同一个问题；有没有独立路由器必须先问清。
- 存储共享的产品化靠「子目录约定」，不靠每新建一个共享就全网自动出盘符。
- 人不在键盘前时，第一次提权仍要当面；之后才能用管理员任务通道。

取舍补充：

- 网关角色：曾偏 NAS 当地基、也曾设想独立路由器；当晚无独立路由器，最终认常开 Linux 枢纽兼任单网关 / 单 DHCP / 出口，不做第二套地址分配。
- Mac 被连端：沙盒图形客户端当不了被连端，必须卸掉改系统级守护进程，不能靠图形版凑合。
- Windows 远程：官方无 Tailscale SSH 服务端，不硬套 Linux 开关，改走本机 OpenSSH / 远程桌面。
- 共用材料：四种手段里选「少建独立共享 + 子目录」，不选每新建共享就全网补挂的路径。

## 行动指南

### 主题行动指南

#### 背景

家庭实验室依赖一台常开枢纽做组网入口与（常兼）局域网出口；多机要同网、共享存储要当磁盘用，还要能远程登录和看屏幕。

#### 核心问题

枢纽失联或基础设施未定稿时，缺少一条可重复执行的主线：如何从复电走到「远程可代跑、有线同网、共享可用、远控可收藏」，并让以后当真当任务执行时有明确完成标准。

#### 核心解决方案

按顺序推进整晚主线（细节见各主题笔记）：

1. 复电：确认整机级问题 → 进入约定默认系统 → 跑固定恢复流程 → 需要时经基于身份的远程登录代跑。相关可选项：只重启助手或只查网络——不够，整机断电级必须先物理开机并进对系统。
2. 远程登录齐套：各服务器侧打开基于身份的远程登录并用邻机实测；Mac 用非沙盒守护进程；Windows 改走本机 OpenSSH / 远程桌面。不做：用沙盒图形客户端当被连端；也不把公钥塞进 authorized_keys 当作长期替代。
3. 有线局域网：非管理型交换机同网段；常开枢纽兼任单网关 / 单 DHCP / 出口；禁止第二套 DHCP。不做：再开第二套地址分配，或把「存储核心」误当成网关核心。
4. 共享存储磁盘化：多端对齐映射；少建独立共享，多用约定子目录。不做：每新建一个独立共享就指望客户端自动出盘符。
5. 客户端审计：用「主机 × Mesh 客户端 × 隧道客户端」矩阵验收，缺项补齐。不做：只看控制台绿点就下结论。
6. 屏幕远控：启用远程桌面入口，用系统账户密码，收藏短名。不做：公网裸奔远程桌面；也不用 PIN 当远程密码。

#### 验收标准

以后按本总览主线执行时，下列全部成立才算完成：

- 常开枢纽能进入约定默认系统，恢复流程可通过。
- 需要代跑的节点已具备基于身份的远程登录（或 Windows 的替代远程命令行/桌面方案），并经邻机实测。
- 有线同网，默认路由指向约定的单网关枢纽，无第二套 DHCP。
- 共享存储在约定客户端上可当磁盘用，新材料有统一入口约定。
- 屏幕远控入口可按短名稳定进入（若本轮需要控屏）。

### 细节与其他

#### 若小主机再断电

则：确认进入约定默认系统后，跑恢复流程或经基于身份的远程登录代跑，再查共享盘与容器。细节见复电主题笔记。相关可选项：只等助手自己变绿——不够，须确认整机与默认系统。

#### 若新 Linux 或 NAS 入网且要远程代跑

则：加入 Tailscale 后打开基于身份的远程登录，并用另一台已通节点实测。Mac 须先换成非沙盒守护进程。不做：往 authorized_keys 塞公钥当作长期替代；Windows 则不要硬套同一开关。

#### 若再有文件要全家共用

则：优先放进已有数据共享下的约定子目录；只有权限或备份策略要求时才新建独立共享，并在各端补挂。不做：每共用一次就新开独立共享。

#### 若要从 Mac 或手机看 Windows 屏幕

则：确认专业版已启用远程桌面、短名已知、使用系统账户密码（不是 PIN），再走 Windows App。不做：公网裸奔；若只要命令行则走 OpenSSH / 本机执行即可。

#### 若稿件要进公开知识库

则：先去掉 Tailscale 数字地址、密钥、授权链接与密码，再入库。当时未比较其它脱敏方案。
