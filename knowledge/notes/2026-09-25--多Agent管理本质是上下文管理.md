# 多 Agent 管理的本质是上下文管理

> 2026-09-25，peng cheng spark。

## 核心主张

管理多个 Agent，本质就是在管理上下文。关键不只是增加 Agent 数量，而是把复杂任务拆成彼此独立、低耦合的部分，并控制每个 Agent 看见什么、交接什么。

## 要点

- 思考如何把复杂任务拆成一个个独立、解耦合的部分；
- 思考如何进行**最小的信息交换**，在减少上下文搬运的同时达成最好的效果；
- 软件工程里的**高内聚、低耦合**，在 Agent 的职责划分与上下文边界上同样关键。

## Insights（轻量）

- Agent 边界大致就是上下文边界。职责不清时，上下文容易互相污染，交接内容也会膨胀。
- 「最小信息交换」对应接口契约：交接只传递对方做决策或执行所需的信息，不把整段 transcript 搬过去。
- Grok Bot 的多 bot 协作、交接 loop，以及 Edges 的任务卡和笔记外脑，都可以作为这个判断的实践互证：交接要闭环，本质上也是上下文与信息交换问题。可参见：[Grok Bot / Artifacts 预览与交接 loop](./2026-09-25--Grok-Bot-Artifacts预览与交接loop.md)。

## Actions（轻量）

- 拆分多 Agent 任务时，先写清每个 Agent 的职责、输入、输出和上下文边界。
- 设计交接时，优先定义最小接口契约，并用任务卡或笔记记录足以让下一位继续执行的信息。
