# edges CLI 多命令架构：关键设计

## 【背景】

`extensions/clis` 从单用途 `edges-note`（手写 parse / 后改 Commander + 默认 ingest）收成多命令 **`edges`**。产品决定：Note 是子命令之一，后面还有 Tasks 等；不保留 `edges-note` shim，根目录不默认入库。相关实现落在 PR #37（合入前以该分支为准）。

## 【过程】

### 三层分工

```
agent
 ├─ edges CLI          extensions/clis/                 # 有 shell 时优先
 ├─ bin/new-note                                       # 唯一真正跑 git 的实现
 └─ new-note MCP       extensions/mcp-servers/new-note # 无 shell 宿主
```

CLI 与 MCP 都 `execFile` 同一条 `bin/new-note`；MCP 不套 CLI。Git 逻辑不进 TypeScript。

### 命令树

包名 `edges-cli`，二进制 **只有** `edges`：

```
edges note …      # 笔记入库（现有能力）
edges tasks …     # 占位，尚无业务
edges --help / -v
```

根上不带子命令 = 用法错误，不跑 note ingest。无 `edges-note` / 无根级默认 ingest / 子命令不叫 `ingest`。

## 【所学】关键设计点

1. **多命令外壳，单职责内核**  
   Commander（`program.ts`）只管命令树与 flags；`note` 之后仍是校验 → auth → service → scriptAdapter → `bin/new-note`。

2. **Agent 契约**  
   stdout 始终 JSON；进度走 stderr；exit：0 成功 / 2 校验 / 4 鉴权 / 1 运行时。`--json` 保留（agent 熟悉的开关）。

3. **鉴权挂在 `note` 上**  
   与 MCP HTTP 同一道可选门：`EDGES_AUTH_TOKEN` 若设置，须 `--token-file` 或 `--token-stdin`（非 TTY）；绝不把 token 放 argv。暂不拆成 `edges auth`。

4. **显式迁移、不留双入口**  
   不保留 `edges-note` shim，避免双 bin 与「根默认命令」锁死命令树；调用方统一 `edges note …`。

5. **`tasks` 先占坑**  
   命令树可见；调用则 usage error，待任务板实现再填。

6. **放置位置**  
   CLI 在 `extensions/clis/`，不放仓库根；本地 agent 走 CLI、无 shell 走 MCP。

## 【行动指南】

- 新能力优先加 `edges <subcommand>`，不要再做一个并列 bin。
- 改入库 / 鉴权时同时核对 MCP 与 CLI 是否仍共用 `bin/new-note` 与同一 token 门闩。
- 更细的操作约定见 `extensions/.memory/projects/project_clis_from_mcp.md`（extensions 侧 project memory）。
