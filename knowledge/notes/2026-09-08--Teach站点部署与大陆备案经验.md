【讨论主题】
在教学助手会话中完成一条完整链路：用 teach skill 建 changelog 教学工作区 → 合并进 VirusPC/edges 的 `knowledge/teach/` → 部署到阿里云国内 ECS（nginx 静态站）→ Cloudflare 绑定 `teach.viruspc.tech` 并开公网 → 撞上大陆未备案拦截 → 明确可用入口与备案分工。本文把可复用的部署与排障经验写全，供后续同类站点参考。

【主要结论】
(事实与共识)

## 1. 教学工作区（teach skill）

- **触发**：用户要求「教我 changelog」；目标定为「给自己的项目写好 `CHANGELOG.md`」。
- **Mission 要点**：按约定写出真实发布条目；区分 Added/Changed/Fixed/Deprecated/Removed/Security；分清 changelog 与 git commit、release notes 的职责。教学中文、术语保留英文；暂不深挖完整 semver 策略与 Conventional Commits 全流程。
- **工作区文件**：
  - `MISSION.md` / `RESOURCES.md` / `NOTES.md`
  - `lessons/0001-*.html`（短课 + 等长选项测验）
  - `reference/changelog-skeleton.html`（骨架速查）
  - `assets/lesson.css`、`assets/quiz.js`（可复用组件）
  - `learning-records/`（当时为空，占位）
- **第一课核心命题**：Changelog ≠ git log；是 curated、notable、按版本组织的人类可读记录。主读 Keep a Changelog 2.0.0；中文镜像可能落后，冲突以英文 2.0 为准。
- **作业**：选真实项目放入 `CHANGELOG.md` 骨架，并说明 Unreleased 先记哪一类。

## 2. 落入 edges：`knowledge/teach/`

- 用户要求：`edges/knowledge` 下增加 `teach` 目录存放教学生成物。
- 约定布局：`knowledge/teach/README.md` 做主题索引；每主题一子目录（首个为 `changelog/`）。
- 执行：Cursor cloud agent 基于最新 `main` 写入并开 PR；合并结果为 **VirusPC/edges PR #9**（约 +470 行，9 文件）。
- 署名规范：`Co-authored-by: <助手名> <grok-bot@users.noreply.github.com>`。
- 公开库脱敏：禁止 Tailscale 账号、mesh `100.x`、授权链接、口令与密钥等。

## 3. ECS 源站部署

### 3.1 访问与权限

- SSH：经 Tailscale，用户名为 `cheng-dev`（首次连接可能需 Tailscale 校验链接，由用户在浏览器完成）。
- sudo：普通提权需密码；仅包管理（dnf/yum）NOPASSWD。助手侧「安全输入」的 sudo 密码**未能注入到实际执行进程**（Shell/子代理环境均读不到），因此系统级 nginx 配置改为用户本机执行脚本。

### 3.2 代码如何到机器上

- ECS 上已有 `~/projects/edges`，但当时 checkout 过旧，且 **从该 ECS 访问 GitHub 超时**，无法依赖源站 `git pull`。
- 做法：在助手可达 GitHub 的环境浅克隆最新 `main`，再经 mesh 用 **tar 管道** 同步 `knowledge/teach/` 到 ECS 对应路径。
- 启示：国内 ECS 部署清单须单独验证「源站能否拉 GitHub」；否则必须中转同步。

### 3.3 nginx

- 包：系统已装 nginx；正式方案用系统 nginx。
- 过渡：用户态 nginx 前缀目录 + 听 **8080**，用于无系统 sudo 时的冒烟。
- 正式：`/etc/nginx/conf.d/teach.conf`，`root` → `~/projects/edges/knowledge/teach`，`index index.html`；后补 **443 ssl** 与 Cloudflare Origin 证书路径。
- 脚本：`~/setup-teach-nginx80.sh`（用户 sudo 交互执行）：写入 conf、注释主配置里冲突的 `listen 80`、`nginx -t`、重启服务。
- **权限坑**：`~` 为 `700` 时 nginx 用户无法穿越 → 全站 **404**。处理：`chmod 711 $HOME`（可执行穿越，不开放目录列表）。改完后 `:80` 立即 200。
- 次要：`server_name "_"` 冲突警告可忽略或日后清理。

### 3.4 冒烟页

- 在 teach 根目录增加简单 `index.html`，链到第一课、骨架速查与 Mission，避免默认目录列表体验差。

## 4. Cloudflare 与公网暴露

- Zone：`viruspc.tech`。可用本机 `cloudflared` 登录证书解析出的 API 能力管理 DNS（权限足以增删记录；改 SSL 全局设置曾 403）。
- 新建：`teach.viruspc.tech` **A → ECS 公网 IP，proxied（橙云）**。
- 安全组：用户要求**本人控制台操作**；助手只讲解（曾转通用辅助说明步骤）。AccessKey 异常时 CLI 无法代改。用户放行后，**裸 IP HTTP 200**。
- HTTPS 排障简史：仅 80 时 Full 回源易 521；后源站上 Origin 证书并听 443。最终阻塞转到备案层（见下），而非「单纯没开端口」。

## 5. 未备案拦截（决定性事实）

| 访问方式 | 结果 |
| --- | --- |
| `http://<公网IP>/`（无域名 Host） | 200，Teach 正常 |
| `http://<公网IP>/` + `Host: teach.viruspc.tech` | 403，阿里云未备案页 |
| 经 Cloudflare 的域名 HTTP | 403（同备案页） |
| 经 Cloudflare 的域名 HTTPS | 521/525 一类回源失败（与 TLS/备案中间层相关） |
| Mesh 内访问 | 可用，但主机名**不是**公网域名 |

结论：大陆 ECS 上用**域名**对外提供网站服务，需 ICP 备案且接入信息匹配；这是常规监管，不是本次 nginx/DNS 配错。橙云不能绕过源站备案墙。

## 6. 备案分工与进度（对话末）

- 用户选择备案，而非 Tunnel / 迁非大陆源站。
- 交给**设备管理**主导；教学助手不并行抢流程。
- 已确认方向：山东**个人**备案；域名实名本人；引导 `beian.aliyun.com` 开单（App 拍证 + 人脸）。
- 安全组开端口惯例写入用户偏好：讲解可以，代开避免。

【认知更新】
(洞察与 Edge 雏形)

1. **Teach → edges 的产品形状**：主题子目录 + README 索引，适合多课并行与 PR 审阅；HTML 课要相对路径自洽（assets/reference）。
2. **「能 SSH」≠「能部署闭环」**：还缺 Git 可达、sudo 策略、进程用户读路径、安全组、域名合规四层。
3. **排障顺序建议**：本机 curl → 权限/root → 裸公网 IP → Host 头 → CDN/证书模式 → 合规页文案。过早纠结 SSL 模式会掩盖备案 403。
4. **711 vs 站点根外置**：把站点放到 `/var/www/...` 也可避家目录权限；711 家目录是改动面更小的折中。
5. **报 URL 的纪律**：区分 mesh 名、公网 IP、CDN 域名；把内网名当成「网址」交给用户会直接翻车。
6. **人机分工**：高风险网络暴露（安全组）默认人点；内容与 DNS/教学编排助手可多做。
7. **合规是架构选项**：备案 / 出站 Tunnel / 源站出境，三者选一，不能假设「上了 Cloudflare 就等于全球可访问国内源站域名」。
