## 3. ECS 源站部署

### 3.1 访问、账号与权限

- **机器**：阿里云国内 ECS（对话中 Mesh 名 `aliyun-ecs`；**仅 Mesh/MagicDNS，不是公网域名**）。
- **SSH**：`tailscale ssh cheng-dev@aliyun-ecs`。首次从助手环境连可能触发 Tailscale 校验（用户浏览器批准后继续）。
- **设备管理探测摘要**（协作背景）：`box` / `ubuntu` / `admin` / `ecs-user` 等曾被 ACL 拒绝；`root` 未被 ACL 拒但 grok-bot 侧仍可能要校验链接。
- **sudo**：普通提权要密码；**仅** `/usr/bin/dnf`、`/usr/bin/yum` 为 NOPASSWD。
- **sudo 密码注入失败**：聊天「安全输入」收到的密码**进不了** Shell/子代理实际进程（试两次仍失败）→ **系统级 nginx 改由用户本机交互执行脚本**。这是可复现的工具链限制，不是用户不会用 sudo。
- **阿里云 CLI 旁路不可用**：机器上有 aliyun CLI（约 3.5.0）；`configure list` 曾显示 Valid（`cn-hangzhou`），但 `GetCallerIdentity` / `DescribeInstances` 仍 **SignatureDoesNotMatch** → **不能靠 CLI 改安全组**。

### 3.2 代码如何到机器上（同步方法）

- ECS 上已有 `~/projects/edges`，但 checkout 偏旧；**从该 ECS 访问 GitHub 超时**，无法依赖源站 `git pull`。
- 实际流程：
  1. 在助手可达 GitHub 的环境：`git clone --depth 1 --branch main` 到临时目录（如 `/workspace/edges-deploy`）；
  2. 尝试 `rsync -e 'tailscale ssh'` → **box 无 rsync**，且无 root 装包；
  3. 改用 **tar 管道**成功：  
     `tar czf - knowledge/teaching | tailscale ssh cheng-dev@aliyun-ecs -- 'mkdir -p ~/projects/edges && tar xzf - -C ~/projects/edges'`
- 同步后 ECS 上可见文件包括：`README.md`、`changelog/MISSION.md`、`NOTES.md`、`RESOURCES.md`、`assets/lesson.css`、`assets/quiz.js`、`learning-records/.gitkeep`、`lessons/0001-...html`、`reference/changelog-skeleton.html`。
- **启示**：国内 ECS 部署清单必须单独验证「源站能否拉 GitHub」；否则固定「构建机拉仓 → mesh 同步制品」。

### 3.3 nginx：用户态 8080 → 系统 :80 → 后来的 :443

- **包**：系统已装 `nginx-1.30.4`（Alibaba Linux 系包名形态）；进程用户 `nginx`（配置 `user nginx;`）。
- **过渡（无 sudo）**：用户态前缀 `~/nginx-teach/`（`conf/` / `logs/` / `run/`），`/usr/sbin/nginx -c ... -p ~/nginx-teach/`，听 **8080**；`root` → `~/projects/edges/knowledge/teaching`。Mesh 冒烟 URL 曾为 `http://aliyun-ecs:8080/`（仅 mesh）。
- **用户选择**：不要停在 Mesh 8080；**给 sudo，绑到 80**（选项里还有「给 nginx/systemctl 开 NOPASSWD」，未采用）。
- **正式脚本**：`~/setup-teach-nginx80.sh`（用户交互 sudo 执行），要点：
  - 写入 `/etc/nginx/conf.d/teach.conf`（`listen 80 default_server` + `[::]:80`，初期 `server_name _`，`root` 指向 teach，`try_files`）；
  - 备份主配置为 `/etc/nginx/nginx.conf.bak.teach.<timestamp>`；
  - 用 sed 把主配置默认 server 的 `listen 80` / `listen [::]:80` 标成 `# DISABLED_BY_TEACH ...`，避免抢端口；
  - `nginx -t` → `pkill -u cheng-dev nginx`（停 8080）→ `systemctl enable/restart nginx`。
- **用户本机执行输出**：`nginx: [warn] conflicting server name "_" on 0.0.0.0:80, ignored`；`syntax is ok` / `test is successful`。该 `_` 冲突警告可忽略或日后清理。
- **权限坑（关键）**：脚本跑完后 `:80` **404**（不是欢迎页）。`namei -l` 显示 `/home/cheng-dev` 为 **`700 (drwx------)`**，nginx 用户无法穿越家目录。处理：`chmod 711 /home/cheng-dev`（可执行穿越、不开放目录列表）。改完后无需再 sudo reload 也可 HUP；`:80` **立即 200**。
- **备选思路**：把站点根外置到 `/var/www/...` 也可避家目录权限；**711 家目录是改动面更小的折中**（本次采用）。
- **冒烟首页**：teach 根目录自建简单 `index.html`，链到第一课、骨架速查、Mission，避免目录列表体验差。
- **后续 HTTPS 源站态**（备案排障时读到）：`/etc/nginx/conf.d/teach.conf` 已含 **80 + 443 ssl**；`server_name teach.viruspc.tech aliyun.viruspc.tech _`；`ssl_certificate` / `ssl_certificate_key` → `/etc/nginx/ssl/origin.pem` 与 `origin.key`（Cloudflare Origin CA）；注释写明不强制 HTTP→HTTPS，以免 Flexible 类环回。家目录另有 `~/ssl-tmp/` 临时材料（公开笔记不展开内容）。

### 3.4 暴露路径选择题（用户拍板记录）

1. Mesh 8080 够用 → **未选**  
2. 我来给 sudo，绑到 80 → **选中**  
3. 加 NOPASSWD 给 nginx/systemctl → **未选**

## 4. Cloudflare、DNS 与公网暴露

### 4.1 Zone 与既有记录

- Zone：`viruspc.tech`。
- 既有指向同 ECS 公网 IP 的记录经验：`aliyun.viruspc.tech`（A，橙云）；`ssh.aliyun.viruspc.tech`（A，仅 DNS）。
- 管理方式：本机已登录的 `cloudflared` 证书可解析出足以 **增删 DNS 记录** 的 API 能力；**改 zone SSL 全局设置曾 403 Forbidden**（DNS 能改 ≠ 全部 zone settings 能改）。

### 4.2 域名选型（用户拍板）

助手给出三选一：

1. `teach.viruspc.tech` → **选中**  
2. `teach.aliyun.viruspc.tech`  
3. 挂在现成 `aliyun.viruspc.tech` 路径下  

新建：`teach.viruspc.tech` **A → 182.92.131.89，proxied（橙云）**。

### 4.3 安全组（偏好固化）

- DNS 就绪后，裸公网 IP 曾超时 → **缺安全组入站 80/443**。
- 设备管理：AccessKey 仍 SignatureDoesNotMatch，CLI 改不了 SG；请用户重配密钥或控制台手动放行。
- **用户明确偏好（已写入记忆）**：阿里云安全组开端口**本人控制台操作**；让 **通用-辅助** 讲点击路径；助手**讲解可以、代开避免**。
- 建议规则形态：TCP 80/443，源 `0.0.0.0/0`（或至少 Cloudflare IP 段）。
- 用户回报「配置好了」后：裸 IP HTTP **200**；设备管理同步时一度见 `http://teach.viruspc.tech` HTTP 200，HTTPS **521**（源站当时无可用 443 回源）。

### 4.4 HTTPS / SSL 排障简史（最终阻塞在备案，不是「单纯没开端口」）

1. 仅源站 80 + Cloudflare **Full** 回源 443 → 边缘 **521**（源站拒连/无 TLS）。  
2. 助手试图把 zone SSL 改成 **Flexible** → **API 403**，改不成。  
3. 向用户二次确认：「改 Flexible」vs「写脚本在 ECS 开 443」——对话被后续「站好像好了 / 为啥不说话」打断；期间源站侧已出现 Origin 证书 + 443 监听。  
4. Origin 就绪后：经 CF 仍可能 **HTTPS 525**、**HTTP 403**；用 `Host: teach.viruspc.tech` 打裸 IP 可复现阿里云未备案页。  
5. **结论**：安全组与证书问题可阶段性修掉；**决定性阻塞是大陆 ECS + 未备案域名**。橙云不能绕过源站备案墙。

## 5. 未备案拦截（决定性事实）

| 访问方式 | 结果 |
| --- | --- |
| `http://182.92.131.89/`（无域名 Host） | **200**，Teach 正常 |
| 同 IP + `Host: teach.viruspc.tech` | **403**，阿里云未备案 / Non-compliance ICP Filing 页 |

- Mesh / 纯 IP 不走这套「域名网站」检查。
- 用户确认「这个事情很正常」——阿里云/腾讯云等均常见，不是本次 nginx/DNS 配错。

【认知更新】
(洞察与 Edge 雏形)

1. **Teach → edges 的产品形状**：`knowledge/teaching/<topic>/` + README 索引，适合多课并行与 PR 审阅；HTML 课必须相对路径自洽（assets/reference）；首页索引页降低「打开就是目录列表」的摩擦。
2. **「能 SSH」≠「能部署闭环」**：至少还要过 Git 可达、sudo/密钥注入策略、进程用户读路径、安全组、CDN/证书模式、**域名合规** 六层。
3. **排障顺序建议**：本机 curl → 权限/`root` 路径（`namei -l`）→ 裸公网 IP → 带 `Host` 头 → CDN/证书模式 → 读合规页文案。过早纠结 Flexible/Full 会掩盖备案 403。
4. **711 vs 站点根外置**：家目录 700 是 Linux 静态站经典坑；711 改动小；长期可迁 `/var/www`。
5. **报 URL 的纪律**：区分 mesh 名、公网 IP、CDN 域名；MagicDNS 名不是公网 URL——**用户会直接打回**。
6. **人机分工**：高风险网络暴露（安全组）默认人点；内容/DNS/教学编排助手可多做；备案材料走设备管理；日记走记录员。
7. **合规是架构选项**：备案 / 出站 Tunnel / 源站出境，三者选一；不能假设「上了 Cloudflare 橙云 = 全球可访问国内源站域名」。
8. **工具链现实**：安全输入的密钥未必进得了执行沙箱；`cloudflared` 登录态 DNS 权限 ≠ zone SSL 设置权限；Aliyun CLI「Valid」≠ API 签名真可用。
9. **同步策略产品化**：国内机拉不动 GitHub 时，把「浅克隆 + tar over Tailscale SSH」写成标准 playbook（rsync 可能根本不在 box 上）。
10. **教学资产质量闸门**：跨 agent 传 tarball 可能损坏 HTML；合并前要验课页/测验，不只看文件列表。
