# 2026-09-26--家庭实验室断电恢复与有线局域网总览

> 由当晚多助手实操整理。公开库已脱敏：不含 Tailscale 私网数字地址、授权链接、密码与 API token。完整含地址的台账在本地协作目录。本篇是总览，细节见各主题笔记。

## 背景

用户常开的一台 Linux 小主机当晚突然失联，原话是问「是不是掉线了」，随即说明「电源断了下，刚重新开机」。由此展开：不间断电源选型、默认进 Linux、一键恢复脚本、全网基于身份的远程登录、用交换机把多台机器收成同一有线局域网、NAS 共享在多端挂成磁盘、审计每台的 Tailscale 与隧道客户端、以及用手机/笔记本控 Windows 屏幕。用户后来说今晚这些事情非常重要，要求按主题写成可复盘的详细笔记。

## 过程

### 19:43–20:16 复电与默认系统

确认是整机不在网而非只灰助手；指导固件菜单选 Linux、把盘内启动顺序改成 Linux 优先；写好运维恢复脚本并在远程登录打通后代跑；外网、共享盘、容器等项恢复为可用。讨论 UPS：要约半小时续航须看电池能量与 USB 通信自动关机，不能只看 VA 数字。脚本曾出现「已在网却被误判未入网」的假警报，当晚修好。

### 20:07–21:05 远程登录齐套

在 Linux 小主机、NAS、云主机、台式 Mac 上打开基于身份的远程登录；Mac 必须卸掉沙盒图形客户端改用系统级守护进程才能当「被连端」。NAS 曾误判在容器里，实际系统包已在跑；遇 Permission denied 不盲重试。Windows 新机不能当 Tailscale SSH 服务端，改为系统 OpenSSH / 远程桌面，并新建专用设备助手；显示名缩短为好记短名。

### 21:37–23:40 有线局域网定稿

用非管理型交换机把多机接到同一网段；用户明确没有独立路由器，靠常开小主机当网关与地址分配。澄清 NAS 自有有线网卡、无 Wi‑Fi；Windows「没连 Wi‑Fi 也能上」是因为网线经交换机走到小主机出口。

### 23:45–23:55 NAS 当磁盘

Windows 映射多盘符，Mac 挂到用户目录下 NAS 文件夹，Linux 写进开机自动挂载。约定以后少建独立共享，优先在已有数据共享下用英文子目录作为全家共通入口。

### 00:01–00:05 客户端审计

表格式核对 Tailscale 与隧道客户端；给 Windows 补装隧道命令行（尚未登录开隧）；修好 Mac 卸图形版后命令行指错路径的问题。

### 00:08–00:36 屏幕远控

Mac 对 Mac 继续屏幕共享；对 Windows 用 Windows App / 远程桌面，并在专业版上启用远程桌面；账号用系统密码而非 PIN；关掉自动锁屏以免远控被打断。

### 散点 支线

企业 Wi‑Fi 按 PEAP 策略配置，且约定 NAS 不上企业无线；密码共享库边界；Windows 更新与 Wi‑Fi 驱动；机箱灯与开机启动项等。详见支线主题笔记。

## 所学

- 失联要先分「助手灰」还是「整机死」；复电能力 = 默认系统正确 + 恢复流程 + 可远程代跑。
- 「网上」不等于「基于身份的免密远程登录」；图形沙盒客户端可能故意不提供被连端。
- 「存储核心」和「网关核心」不是同一个问题；有没有独立路由器必须先问清。
- 存储共享的产品化靠「子目录约定」，不靠每新建一个共享就全网自动出盘符。
- 人不在键盘前时，第一次提权仍要当面；之后才能用管理员任务通道。

## 行动指南

### 主题行动指南

#### 背景

家庭实验室依赖一台常开枢纽做组网入口与（常兼）局域网出口；多机要同网、共享存储要当磁盘用，还要能远程登录和看屏幕。

#### 核心问题

枢纽失联或基础设施未定稿时，缺少一条可重复执行的主线：如何从复电走到「远程可代跑、有线同网、共享可用、远控可收藏」，并让以后当真当任务执行时有明确完成标准。

#### 核心解决方案

按顺序推进整晚主线（细节见各主题笔记）：

1. 复电：确认整机级问题 → 进入约定默认系统 → 跑固定恢复流程 → 需要时经基于身份的远程登录代跑。
2. 远程登录齐套：各服务器侧打开基于身份的远程登录并用邻机实测；Mac 用非沙盒守护进程；Windows 改走本机 OpenSSH / 远程桌面。
3. 有线局域网：非管理型交换机同网段；常开枢纽兼任单网关 / 单 DHCP / 出口；禁止第二套 DHCP。
4. 共享存储磁盘化：多端对齐映射；少建独立共享，多用约定子目录。
5. 客户端审计：用「主机 × Mesh 客户端 × 隧道客户端」矩阵验收，缺项补齐。
6. 屏幕远控：启用远程桌面入口，用系统账户密码，收藏短名。

#### 验收标准

以后按本总览主线执行时，下列全部成立才算完成：

- 常开枢纽能进入约定默认系统，恢复流程可通过。
- 需要代跑的节点已具备基于身份的远程登录（或 Windows 的替代远程命令行/桌面方案），并经邻机实测。
- 有线同网，默认路由指向约定的单网关枢纽，无第二套 DHCP。
- 共享存储在约定客户端上可当磁盘用，新材料有统一入口约定。
- 屏幕远控入口可按短名稳定进入（若本轮需要控屏）。

### 细节与其他

#### 若小主机再断电

则：确认进入约定默认系统后，跑恢复流程或经基于身份的远程登录代跑，再查共享盘与容器。细节见复电主题笔记。

#### 若新 Linux 或 NAS 入网且要远程代跑

则：加入 Tailscale 后打开基于身份的远程登录，并用另一台已通节点实测。Mac 须先换成非沙盒守护进程。

#### 若再有文件要全家共用

则：优先放进已有数据共享下的约定子目录；只有权限或备份策略要求时才新建独立共享，并在各端补挂。

#### 若要从 Mac 或手机看 Windows 屏幕

则：确认专业版已启用远程桌面、短名已知、使用系统账户密码（不是 PIN），再走 Windows App。

#### 若稿件要进公开知识库

则：先去掉 Tailscale 数字地址、密钥、授权链接与密码，再入库。
