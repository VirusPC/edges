【背景】

这次要解决的，不是「家里那台 Mac mini 能不能上网」，而是「Grok Bot 能不能真正坐在这台机器前面，替人打开 App、往里面写字」。

具体想做的验收很朴素：先确认这台 Mac mini 在家里的 mesh 网上是在线的，然后让 Grok Bot 在本机打开 macOS 自带的「备忘录」，新建一条笔记，正文写上测试句「grok bot测试连接」。如果这一步能做成，以后就可以把这台机器当成家里的桌面执行点：代开软件、代写内容、少被一遍遍的系统权限弹窗打断。

动手之前有一个容易混在一起的前提。Mac mini 完全可能已经出现在家里的 mesh 设备列表里，别人也能从另一台机器「看见」它在线；可那只说明网络层通了。Grok Bot 要驱动桌面，还必须在它自己的「电脑 / 本机执行」名单里完成登记。没有这一步，机器人看见的仍是一台网上的邻居，不是一台它能点、能打字的电脑。

所以这一轮的目标有两层。第一层是把本机执行登记做通，让打开备忘录、写入测试句成为可重复的动作。第二层是把 macOS 会反复弹出的自动化、辅助功能、完全磁盘访问、屏幕录制等权限，按正确顺序授给 Grok Bot，让以后同类操作尽量只弹一次、授完就记住，而不是每次都卡在系统对话框上。

授通之后又往下问了一层，值得一并记进这篇给人审阅的笔记：这些权限各自管的是哪一条路？辅助功能和自动化能不能互相替代？辅助功能能不能按像素去点？做 macOS 上的 computer use，主流到底是靠辅助功能树，还是靠截图，还是靠 Apple Events？把这些写清楚，以后换一台 Mac、换一套工具，才不必再翻原对话。

【过程】

开始时，Mac mini 已经在家里的 mesh 上显示在线。可是拿 Grok Bot 去控桌面，仍然做不到。原因很具体：这台机器当时还没有出现在 Grok Bot 的「电脑」列表里，远程 SSH 免密也还没打通。换句话说，网络上能看见它，既不能当本机执行目标，也不能先靠免密 SSH 绕过去代操作。

接下来没有继续在远端猜，而是人坐到 Mac mini 前面，在这台机器上打开 Grok Bot，走进设置里的「电脑 / 本机执行」，当场完成本机登记。登记完成后，节点名称显示为 ChengdeMac-mini，连接状态正常。从这一刻起，Grok Bot 才把这台机器当成一台可驱动的电脑，而不只是 mesh 上的一个在线名字。

登记刚通，就做了最初那条验收：通过本机执行打开「备忘录」，并成功新建一条测试笔记，标题或正文里写下「grok bot测试连接」。这一步本身是成功的，但过程并不干净——系统连续弹出自动化一类权限窗口，必须由坐在机器前的人点「同意」或「好」，机器人才能继续往下走。

为了少被这些窗口反复打断，先处理「辅助功能」。不先把辅助功能给 Grok Bot，它连系统设置里那些开关都没法代点：当你希望它帮你把后面的权限拨开时，它会卡在「我看见开关，可我点不了」这一层。所以顺序上是人先给辅助功能，再谈后面那些更细的授权。

辅助功能打开之后，回头复查「自动化」（也就是 Apple Events）。这时看到「备忘录」和 System Events 已经在授权名单里了。也就是说，针对「打开备忘录、让系统事件帮点界面」这一路，自动化并不是空白，缺的主要是前面那把能替你点系统设置的钥匙，以及后面几项更敏感的磁盘和屏幕权限。

「完全磁盘访问」和「屏幕录制」这两项，没有走自动改写系统设置的路径。原因是：让程序自己去改这类安全开关，会被安全审核拦住。所以这两项是人打开「系统设置 → 隐私与安全性」，对着 Grok Bot 这一条亲手拨开的。

全部授完后做了一次复查。辅助功能、屏幕录制、完全磁盘访问、Apple Events（自动化）这四类都已经亮着。然后又让 Grok Bot 往备忘录里写了一条「复查测试」。这一次没有再冒出新的权限弹窗。同时试了读本机 Desktop，也能读到，说明磁盘侧的授权已经落到实处，而不是只在设置页上勾了一个看不见效果的开关。

到这里，本机执行登记和权限授通都走完了：ChengdeMac-mini 可以稳定作为 Grok Bot 的桌面目标，至少「打开备忘录、写字、读 Desktop」这一条路径不再被弹窗打断。后半段对话没有再改机器，而是把刚才碰到的权限一项项拆开：辅助功能和自动化各走哪条路、按像素点稳不稳、截图录屏是不是每次都要配、以及 macOS 上开源的 computer use 实际把哪一层当主干。这些判断写在后面的【所学】【行动指南】【补充说明】里，过程本身到复查测试通过就结束了。

【所学】

第一组容易错的理解，是把「网上能看见」当成「桌面上能动手」。错的模型是：机器已经在 mesh 里显示在线，所以 Grok Bot 当然可以替你打开备忘录、敲字、点菜单。对的模型是：mesh 在线只回答「网络能不能连上这台机器」；Grok Bot 能不能控桌面，取决于它有没有把这台机器登记成本机执行目标，并且 macOS 是否允许这个 App 去驱动别的 App。两者叠在一起才叫「能控」，缺任何一层都会出现「我 ping 得通，但备忘录打不开」这种看起来很鬼的现象。之所以会混，是因为产品界面里「在线」两个字太容易让人以为能力已经齐了；其实那只是连通性，不是授权，更不是桌面代理权。

第二组容易错的理解，是以为 macOS 权限可以想办法永久静默跳过，或者反过来以为「弹窗出现就说明系统坏了、必须重装」。对的模型是：这类权限不能被程序悄悄、永久地绕开，这是系统设计如此；可是人一旦对正确的那个 App 点过同意，系统会记住，下次同一对「谁 → 对谁做什么」就不会再问。所以反复弹窗，通常不是「授了也没用」，而是授错了对象，或少授了后面自动化还要依赖的那一层。最常见的一种，是辅助功能没给 Grok Bot：后面就算自动化名单里已经有备忘录，机器人也没手去点系统设置里的开关，于是每走一步都还在等人点。判断有没有授对，看的是「授权对象是不是 /Applications/Grok Bot.app 这一份」，而不是「这个名字好像在列表里出现过」。

第三组容易错的理解，是不讲究顺序，看见什么弹窗就先点什么，或者先让机器人去拨系统设置。对的模型是：想让机器人帮你改系统设置里的开关，必须先有辅助功能；没有这把钥匙，后面那些「请帮我打开完全磁盘访问」的代操作都会停在同一道墙上。顺序本身不是为了好看，而是因为后面几步在机制上依赖前一步。把顺序记反，人会觉得「我都让它自动授了，怎么还是弹」，其实它根本没能碰到那个开关。

第四组容易错的理解，是把辅助功能和自动化当成同一把钥匙，以为开了其中一个，另一个就可以省掉。对的模型是：自动化走的是 Apple Events，相当于对那个 App 说「请你自己新建一条笔记」；对方必须有脚本字典，听得懂这套命令。辅助功能走的是辅助技术接口，相当于看见按钮、菜单再去点。用 System Events 去做界面脚本时，常常两条都要：自动化里允许指挥 System Events，同时给控制方开辅助功能，它才能真的点到别人的窗口。自动化补不齐辅助功能，因为没有脚本字典的 App、系统设置里的许多开关，本来就不是靠 `tell application` 就能办完的。

第五组容易错的理解，是以为「能点」就等于「按屏幕上的像素坐标去点」，或者反过来以为辅助功能完全不能按坐标点。对的模型是：辅助功能可以做坐标点击，System Events、CGEvent、cliclick 一类工具都是这条路，通常仍要辅助功能授权。但按元素去点更稳。分辨率一变、缩放一变、窗口一挪，坐标就飘；辅助功能树上的那个按钮还在，名字还在，坐标却已经不是原来那个点了。

第六组容易错的理解，是以为做 Agent 就一定要「一只手加一只眼」，辅助功能和屏幕录制必须成对出现。对的模型是：两者经常一起用，因为手要点、眼要确认；但不是每条路径都需要。辅助功能可以在不看像素的情况下点到元素；屏幕录制是给视觉、核对和坐标落地用的。若整条路径都是纯 Apple Events，比如备忘录听得懂「新建笔记」这条命令，这一步既不必辅助功能，也不必录屏。

第七组容易错的理解，是把完全磁盘访问、屏幕录制和普通的「允许辅助功能」当成同一级，或以为 macOS 上的 computer use 主干是 Apple Events。对的模型分两句。磁盘和录屏更敏感：完全磁盘访问能读到更多被沙箱挡住的位置，屏幕录制能看见屏幕上正在发生的事，宜人确认后手开。computer use 在真实 Mac 上的主流，是辅助功能树为主、截图兜底，不是把 Apple Events 当骨架。跨平台的 computer-use agent 常常只靠截图和像素；落到 Mac 上，开源 MCP 更常见的是先走辅助功能。Apple Events 是加分项：对方 App 能脚本化时更稳，但不能当总控。

这些判断可以带走再用的部分，不是某一天点过哪些按钮的流水账，而是以后换一台 Mac、重装一次 Grok Bot、或换一套桌面自动化工具时，用来分辨「现在卡在网络、登记、权限对象，还是走错了控制通路」的那张心智图。具体权限对照、开源项目和链接放在【补充说明】，不在这里摊成目录。

【行动指南】

若要在一台新的 Mac 上让 Grok Bot 做本机执行，不要先假设「这台机器已经在家里网上，直接下命令就行」。先在这台 Mac 本机打开 Grok Bot，进入设置里的「电脑 / 本机执行」，把当前这台机器登记进去，等到名单上出现这台机器并且连接状态正常，再做一次尽量简单的验收：打开「备忘录」，写一句不会泄露任何地址或密钥的测试句。这一步过了，再谈更复杂的代操作。若登记前就去试打开 App，失败原因会混在一起，后面很难判断是名单问题还是权限问题。

若每次让 Grok Bot 做事都重新弹出权限窗，先不要重装系统，先到「系统设置 → 隐私与安全性」按下面顺序核对。先看辅助功能里有没有 Grok Bot，而且打开的是 `/Applications/Grok Bot.app` 这一份；没有辅助功能，就不要指望它能帮你点后面的开关。再看自动化：至少确认「备忘录」和 System Events 已允许；你还要控别的 App，就把那个 App 也加进去。然后按实际需要，由人亲手打开完全磁盘访问、屏幕录制，不要走自动改写安全设置的捷径。改完之后退出并重新打开一次 Grok Bot，再重复刚才失败的那一个动作。若重启后仍弹，优先怀疑列表里是旧副本或名字相近的另一个 bundle，而不是「开关坏了」。

若从另一台机器可以 ping 通这台 Mac，却怎么也打不开备忘录或其它桌面 App，先把问题从「网络」挪到「本机执行登记」。去 Grok Bot 的「电脑」列表里看：这台机器在不在、是不是显示为已连接、名称是否就是你以为的那一台（这次登记成功后看到的是 ChengdeMac-mini）。只要名单里没有它，或者状态不是已连接，就不要再在 mesh 在线、SSH 是否通上打转——那两件事最多证明网络或远程登录，不证明桌面代理权已经交给 Grok Bot。

若刚做过大版本重装、换过 `/Applications/Grok Bot.app` 这个 bundle，或者系统把权限名单清过一遍，弹窗又回来了，就把上面那张权限清单重新过一次：辅助功能、自动化（备忘录 / System Events 以及你实际在控的 App）、完全磁盘访问、屏幕录制。必要时把旧条目删掉，重新添加当前这份 `/Applications/Grok Bot.app`。不要沿用「上次已经授过，应该还在」的记忆，因为换 bundle 之后，系统完全可能把它当成另一个新 App。

若目标 App 听得懂脚本，比如备忘录、访达、Safari、终端，优先走自动化，对那个 App 发 `tell application "Notes"` 这类命令，不要一上来就按像素去点。若还要点没有脚本字典的界面，比如系统设置里的开关，再补辅助功能。两条路可以叠，不能互相冒充。

若要用 System Events 去点别人窗口上的按钮、菜单，不要只开其中一项。自动化里要允许指挥 System Events，同时给真正出手的那个 App 开辅助功能。只开自动化，System Events 进得去却点不准；只开辅助功能，系统仍可能弹「要控制 System Events 吗」然后把脚本卡住。

若按屏幕坐标去点，点着点着就开始偏，先看是不是分辨率、缩放或窗口位置变了，不要先怀疑辅助功能「坏了」。能取到辅助功能树上的元素时，改回按元素点；坐标只当辅助功能树够不着、又必须点那个位置时的退路。

若整条活都能用纯 Apple Events 做完，比如只让备忘录新建一条指定标题的笔记，就不必为了这一步去开屏幕录制，也不必强行配一套截图回路。反过来，若 Agent 要「先看桌面再决定点哪里」，或者要按坐标落地，再开屏幕录制，把它当成眼睛，而不是当成第二只手。

若要在 Mac 上做或选型 computer use，不要先按跨平台 CUA 的习惯，默认主干是截图加像素。先看它是不是辅助功能树优先、截图只做兜底；Apple Events 只当对方 App 能脚本化时的加分。权限上也按这个映射来：辅助功能是核心，屏幕录制用来看见，自动化给能脚本化的 App 当快路。具体开源项目和链接见【补充说明】，这里只用来判断「这套工具站在哪一层」。

若只处理文稿、下载这类日常目录，先走「文件与文件夹」，不必一上来就开完全磁盘访问。若 Agent 或终端要到处读、查权限有没有授上、跨 App 取数据，再升级到完全磁盘访问。想少被按目录弹窗打断的稳定执行机，完全磁盘访问更常见；想先收窄授权，就从按块放行开始。

若同时有一台家里最低配的 M4 Mac mini（大约 16G 内存、256G 盘）和一台云上的小规格 ECS，不要让它们抢同一类活。Mac mini 适合当 Grok Bot 的本机执行目标，做打开 App、写备忘录、点系统界面这类必须碰到桌面的事；ECS 继续跑站点、轻服务、不依赖图形界面的任务。磁盘和内存都紧的时候，更不要把站点数据、大仓库和桌面自动化堆在同一台小机器上，否则哪边出问题都会先误伤另一边。

【补充说明】

下面这张表是给以后审阅和复用的：Agent 在 macOS 上做桌面自动化时，各权限各管一件事，缺哪一项，失败样子也不一样。本机执行登记不是系统隐私开关，但没有它，后面那些权限都还轮不到用。

### Agent 在 macOS 做自动化需要哪些权限

| 权限 | 没有它会怎样 | 为什么需要 | 典型场景 |
|------|--------------|------------|----------|
| 辅助功能 Accessibility | 点不了别人的窗口、菜单、开关；也代操作不了「系统设置」里的按钮 | 允许通过辅助技术接口读取界面，并模拟点击和键盘 | 代点系统设置、点 App 按钮、往表单里填字 |
| 自动化 Automation（Apple Events） | 对「备忘录」「访达」等弹出「要控制 xxx 吗」；脚本停在那里等同意 | 允许用 AppleScript / osascript 指挥另一个 App 做事。这和「去点它窗口上的按钮」不是同一条路 | 新建备忘录、让访达打开文件夹、驱动 Safari 或终端 |
| 完全磁盘访问 Full Disk Access | 读不了部分受保护目录；有时连系统用来记授权状态的数据也读不了 | 越过「按文件夹一项项授权」的限制，读取用户数据和一部分与隐私授权相关的系统数据 | 读 Desktop / 文稿以外的受控路径，或排查某个权限到底有没有授上 |
| 屏幕录制 Screen Recording | 截不了屏，也看不清当前桌面上到底显示了什么 | 允许捕获屏幕上的画面 | 截图确认结果，或先看清桌面再决定点哪里 |
| 文件与文件夹（桌面 / 文稿 / 下载） | 一访问对应目录就报错，或读出来是空的 | 还没开完全磁盘访问时，可以按目录单独放行 | 只碰文稿或下载时的轻量读写 |
| 本机执行登记（Grok Bot「电脑」） | 机器已经在 mesh 上显示在线，Grok Bot 仍然控不了这台机 | 这不是系统隐私项，却是 Agent 能连上这台 Mac、在上面跑 Shell 或开 App 的前提 | 一切本机命令、打开 App 之前都要先有它 |

### 完全磁盘访问和「文件与文件夹」差在哪

这两项管的都是「能不能读到、写到磁盘上的东西」，容易被看成同一把钥匙。其实不是。差别在范围：一个是按目录一块一块放行，一个是几乎把更大一片盘一次放开。

「文件与文件夹」是细粒度的。系统会按桌面、文稿、下载这类常见目录分别问你。很多日常读写到这一层就够了，不必一上来就开完全磁盘访问。缺哪一个目录，往往就只为那一个目录再弹一次。

「完全磁盘访问」更粗、权限也更高。开了之后，许多按文件夹设置的门就不再挡住它，因此能走到更多受保护的位置：和隐私授权相关的数据、别的 App 自己的容器、以及更广的一份用户数据。自动化工具、备份程序、终端里到处读文件的 Agent，常常会碰到「只开了文稿和下载仍然不够」的情况，这时才需要这一项。

| | 文件与文件夹 | 完全磁盘访问 |
|---|--------------|--------------|
| 粒度 | 按目录一块块放行 | 一次放开更大范围 |
| 敏感度 | 较低 | 较高 |
| 典型够用 | 只处理文稿、下载这类日常目录 | Agent 或终端要到处读、查权限有没有授上、跨 App 取数据 |
| 关系 | 还没开完全磁盘时的常规手段 | 开了之后，许多按文件夹设的限制就不再挡 |

它们不是两套不同的哲学，只是「按块放行」和「几乎整盘放行」的差别。若要把一台机器养成稳定的 Agent 执行机、不想每碰到一个新目录就弹一次，完全磁盘访问是常见选择；若想先收窄授权，就从「文件与文件夹」开始，真的读不动再升级。

### 辅助功能和自动化差在哪

自动化走的是 Apple Events。典型写法就是 `tell application "Notes"` 后面跟一条对方听得懂的命令：新建笔记、打开文件夹、让 Safari 打开某个地址。这条路要成立，对方 App 得有脚本字典；没有字典，你就是把句子说对了，它也没有接口可接。系统这时往往会弹出「要控制 xxx 吗」，脚本就停在那里等人点。

辅助功能走的是另一条路。它读取的是辅助技术接口上的界面树，也就是常说的 AX 树：看见哪个按钮、哪条菜单、哪个开关，再去模拟点击或键盘。它不问「备忘录听不听得懂新建笔记」，它问的是「屏幕上那个叫存储的按钮，我能不能按到」。

这两条路最容易在 System Events 上缠在一起。用 System Events 去做界面脚本时，控制方常常既要在自动化里被允许指挥 System Events，又要自己拥有辅助功能。缺前一项，系统会拦住「你不能指挥 System Events」；缺后一项，System Events 进得去，却点不了别人窗口上的控件。所以自动化不能完整替代辅助功能：能脚本化的 App 可以走快路，不能脚本化的界面仍然要靠手去点。

| | 自动化 Automation（Apple Events） | 辅助功能 Accessibility |
|---|----------------------------------|------------------------|
| 在问什么 | 那个 App 听不听得懂一条命令 | 界面上那个控件看不看得见、点不点得到 |
| 典型入口 | `tell application "Notes"…`，要有脚本字典 | AX 树、模拟点击和键盘 |
| System Events 界面脚本 | 自动化里要允许指挥 System Events | 控制方通常还要有辅助功能，才能点到别人的窗口 |
| 替代关系 | 替代不了辅助功能 | 也替代不了「让备忘录自己新建笔记」这条命令路 |
| 典型失败 | 反复弹「要控制 xxx 吗」，脚本卡住 | 看得见开关，手点不下去 |

先开辅助功能，再让 Agent 去帮你勾后面那些开关。顺序反了，人会看见它已经进了系统设置，却怎么也点不动按钮。若要控备忘录，至少要在「自动化」里允许它指挥「备忘录」；实际操作里常常还要给 System Events。只开辅助功能不够，因为「点界面」和「发指令给备忘录」是两条路。

### 辅助功能能不能按像素点击

能。辅助功能授权之后，仍然可以用坐标去点：System Events 可以点某个屏幕位置，底层也可以走 CGEvent，外面还有 cliclick 这类按坐标点击的小工具。缺辅助功能时，这些路多半会直接失败，或只在自己的窗口里打转。

但「能」不等于「应该当默认」。按辅助功能树上的元素去点更稳，因为按钮还在、名字还在，窗口挪了也能找到。按像素点则绑在当时的分辨率、缩放和窗口位置上。外接显示器一换、系统缩放一改、有人把备忘录窗口拖到另一边，昨天能点中的那个坐标今天就点到空白处去了。坐标适合当退路：元素树够不着、又必须点那个位置时再用，不要把它当成稳定 Agent 的第一选择。

### 辅助功能是不是一般都要配合截图、录屏

常常成对出现，但不是每条路径的必选项。Agent 要在桌面上既动手又确认时，辅助功能像手，屏幕录制像眼：手去点，眼用来看现在画面是什么、点完有没有点对。可是辅助功能并不依赖像素才能工作，它可以直接在 AX 树上找到控件再点，中间不必先截一张图。

屏幕录制的位置是视觉、核对，以及给坐标点击提供落地依据。没有录屏，按元素点的路往往还能走；没有录屏，按坐标点或「先看桌面再决策」就会瞎。纯 Apple Events 那条路更窄：备忘录如果听得懂「新建笔记」，这一步既不必辅助功能，也不必录屏。不要因为「Agent 以后可能要看屏幕」，就把录屏说成辅助功能的前置条件。

完全磁盘访问和屏幕录制都更敏感，适合人亲手开一次。授过之后系统一般会记住；Grok Bot 大版本重装或换了 bundle，名单可能把新副本当成另一个 App，那时要再授一遍。不能指望长期静默跳过权限弹窗。能追求的目标是：对正确的那个 App 授一次，以后少再弹。

### macOS 上的 computer use 主要靠什么，开源在走哪条路

在真实的 Mac 上，主流 computer use 不是把 Apple Events 当骨架。主干是辅助功能树，截图当看不清或树不够用时的兜底。Apple Events 很有用，可它只覆盖那些愿意公开脚本字典的 App，覆盖不了整个桌面。

跨平台的 computer-use agent 常常直接走截图加像素，因为那样不依赖某一家操作系统的辅助功能接口。这个习惯一旦原样搬到 Mac 上，就会显得又脆又重：分辨率、缩放、暗色模式、窗口叠放都能让像素策略失手。落到 Mac 上的开源 MCP，更常见的选择是辅助功能优先，需要看见时再截图，遇到能脚本化的 App 再顺手走自动化。权限映射也按这个来：辅助功能是核心，屏幕录制用来看见，自动化是给能脚本化的 App 的加分项。

下面这些是这一轮对照过的开源例子。列它们不是要马上换掉 Grok Bot，而是给人一个「Mac 上这条路已经被走过」的路标。

- [macos-use](https://macos-use.dev/)：面向 Mac 桌面自动化的入口站，适合先建立「这是 Mac 上的 computer use，不是通用截图 CUA」的印象。
- [computer-use-mcp](https://github.com/minghinmatthewlam/computer-use-mcp)：把 computer use 做成 MCP 的一种接法，可用来对照「工具层怎么把看和点暴露给 Agent」。
- [mac-cua](https://github.com/hyprcat/mac-cua)：Mac 上的 computer-use agent 实践，适合看辅助功能和视觉兜底在真机上怎么拼。
- [MacMCP](https://github.com/obra/macMCP)：偏 Mac 原生能力的 MCP，可用来对照 AX 优先、而不是先截一整屏再猜坐标。
- 同一路上还有 Ghost OS、axmcp、blade-computer-use、axterminator 这一族：名字不同，共同点是辅助功能树优先的 MCP，而不是把 Apple Events 或纯像素当唯一主干。

本机执行的登记入口就在 Grok Bot 设置里，文案是「电脑」或「本机执行」这一组。人要坐在目标 Mac 前面完成登记；只在别的设备上改设置，登记不到这台机器自己。
