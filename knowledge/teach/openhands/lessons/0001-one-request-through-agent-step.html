一次请求如何穿过 Agent.step

范围收紧：Conversation / EventLog → Agent.step → LLM → Tools / Workspace。不讲 Canvas 全产品、Cloud、Automations。

这一课你能带走什么

能用自己的话指着 V1 的八步，说出一次用户消息如何变成事件、如何进无状态的 Agent.step、如何经 LLM 变成工具调用、又如何在 Workspace 里变成 Observation。

先避开仓库边界陷阱

github.com/OpenHands/OpenHands 在 main 上是 Agent Canvas（前端 / 控制台 / 本地栈编排）， 不是代理循环本体。

真正的 agent loop、events、LLM、workspace、Agent Server 在 OpenHands/software-agent-sdk。 官方文档总览： SDK Architecture Overview。

打开错仓库会在 Canvas 的 UI / 编排文档里空转。Lesson 1 的代码与概念主线一律指向 software-agent-sdk + docs 的 sdk/arch/*。

一句话骨架

用户消息进入 Conversation，落成 EventLog 里的事件； Conversation 调用无状态的 Agent.step()； 可选 Condenser 之后问 LLM； 解析出 Action 或 Message；过确认门后，在 Workspace 环境执行 Tool， 写回 ObservationEvent，再决定是否继续 step。

八步展开见 一步循环速查； 十个词见 V1 术语表。

三个容易混的点

  • Agent 无状态：会话真相在 ConversationState / EventLog，不在 Agent 成员变量里。
  • 记忆 ≈ 事件日志（+ Condenser）：不是另起一套隐式 chat buffer；长期跨会话 memory 是后话。
  • 隔离可选：V1 不默认「必须 Docker」；Local vs Remote 由 Workspace 类型决定。
