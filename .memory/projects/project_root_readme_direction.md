根 README 以知识闭环为唯一叙事主线，按「理念：知识只有进入闭环，才能产生复利 → 知识模型 → 系统实现 → 使用与维护 → 公开仓库边界」组织；新增概念必须替换或收编旧结构，不能继续叠加平行章节。

README 顶部价值主张使用「把认知资本转化为可复利的判断优势」，核心原则使用「多端捕获，选择投入；沉淀 Edge，按需部署；反馈回流，持续复利」。这些表述替换现有措辞，不另建金融理念章节。

README 从知识管理、投资、ETL 和 Agent 四个互补视角解释同一知识闭环：知识管理关注知识如何捕获、组织、检索、使用与更新；投资关注认知资本如何形成知识资产与判断收益；ETL 关注多源输入、统一知识转化和多形态输出；Agent 关注 Memory 对上下文与经验的延续、长期任务（Long-horizon Tasks）的跨会话与跨阶段推进、Agent Teams 的分工协作与交接，以及以递归自我改进（Recursive Self-Improvement，RSI）为目标的自进化。四者相互支撑：记忆为任务接续和团队协作提供上下文，执行反馈经验证、采纳后用于改进记忆、工具和工作流，并在后续任务中使用；人设定目标与边界，判断和采纳重要变更。这些是设计关注点，不据此宣称已有完整的长期任务自动编排、团队自动调度或 RSI 闭环。是否有人参与治理与是否递归改进是两个维度，受控自进化与 RSI 不互斥。知识投资仍是将有限的时间、注意力和推理能力投入知识研究与使用，不意味着 Edges 专门服务于金融研究。四个视角共同描述同一系统，不拆成四条平行叙事，也不预设其中一个高于其他视角；七条核心思想共同承载这些视角，不要求一一对应。ETL 不要求所有材料走同一加工路径，消费反馈仍回到捕获入口。

人是认知资本所有者、资产配置者和最终风险负责人；Agent 是在人设定的目标、授权与风险边界内工作的主动管理者，承担研究、提炼、检索、部署和反馈处理，但不能自主决定重要资产或系统变更。

Memory 是分层资产管理基础设施，不等同于资产本身。会话上下文是临时研究活动；项目记忆是维护系统所需的运营账本、制度、纠错记录与操作手册；长期知识空间保存认知资产；检索与接口负责资产调用。项目记忆与长期知识不能混成同一层。理念部分只概括人、Agent、Memory 与 Loop 的关系，具体分层映射放在系统实现中，不新增顶级章节。

知识资产包含不同成熟度：Note 和 Projects、Teach 承载在研资产或知识生产过程，Edge 是可以反复部署、持续产生决策收益的核心资产，Post 是资产部署后的输出物。知识闭环对应「发现研究机会—低成本捕获—投入认知资本—形成 Edge—部署资产—获得收益—反馈再投资」；输出不是退出，Archive 才是退出机制。

认知资本采用分阶段配置：捕获保持低成本和低摩擦，再按预期复用价值、决策影响和不确定性选择性投入提炼成本。全部 Edge 可以作为认知资产组合来理解，不设计配置比例、再平衡制度或仪表盘。

认知复利发生在两个耦合层面：知识资产在反馈中改善；Agent 的记忆、检索、工具和工作流也在反馈中改善资产管理能力。两者属于同一知识闭环；只有改进后的系统继续参与自身改进，才形成这里所指的 RSI 闭环，不能仅凭记忆积累或一般反馈循环宣称已实现。

知识流动性表示资产能否被快速、可靠且带着必要上下文检索和部署。规划中的 RAG、PageIndex 和 extensions 不直接创造 Edge，而是提高资产流动性；当前只能描述为规划方向，不能声称已经实现。

认知复利不是文件数量增长，而是知识复用节约重复研究成本，行动和外部反馈提高判断质量，所得经验再投入知识闭环。金融语言应强化这条因果链，而不是散布资产、复利等装饰性术语。

Edge 同时具有收益潜力和认知风险。风险包括证据不足、越过适用边界、环境变化导致价值衰减，以及新证据反驳；边界、检验方式和失效条件是认知风险控制，不套用 VaR、夏普率等金融指标。过时、重复、错误或不可检索的记忆具有持有成本，修正、压缩和归档属于资产治理，但不额外引入“知识负债”作为核心术语。

量化先采用置信度、验证证据、最近复查时间、复用记录、失效条件和衰减风险等轻量观察维度，不承诺统一知识评分、ROI 或 Alpha。现有 Edge 没有统一 frontmatter 或可统计字段，因此 README 只能把这些作为「Edge 与演化」中的新增内容目标约定，不能声称历史内容已量化或要求全量回填，也不新增“量化体系”章节。

理念只保留一段连续叙事和唯一一张核心图。核心图在原阶段上融入「发现机会—投入研究—形成资产—部署—获得收益—反馈再投资」，并明确反馈回到捕获入口；不增加第二张投资图。“机会”指研究线索，“收益”指决策改善与反馈，不指交易机会或财务利润。

知识模型按角色而不是物理目录平铺：Notes、Projects、Teach 是同级知识生产入口；Edges 是知识沉淀；内部调用、Posts 和系统接口让知识发挥作用；Resources 与 Archive 分别是支撑和退出机制。现有角色表直接在作用列吸收投资语义，不增加金融概念映射表。Projects 是解决问题或交付产出的专项，Teach 是学习进展和能力获得的专项，两者不是 Notes 到 Edges 之间的成熟度阶段。外部反馈先作为材料回到 Note 或对应专项，再判断是否演化 Edge。

Edge 是已经提炼出理由与适用边界、能够影响未来判断或行动的可复用判断。准入标准是复用、行动、检验和复利；现实验证不是身份前提。小幅勘误、证据和链接补充可原地修改；判断含义、边界或因果解释实质改变时建立继任 Edge，旧版本归档。

Posts 是面向人的发布物，不替代内部知识真源，并继续受人维护、AI 不得自动改动的硬约束。Resources 只放跨区域共享附件，专项独占附件与专项共置。Archive 可接收 knowledge 下的所有类型，保留 archive/<原始 knowledge 相对路径>；它不是知识出口。

Loop 是自进化的基础，但自进化与 Recursive Self-Improvement 不应成为 README 的平行主线。反馈修正 Edge 属于知识演化；反馈改变知识组织、检索、输出方式或工具能力属于系统演化。README 将 Recursive Self-Improvement 明确为演进目标，同时如实描述当前 Human/Agent-in-the-loop 的受控自进化；人参与治理不妨碍递归关系，但目标不写成已实现能力。

README 描述新增内容与后续维护的目标约定，集中用一处说明历史内容尚未全部迁移。根 README 是目录约定、业务逻辑和内容标准的唯一真理源；局部命令、安装、实现和发版细节链接到子目录 README。隐私与脱敏是公开仓库的简洁约束，不是内容主线。

“任意输入、统一转化、多种输出”是系统的核心设计思想：贯通知识从沉淀、转化到消费的全流程。它说明输入、知识处理和消费之间的贯通关系，与“闭环复利”所强调的使用反馈回流互补；不据此要求 Notes、Projects、Teach 依次晋级，也不将任意格式接入写成已经实现的能力。

**How to apply:** 修改根 README 时先确认每段服务于同一阅读路径：为什么需要闭环、闭环中的知识角色、仓库如何实现、如何使用维护。以现有标题、原则和唯一一张图呈现知识管理、投资、ETL 与 Agent 四个互补视角；用认知资本、知识投资、知识资产、Edge、资产部署、决策收益、认知风险、Agent Memory、知识流动性和认知复利解释同一闭环，不新增平行的“投资理念”“量化体系”或 Memory 顶级章节。量化表达优先说明可观察、可检验和会衰减，避免尚无数据支撑的统一评分。知识角色表直接吸收投资语义；Agent Memory 的具体分层放在系统实现。在 Agent 核心思想中串联 Memory、长期任务、Agent Teams 与受控自进化，保留 AGENTS.md 入口和人机共用；递归维护另行说明谁维护谁，不把递归层级直接视为自进化。系统实现节可以在目录表前用一小段写明三件尽量一键的设计目标（部署底座、接入 Agent 客户端、产出对外资产），并标明仓库按这个方向收敛；不要另开顶级章节，也不要用它取代知识闭环主线。出现重复概念时优先删除、合并或链接，不要新增同级章节。正式术语用「知识闭环（Knowledge Loop）」；避免交替使用 Loop、闭环和知识循环。

在系统实现的核心思想列表中保留“任意输入、统一转化、多种输出”的精炼表述，与现有知识闭环和部署、接入、输出目标衔接；具体输入格式与输出能力仍以各能力面的实际实现为准。
