根 README 以知识闭环为唯一叙事主线，按「理念：知识必须进入闭环 → 知识模型 → 系统实现 → 使用与维护 → 公开仓库边界」组织；新增概念必须替换或收编旧结构，不能继续叠加平行章节。

理念先说明信息只有经过捕获、提炼、使用和反馈才会成为知识资产，再用「多端捕获，统一沉淀；按需输出，反馈演化」和唯一一张核心图解释知识闭环。内部调用形成个人的判断—行动—经验循环；Posts 和系统接口是闭环扩展点，把知识接入外部参与者，只有读者反馈、使用结果和新洞察重新进入知识生产入口，才形成更大的闭环。

Loop 是自进化的基础，但自进化与 Recursive Self-Improvement 不应成为 README 的平行主线。反馈修正 Edge 属于知识演化；反馈改变知识组织、检索、输出方式或工具能力属于系统演化。当前只描述 Human/Agent-in-the-loop 的受控自进化，Recursive Self-Improvement 只用一句话标为长期方向，不写成现有能力。

知识模型按角色而不是物理目录平铺：Notes、Projects、Teach 是同级知识生产入口；Edges 是知识沉淀；内部调用、Posts 和系统接口让知识发挥作用；Resources 与 Archive 分别是支撑和退出机制。Projects 是解决问题或交付产出的专项，Teach 是学习进展和能力获得的专项，两者不是 Notes 到 Edges 之间的成熟度阶段。外部反馈先作为材料回到 Note 或对应专项，再判断是否演化 Edge。

Edge 是已经提炼出理由与适用边界、能够影响未来判断或行动的可复用判断。准入标准是复用、行动、检验和复利；现实验证不是身份前提。小幅勘误、证据和链接补充可原地修改；判断含义、边界或因果解释实质改变时建立继任 Edge，旧版本归档。

Posts 是面向人的发布物，不替代内部知识真源，并继续受人维护、AI 不得自动改动的硬约束。规划中的 RAG、PageIndex 和机器检索接口经 extensions 暴露，必须标成规划能力。Resources 只放跨区域共享附件，专项独占附件与专项共置。Archive 可接收 knowledge 下的所有类型，保留 archive/<原始 knowledge 相对路径>；它不是知识出口。

README 描述新增内容与后续维护的目标约定，集中用一处说明历史内容尚未全部迁移。根 README 是目录约定、业务逻辑和内容标准的唯一真理源；局部命令、安装、实现和发版细节链接到子目录 README。隐私与脱敏是公开仓库的简洁约束，不是内容主线。

**Why:** 用户在 2026-09-09 指出，加入 Loop、自进化和 RSI 后 README 再次显得混乱。问题不是 Loop 本身，而是新概念叠加在原有章节上，导致知识流程、目录角色、实现现状和长期愿景在多个章节重复解释。经 grilling 确认，应让 Loop 成为唯一主线，并降低自进化与 RSI 的篇幅。

**How to apply:** 修改根 README 时先确认每段服务于同一阅读路径：为什么需要闭环、闭环中的知识角色、仓库如何实现、如何使用维护。理念只保留一段连续叙事和一张图；知识目录用角色表组织，只展开 Edge、知识如何发挥作用、支撑与退出的必要边界；实现用职责表和简短文字说明；使用与维护合并。出现重复概念时优先删除、合并或链接，不要新增同级章节。正式术语用「知识闭环（Knowledge Loop）」；避免交替使用 Loop、闭环和知识循环。
