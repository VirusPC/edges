# 周复盘

一篇周复盘覆盖一个自然周：周一到周日。文件名里的日期是该周的周一，不是动笔的那天。

## 命名

```text
retrospectives/weekly/<YYYY-MM-DD>--周复盘/INDEX.md
```

`<YYYY-MM-DD>` 是该周周一。例如覆盖 2026-10-05（周一）到 2026-10-11（周日）的一篇，路径是 `retrospectives/weekly/2026-10-05--周复盘/INDEX.md`。

同一个周一日期只保留一篇。补记改原来的 `INDEX.md`。

## 正文

`INDEX.md` 从一级标题起：

```markdown
# <YYYY-MM-DD> 周复盘
```

日期与文件名里的周一相同。后面六节顺序固定，标题用下面的名字。

### 范围

这一周的起止日期，以及这次回看覆盖的范围。

### 事实

这一周发生了什么。评价尽量少。

### 对照目标

这一周事先要推进的目标，以及实际差在哪里。事先没有目标，就写明没有。

### 洞见

可以带走的判断。过程的复述留在「事实」。

### 行动

至多 3 条。每条写清做什么，以及怎样算做完（能被观察或命令核对）。

同一节回顾上一篇周复盘里的行动：做成了、没做成，或还在做。没有上一篇，就写明没有。

### 启发

这一周里，哪件事改变了下一步怎么做。没有就写明没有。

## 登记

写好 `INDEX.md` 之后，在本文件「本层内容」追加一行。描述用一句话说明范围：

```markdown
- [2026-10-05 周复盘](2026-10-05--周复盘/INDEX.md) — 一句话范围
```

日期换成该周周一。上面这一行只说明格式，仓库里不放对应正文。

破折号两侧各留一个空格（` — `），清单解析靠这个分隔描述。

笔记、任务和项目记忆的正文写到它们自己的目录。这里只留候选的一句话，以及处理结果：已写入的路径、明确不做的原因，或留到下次的触发条件。边界见 [上一级说明](../README.md)。
