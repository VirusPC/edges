# 日复盘

一篇日复盘覆盖过去约 24 小时。文件名里的日期是这次回看结束时刻所在的日历日；跨过午夜时用结束那天。日历日按作者日常作息的时区计算，时区不写进文件名。

## 命名

```text
retrospectives/daily/<YYYY-MM-DD>--日复盘/INDEX.md
```

例如 2026-10-12 这一天的日复盘：`retrospectives/daily/2026-10-12--日复盘/INDEX.md`。

同一个日历日只保留一篇。补记改原来的 `INDEX.md`。

## 正文

`INDEX.md` 从一级标题起：

```markdown
# <YYYY-MM-DD> 日复盘
```

日期与文件名相同。后面两节顺序固定。

### 范围

写明这 24 小时的起止。

### 候选

过去这段对话里，值得送去笔记、任务或项目记忆的条目，以及每条的处理结果。一条一个小节，三行：

- **类型**：笔记、任务、记忆，三者取一。
- **候选**：一句话，够以后找到原意。
- **处理**：三选一。已写入，给出从仓库根起的路径；明确不做，写出原因；留到下次，写出再处理的触发条件。

没有要沉淀的候选时，仍保留「候选」一节，写明今天没有。这样和漏写分开。

笔记正文、任务卡和记忆条目写到它们自己的目录，命令见 [上一级说明](../README.md)。日复盘不复制那些正文。

## 登记

写好 `INDEX.md` 之后，在本文件「本层内容」追加一行：

```markdown
- [2026-10-12 日复盘](2026-10-12--日复盘/INDEX.md) — 一句话范围
```

日期换成被复盘的日历日。上面这一行只说明格式，仓库里不放对应正文。

破折号两侧各留一个空格（` — `），清单解析靠这个分隔描述。
