# 内容总结
这篇白皮书《Context Engineering: Sessions & Memory》由 Kimberly Milam 和 Antonio Gulli 撰写（2025年11月），系统介绍了构建有状态 AI 智能体的核心技术框架。以下是主要内容总结：

---

## 一、Context Engineering（上下文工程）

**核心概念**：LLM 本质上是无状态的，每次 API 调用只能感知当前上下文窗口内的信息。Context Engineering 就是动态组装和管理这个上下文窗口的过程，是 Prompt Engineering 的进化版——它不只关注静态指令，而是动态构建包含用户历史、外部数据、工具输出等的完整上下文。

上下文的组成要素分三类：
- **引导推理的上下文**：系统指令、工具定义、少样本示例
- **事实与证据数据**：长期记忆、外部知识（RAG）、工具输出、子智能体输出
- **即时对话信息**：对话历史、临时状态/草稿、用户当前提问

---

## 二、Sessions（会话）

**会话**是单次对话的容器，包含两个核心要素：
- **Events（事件）**：用户输入、智能体回复、工具调用、工具输出等的时序记录
- **State（状态）**：临时结构化数据，如购物车内容

**多智能体系统中的会话管理**有两种模式：
- **共享统一历史**：所有智能体共写同一个会话日志，适合紧密协作场景
- **独立私有历史**：每个智能体维护自己的历史，通过 Agent-as-a-Tool 或 A2A 协议通信

**生产环境注意事项**：安全隔离（ACL 权限控制、PII 脱敏）、数据生命周期管理（TTL 策略）、性能优化（减少传输数据量）。

---

## 三、长上下文管理策略

随着对话增长，面临上下文窗口限制、API 成本上升、延迟增加、"上下文腐化"等问题。常见的压缩策略包括：

| 策略 | 说明 |
|------|------|
| 保留最近 N 轮 | 滑动窗口，丢弃旧内容 |
| 基于 Token 截断 | 从最新消息向前计数，超出则截断 |
| 递归摘要 | 用 LLM 对旧对话生成摘要，替代原始内容 |

触发压缩的时机：基于数量阈值、基于时间（用户不活跃）、基于事件（任务完成）。

---

## 四、Memory（记忆）

**记忆**是从对话或数据源中提取的持久化信息快照，跨会话保存，为智能体提供连续、个性化的体验。

**记忆的核心价值**：个性化服务、上下文窗口管理、数据洞察挖掘、智能体自我改进。

**记忆的分类维度**：

- **信息类型**：陈述性记忆（"知道什么"，如用户偏好）vs. 程序性记忆（"知道怎么做"，如工具调用流程）
- **组织模式**：集合（多条独立记忆）、结构化用户档案（类似联系人卡片）、滚动摘要（单一持续更新的文档）
- **存储架构**：向量数据库（语义相似度检索）、知识图谱（关系推理）、混合方案
- **创建机制**：显式记忆（用户主动要求记住）vs. 隐式记忆（智能体从对话中自动提取）
- **作用范围**：用户级（跨会话个性化）、会话级（单次会话压缩）、应用级（全局共享上下文）

---

## 五、RAG vs. Memory 的本质区别

| 维度 | RAG | Memory |
|------|-----|--------|
| 目标 | 注入外部事实知识 | 构建个性化、有状态体验 |
| 数据来源 | 静态知识库 | 用户对话历史 |
| 隔离级别 | 共享（全局只读） | 高度隔离（按用户） |
| 比喻 | 图书馆研究员 | 私人助理的笔记本 |

> **核心结论**：RAG 让智能体成为世界知识专家，Memory 让智能体成为用户专家，两者缺一不可。


## 六、Memory Generation：记忆的生成机制

记忆生成本质上是一个 **LLM 驱动的 ETL 管道**，将原始对话噪声转化为结构化知识，分四个阶段：

1. **Ingestion（摄入）**：将原始对话历史输入记忆管理器
2. **Extraction & Filtering（提取与过滤）**：LLM 根据预定义的"主题定义"筛选有意义的信息，不匹配则不创建记忆
3. **Consolidation（整合）**：最复杂的阶段，LLM 将新提取的信息与已有记忆对比，执行 Merge / Delete / Create 三种操作，解决重复、冲突、信息演化问题
4. **Storage（存储）**：将新记忆或更新后的记忆持久化到数据库

---

## 七、Memory Extraction 深度解析

提取的核心问题是：**"这段对话中哪些信息值得成为记忆？"** 这不是简单的摘要，而是有目标的智能过滤。提取方式有三种：

- **Schema/模板提取**：给 LLM 预定义 JSON schema，让其按结构填充
- **自然语言主题定义**：用自然语言描述什么类型的信息值得记录
- **Few-shot 示例提示**：给 LLM 展示输入→记忆的示例，适合复杂或细微的主题

---

## 八、Memory Consolidation 深度解析

整合解决四类核心问题：

| 问题 | 说明 |
|------|------|
| 信息重复 | 同一事实被不同表述多次提及 |
| 信息冲突 | 用户状态随时间变化，旧记忆可能过时 |
| 信息演化 | 简单事实逐渐变得更加复杂和具体 |
| 记忆衰减 | 过时、低置信度的记忆需要被主动"遗忘" |

整合流程：检索相似已有记忆 → LLM 分析新旧信息 → 执行 UPDATE / CREATE / DELETE 操作 → 写入数据库。

---

## 九、Memory Provenance（记忆溯源）

记忆的可信度来自其**来源（Provenance）**，数据来源分三类：

- **Bootstrapped Data**（预加载数据，如 CRM）：高可信，可解决冷启动问题
- **User Input**（用户输入）：显式输入（高可信）vs 隐式推断（较低可信）
- **Tool Output**（工具输出）：通常不建议生成长期记忆，更适合短期缓存

记忆的置信度会随时间动态变化——多源印证则提升，时间流逝或出现矛盾则下降，最终触发**记忆剪枝（Memory Pruning）**。

---

## 十、触发记忆生成的时机

| 触发策略 | 说明 |
|----------|------|
| 会话结束时 | 成本低，但记忆粒度粗 |
| 每 N 轮对话 | 平衡成本与新鲜度 |
| 实时（每轮） | 记忆最精细，但成本最高 |
| 显式指令 | 用户主动说"记住这个" |

更高级的做法是 **Memory-as-a-Tool**：将记忆生成暴露为工具，由智能体自主决定何时触发，而非外部固定规则。

---

## 十一、Memory Retrieval（记忆检索）

检索策略需在**有用性**与**延迟预算**之间取得平衡，评分维度有三个：
- **相关性**（语义相似度）
- **新近度**（时间维度）
- **重要性**（生成时预定义的显著性）

检索时机有两种模式：
- **主动检索（Proactive）**：每轮开始时自动加载，延迟稳定但可能浪费资源
- **被动检索（Reactive / Memory-as-a-Tool）**：智能体按需调用，更高效但增加一次 LLM 调用

---

## 十二、Inference with Memories（记忆注入推理）

检索到的记忆有两种注入方式：

- **注入系统指令（System Prompt）**：适合稳定的全局信息（如用户档案），权威性高，但有"过度影响"风险
- **注入对话历史（Conversation History）**：适合临时性、情境性记忆，但需注意模型可能将记忆误认为真实对话内容

实践中推荐**混合策略**：稳定信息放系统提示，瞬态信息用对话注入或 Memory-as-a-Tool。

---

## 十三、程序性记忆（Procedural Memory）

当前商业记忆系统主要聚焦于**陈述性记忆**（"知道什么"），而程序性记忆（"知道怎么做"）是完全不同的问题——它不是信息检索，而是**推理增强**。其生命周期同样包含提取、整合、检索三步，但目标是提炼可复用的"操作手册（Playbook）"，并与 Fine-tuning 形成互补：Fine-tuning 修改模型权重（慢、离线），程序性记忆通过上下文注入动态适配（快、在线）。

---

## 十四、测试与评估

记忆系统的评估分三个层次：

| 评估维度 | 核心指标 |
|----------|----------|
| 记忆生成质量 | Precision（准确率）、Recall（召回率）、F1-Score |
| 记忆检索性能 | Recall@K、Latency（需在 200ms 内） |
| 端到端任务成功率 | 用 LLM 作为"裁判"对比最终输出与黄金答案 |

---

## 十五、生产环境注意事项

- **异步解耦**：记忆生成必须在后台异步执行，不能阻塞用户响应
- **并发安全**：高并发下需防止竞态条件，可用事务操作或乐观锁
- **隐私与安全**：用户有权删除记忆，需支持数据溯源删除；应用级记忆必须清除敏感内容防止用户间数据泄露

---

至此，白皮书的完整内容已全部覆盖。整体来看，后半部分的核心贡献在于将记忆从一个抽象概念落地为**可工程化的完整系统**，涵盖生成、整合、溯源、检索、注入、评估和生产部署的全链路设计。

# 重点记录
- **定义**
	- **Context Engineering**: The process of dynamically assembling and managing information within an LLM's context window to enable stateful, intelligent agents.
	- **Sessions**: The container for an entire conversation with an agent, holding the chronological history of the dialogue and the agent's working memory.
	- **Memory**: The mechanism for long-term persistence, capturing and consolidating key information across multiple sessions to provide a continuous and personalized experience for LLM agents.
