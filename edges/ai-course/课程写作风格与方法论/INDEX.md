# AI 课程写作风格与方法论

> 核心定位：培养能做理性 AI 工程决策的开发者，而非研究者。

---

## 核心原则

### 1. 工程导向
- 每个技术概念必须有"工程视角"：成本、延迟、选型影响
- 关注"为什么这会影响我的决策"，而非数学推导

### 2. 成本意识
- Token 计费、显存占用、API 价格差异贯穿全文
- 技术选择与经济可持续性绑定

### 3. 具象化表达
- 用类比解释原理
- 优先给代码、配置、命令，而非抽象描述

### 4. 明确反模式
- 直接告诉"不要做什么"
- 警告常见误区和过度工程

### 5. 前沿实践对齐
- 从主流开源项目（Coding Agent、AI IDE、评估框架）提取真实工程模式
- 示例和配置应与当前工业界最佳实践兼容
- 反模式应来自真实生产问题，而非臆想

---

## 内容结构

### 递进三层
| 层级 | 核心问题 | 教学目标 |
|------|---------|---------|
| 是什么 | 能力从何而来？ | 建立基本概念 |
| 为什么 | 机制如何影响能力与成本？ | 理解原理 |
| 怎么做 | 如何选型/调参/部署？ | 可执行的决策流程 |

### 单元组织
```
问题定义 → 机制解释 → 工程启示 → 实操方法 → 动手验证
```

---

## 写作规范

### 语言风格
- 避免模糊词："通常" → 具体数值
- 用主动语态："模型被训练" → "训练模型"
- 数据支撑："效果更好" → "pass@1 提升 15%"

### 示例标准
- 可直接复制执行
- 包含预期输出
- 附带故障排查

### 常用格式
- **表格**：横向对比、配置模板
- **代码块**：可执行命令 + 预期输出
- **标注**：✅ 已内化 / 🔄 正在内化 / ❌ 值得投入

---

## 内容模板

### 技术概念
```markdown
### [名称]：[一句话定位]

#### 工作原理
[类比/可视化]

#### 工程视角
- 成本：[数值]
- 性能：[影响]
- 适用：[场景]

> 动手验证：[实验]
```

### 选型决策
```markdown
1. 确认约束（硬件/预算/时延）
2. 形成候选池（表格对比）
3. 验证方案（Benchmark + 实测）
4. 固定版本（避免 latest 漂移）
```
