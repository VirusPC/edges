# Lesson2 大纲改进方向

> 当前问题：像"知识点清单"，而非"可执行的工程决策流程 + 动手验证闭环"

---

## 核心差距

| 差距项 | 严重程度 |
|--------|---------|
| 缺少"工程视角"专栏 | 🔴 严重 |
| 缺少类比化表达 | 🔴 严重 |
| 缺少"动手验证"环节 | 🔴 严重 |
| 缺少场景化配置模板 | 🔴 严重 |
| 缺少成本意识 | 🔴 严重 |

---

## 必须补充的内容类型

1. **工程视角专栏**：每个技术点后附成本/延迟/适用判断
2. **类比化表达**：用考试、实验等日常场景解释技术
3. **反模式清单**：过度拟人化、角色宽泛、指令模糊等
4. **场景化配置模板**：代码生成/审查/调试/设计/测试
5. **成本分析**：Token 成本公式、优化策略（Cache/路由/控制输出）
6. **前沿实战案例**：解析真实 Coding Agent 的 System Prompt 设计
7. **可执行代码**：完整测试套件 + 使用说明 + 预期输出

---

## 与 Lesson3 的衔接

在以下位置预埋上下文工程概念：

- **提示词框架设计**：System Prompt ≈ 固定上下文，User Input ≈ 动态上下文
- **迭代优化流程**：提示词过长导致 Overload，引入"关键信息置顶"
- **系统提示词架构**：提及完整上下文组成（System + History + Tool Output）

---

## 核心理念

**不是知识清单，是可执行手册**：
- 看到真实工具的提示词设计
- 复制粘贴代码立即验证
- 建立成本和质量的直觉
- 积累可复用的模板库
