## 📘 章节 1：模型架构 — 建立 Token 直觉

> 入口句：先从第一个问题开始：模型不认识文字，它到底是怎么"读"代码、"看出"空指针风险的？

📍 路标 1.1：统一范式
- 论据：**涌现（Emergence）**——"没人在训练目标里写过'请学会 review 代码'"
- 一句话：以前一个任务一个模型，现在大到一定程度突然涌现出能力，所有任务都被"预测下一个 token"统一了。
- ⚠️ 提醒：对比 Snyk/DeepCode 的传统静态分析做铺垫；引出"模型当作可替换组件"的工程观。

📍 路标 1.2：Tokenizer
- 论据：`"user.name" → ["user", ".", "name"] → [882, 13, 2601]`
- 一句话：模型不认识文字，第一步是切词成 token，按 token 算钱、算窗口、算显存。
- ⚠️ 提醒：GPT-4 中文 104 / GPT-5 中文 82 / Qwen-3 中文 75 / GPT-5 英文 53——记住这组数字证明"中文比英文贵"。

📍 路标 1.3：Embedding
- 论据：`user.name - callback() + callback?.() ≈ user?.name`（"安全防御"维度的向量加减）
- 一句话：token ID 没语义，Embedding 把它变成向量，让"语义相近"等于"距离相近"——这就是 RAG 的根本原理。
- ⚠️ 提醒：3 维示意 `[访问属性, 函数调用, 安全防御]`，真实是几百到几千维。

📍 路标 1.4：Attention
- 论据：两个 `!` 含义相反——非空断言 vs 逻辑取反；Q/K/V 让 `user.name` 回头打分到 `const user = ... : null`
- 一句话：Attention 让当前位置回头查询前文，按相关性加权——这就是模型"看到"跨行空值风险的机制。
- ⚠️ 提醒：O(n²) 复杂度 → 长上下文是难题；**Lost in the Middle** 论文（arxiv 2307.03172）。

📍 路标 1.5：Transformer
- 论据：三件套——残差连接（救 96 层）、FFN（独立思考）、堆叠 N 层（浅层语法→深层推理）
- 一句话：Transformer 是把 Embedding + Attention + FFN 组装起来的完整架构，现代 LLM 全是 Decoder-Only。
- ⚠️ 提醒：Encoder-Only=BERT；Encoder-Decoder=T5；Decoder-Only=GPT/Claude/Gemini/DeepSeek。"闭卷考试 vs 即兴接话"是讲 Decoder-Only 的金句。

↗️ **过渡 → 章节 2**
> 但架构只解释了"怎么处理"，还没回答"为什么它懂空指针检查却对你的内部 API 说错"——这是训练决定的。

## 📘 章节 2：训练机制 — 能力从何而来

> 入口句：第一部分回答了模型怎么从纯文本中"看出"空指针风险。但第二个问题还没解——它"懂" try-catch 却不"懂"你的内部 API……能力的边界到底在哪？

📍 路标 2.1：预训练
- 论据：Base 模型是"强大的文本补全器"——给它"请 review 以上代码"会续写成"请 review 以上代码的测试覆盖率……"
- 一句话：预训练让模型学会语言本身，但它不懂指令——所以**不要直接用 Base 模型**。
- ⚠️ 提醒：海量无标注 + next-token prediction。

📍 路标 2.2：CPT 持续预训练
- 论据：Qwen2.5-Coder vs 通用 Qwen2.5——同规模差距来自代码 CPT
- 一句话：通用预训练对专业领域只是"扫过"，CPT 是用领域数据做的"浸泡式深化"，把知识基础打厚。
- ⚠️ 提醒：知识截止日期 → 内部 API 必然幻觉 → RAG 的根本原因。

📍 路标 2.3：SFT 监督微调
- 论据：四个方向——指令微调 / CoT SFT / 工具调用微调 / 代码微调
- 一句话：SFT 不改变模型懂什么，只改变行为模式——让它从"续写"切换到"响应指令"。
- ⚠️ 提醒：**不要给推理模型加"请一步一步思考"**，会干扰 RLVR 训出来的内置推理链。

📍 路标 2.4：Alignment 对齐
- 论据：两条路——RLHF/DPO（人类偏好）vs RLVR（编译器/测试用例打分）
- 一句话：对齐让模型在多个可行答案里选最符合人类期望的那个，但会带来"对齐税"。
- ⚠️ 提醒：**Alignment Tax** 就是 CR 工具里"建议考虑是否……"的根源；强制 JSON 枚举（BLOCKER/WARNING/NIT）可以缓解。

📍 路标 2.5：15 度夹角
- 论据：0 度被淘汰、90 度无杠杆、**15 度构建模型增强但不会替代的能力层**（Respect To 秒哒产品经理 2026 年 2 月访谈）
- 一句话：理解了能力来源后，跳出来想——哪些工程投入不会被下一代模型吞掉。
- ⚠️ 提醒：4 个长期方向——领域私有数据、外部系统集成、评估可观测、判断"哪些问题值得用 AI 解决"。
- ⚠️ 金句收束：**Pre-train 给能力，CPT 补知识，SFT 教行为，Alignment 调偏好。**

↗️ **过渡 → 章节 3**
> 前两部分回答了模型怎么"读"代码、能力边界在哪。第三个问题关于钱：output token 为什么比 input token 贵好几倍？

## 📘 章节 3：推理机制 — 成本因何而生

> 入口句：这是推理机制决定的。

📍 路标 3.1：Prefill vs Decode
- 论据：Prefill 瓶颈是 GPU 算力（TTFT），Decode 瓶颈是显存带宽（TPS）
- 一句话：处理输入和生成输出是两个完全不同的过程——所以长 prompt TTFT 高、output 比 input 贵 3-5 倍、流式输出并不真的加速。
- ⚠️ 提醒：Thinking 模型贵在 Decode 阶段会产生大量推理 token，全按 output 计费。

📍 路标 3.2：KV Cache & Prompt Cache
- 论据：KV Cache 把 O(n²) 降到 O(n)；Claude Code 缓存命中只算原价 ~10%
- 一句话：KV Cache 是空间换时间，Prompt Cache 是跨请求复用——这就是为什么 Claude Code 鼓励写长 CLAUDE.md。
- ⚠️ 提醒：设计 prompt 时**稳定内容放前面、变化内容放后面**，最大化缓存命中。

📍 路标 3.3：加速降本技术全景
- 论据：量化 / GQA-MQA / 推测解码 / vLLM Paging / MoE / 蒸馏 / DeepSeek DualPath
- 一句话：作为 API 调用者你不需要实现这些，但要理解——它们解释了为什么同模型不同平台价格速度差别巨大。
- ⚠️ 提醒：MoE 看激活参数不要看总参数；INT4 量化 70B 可能比 FP16 7B 还好。
- ⚠️ 收束：**output 贵是因为 Decode 串行；追问快是因为 Prompt Cache 复用了上一轮的 KV Cache。**

↗️ **过渡 → 章节 4**
> 前面三部分建立了理性基线——你知道了模型怎么处理代码、能力边界在哪、成本花在了哪里。现在回到第四个问题：为什么不直接用最强的模型？

## 📘 章节 4：模型选型 — 为什么不直接用最强

> 入口句：你的 AI CR 工具每天跑上百个 PR，全用 Opus 一个月账单可能比招一个人还贵——这就是选型要解决的问题。

📍 路标 4.1：为什么要选型
- 论据：5 类不该用旗舰模型的场景——高频简单 / 延迟敏感 / 大量中文 / 私有合规 / 垂直专项
- 一句话：旗舰是能力上限不是工程默认；约束（合规、延迟、成本）比"哪个 review 质量最高"优先级更高。
- ⚠️ 提醒：各家强项不同——Claude（长上下文、Agentic 编码）、GPT-4o（结构化、视觉）、o3/o4（数学推理）、Gemini（1M+ 上下文）、DeepSeek（成本极低）。

📍 路标 4.2：需求定义
- 论据：8 个维度——输入模式 / 上下文长度 / 价格 / 延迟 / 吞吐 / 部署模式 / 任务场景 / 显存
- 一句话：选型之前先把需求写成可检查的问题，约束直接划掉一大批候选。
- ⚠️ 提醒：知识策略阶梯——**Prompt → Long Context → RAG → SFT**；路由策略可降本 50%+。

📍 路标 4.3：Step 1 聚合平台快速选型
- 论据：OpenRouter 三个入口——/rankings、/models、单模型详情页
- 一句话：带着约束去聚合平台过滤，几分钟锁定 2-3 个候选池。
- ⚠️ 提醒：4 种 token 计费——Input / Output / Cached Input / Thinking Token。

📍 路标 4.4：Step 2 从模型名字看本地可行性
- 论据：`Qwen2.5-Coder-7B-Instruct-Q4_K_M.gguf` 拆解（家族/任务/规模/对齐/量化/格式）
- 一句话：本地部署时模型名字就藏着所有关键信息——家族、规模、量化、上下文窗口。
- ⚠️ 提醒：显存粗算——FP16=2×B、INT8=1×B、Q4=0.5×B；KV Cache 随上下文线性涨；**Apple Silicon 留 30%+ 给系统**。

📍 路标 4.5：Step 3 真实数据评测
- 论据："**50 条真实样本的评测结果比任何榜单都更能预测模型在你任务上的表现**"
- 一句话：候选只剩 2-3 个时，跳过公开 Benchmark，用 50-100 个生产样本 + LLM-as-Judge + 人工抽检定胜负。
- ⚠️ 提醒：注意 LLM-as-Judge 的 **position bias**；分数差 1-2% 不值得换。

↗️ **过渡 → 章节 5**

## 📘 章节 5：参数配置 — 选定后怎么调

> 入口句：答案可能出乎你意料：大多数时候，影响不大。

📍 路标 5.1：调参影响层级
- 论据：**80% Prompt / 15% 上下文 / 4% 参数 / 1% 模型本身**
- 一句话：先改 prompt，再调参数，最后才考虑换模型——参数是锦上添花，不是救命稻草。
- ⚠️ 提醒：这个 80/15/4/1 是开场金句，必须背下来。

📍 路标 5.2：temperature
- 论据：4 档——0–0.2 代码/JSON、0.3–0.5 CR/技术问答、0.6–0.8 对话、0.9–1.2 创意
- 一句话：temperature 控制随机程度，但只调它——top_p 留默认 1.0，top_k 不要碰。
- ⚠️ 提醒：三个坑——temperature=0 不等于完全确定（要 seed）；低 temp 不等于更正确；代码任务用 0.1–0.2 而非 0。

📍 路标 5.3：max_tokens 与 stop
- 论据：JSON 没闭合、代码缺 `}` 是最常见 bug——通常就是 max_tokens 不够
- 一句话：max_tokens 是硬性上限不是目标，stop 是结构化解析的"断路器"。
- ⚠️ 提醒：函数级代码 4096–8192；长文档/重构 16384+。

📍 路标 5.4：logit_bias
- 论据：Manus 的做法——保持 prompt 不变、用 logit masking 或 response prefilling 控制工具子集
- 一句话：删除工具会破坏 KV Cache，更聪明的做法是 prefilling `browser_` 让模型只能续写浏览器工具。
- ⚠️ 提醒：直接操作 logits 维护成本高，轻易不要碰。

📍 路标 5.5：Thinking 模式
- 论据："用错场景成本翻 5–10 倍效果几乎不变"
- 一句话：Thinking token 按 output 计费，复杂推理才开，简单补全和摘要不要开。
- ⚠️ 提醒：Claude `budget_tokens` 控制思考长度——复杂 10000–20000，中等 5000–8000；上下文不足时开 Thinking 也无济于事。

📍 路标 5.6：速查表 + 调参方法
- 论据：CR 起点配置 = `Sonnet, temperature=0.2, max_tokens=4096, thinking=关`
- 一句话：从模板出发 → 跑 5–10 个真实 case → 一次只改一个参数 → 对比效果。

## 📘 章节 6：本地部署 — 在自己电脑跑一个

> 入口句：能。这一部分只做一件事：在你自己的 Mac 上把本地模型和 AI 编码工具跑通。

📍 路标 6.1：硬件 → 模型对照
- 论据：8GB→3B / 16GB→7B / 24GB→14-33B / 32GB+→32B / 64GB+→70B
- 一句话：Apple Silicon 统一内存的粗略规则——模型大小不超过总内存的 70-80%。
- ⚠️ 提醒：四档推荐——跑通流程 3b、日常用 7b、追质量 32b、追最好直接走 API。

📍 路标 6.2：Ollama 跑通
- 论据：`brew install ollama` → `ollama pull qwen2.5-coder:7b` → `ollama run`
- 一句话：三条命令把本地模型跑起来，再用同一段 `renderProfile` 代码喂给它做 review。
- ⚠️ 提醒：Ollama 默认在 `localhost:11434` 暴露 API，后面 OpenCode 直接接。

📍 路标 6.3：OpenCode 接入
- 论据：`opencode.json` 配 `provider: ollama, model: qwen2.5-coder:7b`
- 一句话：OpenCode 是终端 AI 编程助手，先连本地 Ollama 跑通，再切到云端 API 对比。
- ⚠️ 提醒：建议顺序——**先本地跑通，再切 API 对比效果**。

📍 路标 6.4：对比实验
- 论据：3b vs 7b vs 云端模型，比响应时间、代码质量、是否一次通过
- 一句话：实验目的不是分胜负，而是建立"什么叫够用"的体感。
- ⚠️ 提醒：金句——"现在你不只会调 API——你也多了一个不走外网的选项。"
