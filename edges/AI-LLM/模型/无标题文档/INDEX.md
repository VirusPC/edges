# AI模型格式核心笔记：Safetensors/ONNX/GGUF 对比与转换流程
## 一、核心定位（程序员编译类比）
+ **Safetensors**  
类比：源码配套的**权重数据文件**  
内容：仅存储模型权重+元数据，**无计算图结构**  
依赖：必须搭配PyTorch/Transformers代码运行  
适用：模型训练、微调、权重存储、Hugging Face分发
+ **ONNX**  
类比：**编译后的静态可执行计算图**（机器码级）  
内容：计算图结构+权重完整打包，静态化无动态逻辑  
依赖：脱离训练框架，仅需推理引擎加载  
适用：生产部署、API服务、跨硬件加速、高并发推理
+ **GGUF**  
类比：**单文件绿色便携压缩包**（内置精简运行逻辑）  
内容：权重+分词器+量化参数+模型结构元数据  
依赖：llama.cpp/Ollama等轻量推理框架  
适用：个人PC本地LLM推理、低资源设备运行

## 二、格式核心对比表
| 格式 | 类比定位 | 计算图 | 运行依赖 | 核心使用场景 |
| --- | --- | --- | --- | --- |
| Safetensors | 源码+数据文件 | 无 | PyTorch完整环境 | 训练、微调、模型存储 |
| ONNX | 编译后可执行计算图 | 有 | ONNX Runtime/推理引擎 | 生产部署、服务化、硬件加速 |
| GGUF | 单文件便携量化包 | 内置结构 | 轻量LLM推理框架 | 本地跑大模型、个人使用 |


## 三、标准转换链路（工业级通用流程）


训练/微调完成

↓

Safetensors + 模型代码（结构+权重）

├───────────────┐

│  编译导出      │  量化打包

↓               ↓

ONNX            GGUF

│

│ 硬件专属二次编译

↓

TensorRT / OpenVINO / Core ML

│

生产服务/API/高并发部署

### 主流有效转换方向
1. **训练 → 生产部署**  
Safetensors + 代码 → **编译导出 → ONNX** → 加速引擎 → 上线
2. **训练 → 本地自用**  
Safetensors + 代码 → **量化封装 → GGUF** → 直接推理
3. **非标/不推荐转换**  
GGUF ↔ ONNX、ONNX → Safetensors（无工具链、无实际价值）

## 四、极简速记口诀
+ Safetensors：存权重、做训练
+ ONNX：编译好、上生产
+ GGUF：单文件、本地跑
