---

核心是无状态。服务端存储密钥，客户端不感知密钥。

JWT包括：header、payload和signature三部分。服务端对用户名密码等信息签名。

如果客户端伪造了jwt信息，由于客户端不知道密钥，所以必定出现签名错误，验签失败，登陆失败。

Supabase 选择使用 **JWT（JSON Web Token）** 而不是传统的 **简单 cookie + session**，主要是因为 JWT 在现代应用中具有以下优势，尤其是在分布式系统和无状态架构中更适合。以下是 Supabase 使用 JWT 的原因以及它相比传统 cookie + session 的优点：

***

### **1. 无状态架构**

* **传统的 cookie + session：**
  * 需要服务器端维护会话状态（通常存储在数据库或内存中）。
  * 每次请求都需要查询服务器端的会话数据，增加了服务器的负担。
  * 在分布式系统中，需要额外的机制（如共享数据库或缓存）来同步会话数据。
* **JWT：**
  * 是一种无状态认证机制，所有用户信息都编码在令牌中，服务器不需要维护会话状态。
  * 客户端携带 JWT，服务器只需验证令牌的签名即可判断用户身份，无需查询数据库。
  * 更适合分布式架构和微服务场景，因为服务器之间无需共享会话状态。

***

### **2. 跨平台支持**

* **传统的 cookie + session：**
  * 主要依赖浏览器的 cookie 机制，适用于 Web 应用。
  * 在移动端（如 iOS/Android）或其他客户端（如桌面应用）中使用时，需要额外的支持或转换。
* **JWT：**
  * 是标准化的令牌格式，可以轻松地在 Web、移动端、桌面端甚至 API 调用中使用。
  * 客户端可以将 JWT 存储在浏览器的 cookie、`localStorage` 或 `sessionStorage` 中，也可以直接在移动端存储。

***

### **3. 更高的扩展性**

* **传统的 cookie + session：**
  * 会话数据存储在服务器端，随着用户数量增加，服务器需要更多的存储资源。
  * 用户的认证状态只能由服务器管理，扩展性受到限制。
* **JWT：**
  * 用户的认证状态由令牌携带，服务器端完全无状态。
  * 令牌可以直接传递给其他服务（如微服务），无需共享会话数据。
  * 更适合现代的微服务架构和 Serverless 应用。

***

### **4. 安全性**

* **传统的 cookie + session：**
  * 会话数据存储在服务器端，容易受到会话劫持攻击。
  * 如果没有正确配置，cookie 可能会被 XSS 或 CSRF 攻击利用。
* **JWT：**
  * 使用签名（如 HMAC 或 RSA）确保令牌的完整性，防止篡改。
  * 可以通过设置短期有效期（`access_token`）和长期刷新令牌（`refresh_token`）来降低令牌泄露的风险。
  * 可以结合 HTTPS 和 `HttpOnly` cookie 增强安全性。

***

### **5. 易于与第三方服务集成**

* **传统的 cookie + session：**
  * 会话数据通常是服务器端的私有数据，与第三方服务集成时需要额外的授权机制（如 OAuth）。
* **JWT：**
  * 是一种标准化的认证令牌，可以直接用于第三方服务（如 API 网关、云服务）。
  * 例如，Supabase 可以直接使用 JWT 来授权对数据库的访问，而无需额外的会话管理。

***

### **6. 更灵活的认证机制**

* **传统的 cookie + session：**
  * 依赖服务器端的会话管理，难以实现复杂的认证逻辑（如多设备登录、权限管理）。
* **JWT：**
  * 可以在令牌中嵌入用户的权限、角色等信息（通过 `claims`），方便实现细粒度的权限管理。
  * 令牌的内容完全由服务器控制，客户端只需携带令牌即可。

***

### **7. 简化前后端分离开发**

* **传统的 cookie + session：**
  * 需要服务器端和浏览器协同工作，前后端耦合较高。
  * 在前后端分离的场景下，管理会话状态可能会变得复杂。
* **JWT：**
  * 前端只需获取令牌并携带它，后端只需验证令牌即可。
  * 前后端完全解耦，开发更加简单。

***

### **总结**

Supabase 使用 JWT 而不是简单 cookie + session，主要是为了：

1. 支持无状态架构，提升扩展性和性能。
2. 更好地支持分布式系统和跨平台应用。
3. 提供更灵活的认证机制和权限管理。
4. 简化前后端分离开发，适应现代应用的开发需求。

虽然传统的 cookie + session 在某些场景下仍然有效，但对于现代的分布式、跨平台应用来说，JWT 是更优的选择。
