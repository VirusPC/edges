这篇文章介绍了如何使用仓库中的 **CLAUDE.md 文件**，为 Claude Code 提供持久的项目上下文，从而让 AI 更好地理解你的代码结构、编码规范和工作流程。[1]

## CLAUDE.md 是什么

CLAUDE.md 是放在代码仓库或用户目录里的配置型 Markdown 文件，用来向 Claude 提供项目特定信息，如项目简介、目录结构、依赖、编码规范和常用命令。 它会被自动加入 Claude 的系统提示，每次使用 Claude Code 时都带上这些上下文，避免你反复解释相同背景。[1]

## 主要用途和内容

文章强调，CLAUDE.md 应该解决你在项目中真实遇到的问题，比如复杂架构说明、测试要求、代码风格约定、常用脚本命令等，而不是堆砌理论信息。 文件没有强制格式，但建议保持简洁、人类可读，类似既给人看也给 Claude 看的项目文档。[1]

## 用 /init 快速生成初稿

在项目里运行 `/init` 命令，Claude 会扫描代码、配置和文档，自动生成一个初始版本的 CLAUDE.md，包括构建命令、测试方法、关键目录和检测到的编码约定。 这只是起点，需要你再根据团队实际工作流补充、删改并提交到版本库中，以便团队共享。[1]

## 如何组织 CLAUDE.md

文章给出了几类推荐内容结构：[1]
- 给 Claude 一张“地图”：提供项目概览、目录树、主要依赖、架构模式（如 DDD、微服务）等，帮助其定位代码和修改位置。[1]
- 连接自定义工具：在文件中记录部署脚本、自定义 CLI、MCP 工具（例如 Slack MCP）的用途和调用方式，便于 Claude 正确使用它们。[1]
- 定义标准工作流：为功能开发、重构、TDD、UI 迭代等任务规定步骤，如先调查现状、再出方案、补充缺失信息、最后说明测试方式。[1]

## 额外使用技巧

文章还给出三个提升使用体验的技巧：[1]
- 保持上下文“干净”：在任务切换时使用 `/clear` 清理历史对话，只保留 CLAUDE.md 这类持久配置，避免旧信息干扰当前任务。[1]
- 使用子代理（subagents）：为实现、审计、安全评审等不同阶段启用子代理，隔离上下文，保证每个阶段视角独立、聚焦。[1]
- 创建自定义命令：在 `.claude/commands/` 中用 Markdown 定义常用提示（如性能优化检查），通过斜杠命令复用，减少重复输入、统一提示质量。[1]

## 使用建议与注意事项

作者建议从简单版本开始，随着真实使用过程中的“摩擦点”逐步扩展 CLAUDE.md，而不是一开始就写得面面俱到。 同时提醒不要把 API 密钥、凭证、连接串或敏感安全信息放入 CLAUDE.md，因为它相当于可能公开的系统文档，应按可公开文档的标准对待。[1]
