在 Docker 中，\*\*容器（Container）和镜像（Image）\*\*是两个核心概念，它们有着不同的功能和性质。以下是它们的区别：

***

### **1. 定义**

* **镜像（Image）**:
  * 镜像是一个静态的文件，包含了应用程序及其运行环境的所有必要内容（如代码、依赖、配置等）。
  * 是一种“模板”或“快照”，用于创建容器。
  * 镜像是不可变的，可以被多个容器重复使用。
* **容器（Container）**:
  * 容器是镜像的运行时实例，是一个动态的、可操作的对象。
  * 容器是镜像运行后生成的独立环境，类似于一个轻量级的虚拟机。
  * 容器可以读写数据，并且可以被启动、停止、删除等。

***

### **2. 状态**

* **镜像**:
  * 静态的，不会改变。
  * 是只读的。
* **容器**:
  * 动态的，可以运行、暂停或停止。
  * 容器内部的文件系统是可写的，可以对其进行修改。

***

### **3. 用途**

* **镜像**:
  * 用于分发和共享应用程序。
  * 是创建容器的基础。
* **容器**:
  * 用于运行应用程序。
  * 是镜像的运行时表现。

***

### **4. 生命周期**

* **镜像**:
  * 镜像是长期存在的，可以存储在 Docker Registry（如 Docker Hub）中，供其他人或系统使用。
  * 镜像可以被拉取（pull）和推送（push）。
* **容器**:
  * 容器的生命周期通常较短，运行时创建，停止后可以删除。
  * 容器可以基于同一个镜像创建多个实例。

***

### **5. 示例**

假设有一个基于 Python 的镜像：

* **镜像**: `python:3.9` 是一个镜像，包含了 Python 3.9 的运行环境。
* **容器**: 当你运行 `docker run -it python:3.9`，就会基于这个镜像创建一个容器，进入 Python 3.9 的交互式环境。

***

### **总结**

| **属性** | **镜像（Image）** | **容器（Container）** |
| --- | --- | --- |
| **状态** | 静态、只读 | 动态、可读写 |
| **用途** | 创建容器的模板 | 应用程序的运行环境 |
| **生命周期** | 长期存在，可共享 | 短暂运行，可删除 |
| **关系** | 是容器的基础 | 是镜像的运行时实例 |

简单来说，**镜像是“模板”，容器是“实例”**。镜像是静态的，而容器是运行时动态的表现形式。
