# 代理、网关和隧道

HTTP 通信时，除了客户端和服务器，还有一些用于通信数据转发的应用程序，例如：代理、网关和隧道。

## 代理

1. 是一种有转发功能的应用程序。
2. 作用：转发客户端请求到其他服务器。**不改变URI**。
3. 缓存代理：将资源的副本缓存在代理服务器上。
4. 透明代理：转发请求或响应时，不对报文做任何加工。

| **代理** | **反向代理** |
| --- | --- |
| 隐藏客户端的真实 IP 地址 | 隐藏后端服务器的真实 IP 地址 |
| 帮助客户端访问目标服务器 | 帮助后端服务器处理客户端请求 |

## 网关

1. 是转发其他服务器通信数据的服务器。
2. 工作机制类似代理，但是能使通信线路上的服务器提供非HTTP协议服务。利用网关可以由HTTP请求转化为其他协议通信。

## 隧道

1. 按要求建立起一条与其他服务器的通信线路，届时使用SSL等加密手段进行通信。
2. 隧道本身是透明的。本身不会解析HTTP请求。
3. 隧道在通信双方断开连接时结束。
4. 通过隧道的传输，可以和远距离的服务器安全通信。

## 代理 VS 反向代理**代理**和**反向代理**虽然都涉及“代理”请求和响应，但它们的作用和工作方向完全不同。以下是两者的详细对比：

***

### **1. 定义和作用**

#### **代理（正向代理，Forward Proxy）**

* **定义**：代理服务器位于客户端和目标服务器之间，代理客户端向目标服务器发起请求。
* **作用**：代理客户端访问目标服务器，通常用于帮助客户端绕过访问限制、隐藏客户端的真实 IP 地址或提升访问速度。
* **工作方向**：**客户端 -> 代理服务器 -> 目标服务器**

#### **反向代理（Reverse Proxy）**

* **定义**：反向代理服务器位于客户端和后端服务器之间，代理后端服务器响应客户端的请求。
* **作用**：代理后端服务器，隐藏后端服务器的真实信息，分发流量，增强安全性和性能。
* **工作方向**：**客户端 -> 反向代理服务器 -> 后端服务器**

***

### **2. 主要功能**

#### **代理（正向代理）**

* **隐藏客户端信息**：客户端通过代理服务器访问目标服务器，目标服务器只能看到代理服务器的 IP 地址，而看不到客户端的真实 IP。
* **跨越访问限制**：帮助客户端绕过防火墙或地理限制（如访问被屏蔽的网站）。
* **缓存内容**：代理服务器可以缓存常用数据，从而加快客户端的访问速度。
* **过滤内容**：可以对客户端的请求进行过滤（如禁止访问某些网站）。

#### **反向代理**

* **隐藏后端服务器信息**：客户端只能看到反向代理服务器的 IP 地址，而无法直接访问后端服务器。
* **负载均衡**：将客户端的请求分发到多个后端服务器，均衡负载，提升系统性能。
* **安全防护**：反向代理可以作为防火墙的一部分，防止直接访问后端服务器，保护后端免受攻击。
* **SSL 卸载**：反向代理可以处理 HTTPS 请求的加解密操作，减轻后端服务器的负担。
* **缓存内容**：反向代理可以缓存静态资源，减少后端服务器的压力。

***

### **3. 工作方向对比**

| **类型** | **工作方向** | **代理谁** |
| --- | --- | --- |
| **正向代理** | 客户端 -> 代理服务器 -> 目标服务器 | 代理客户端 |
| **反向代理** | 客户端 -> 反向代理服务器 -> 后端服务器 | 代理后端服务器 |

***

### **4. 应用场景**

#### **代理（正向代理）**

* 公司或学校的网络中，通过代理服务器控制员工或学生的上网行为。
* 客户端需要访问被防火墙屏蔽的网站（如翻墙访问国外网站）。
* 加速访问：通过代理服务器缓存常用内容，提升访问速度。

#### **反向代理**

* 网站隐藏后端服务器的真实 IP 地址，防止直接攻击。
* 提供负载均衡服务，将请求分发到多个后端服务器（如 Nginx 或 HAProxy）。
* 提供 HTTPS 支持，通过反向代理服务器处理 SSL 加解密，减轻后端服务器的负担。
* 缓存静态资源（如图片、CSS 文件），减少后端服务器的压力。

***

### **5. 示例对比**

#### **正向代理示例**

* **场景**：用户 A 想访问被屏蔽的 `example.com` 网站。
* **流程**：
  1. 用户 A 将请求发送给代理服务器。
  2. 代理服务器代表用户 A 请求 `example.com`。
  3. `example.com` 将响应返回给代理服务器。
  4. 代理服务器将响应返回给用户 A。

#### **反向代理示例**

* **场景**：用户 B 想访问 `example.com` 网站，该网站使用反向代理服务器。
* **流程**：
  1. 用户 B 的请求发送到反向代理服务器（如 Nginx）。
  2. 反向代理服务器将请求转发到后端服务器（如 Web 服务器）。
  3. 后端服务器处理请求并将响应返回给反向代理服务器。
  4. 反向代理服务器将响应返回给用户 B。

***

### **6. 总结对比表**

| **对比项** | **正向代理** | **反向代理** |
| --- | --- | --- |
| **代理对象** | 客户端 | 后端服务器 |
| **隐藏信息** | 隐藏客户端的真实 IP 地址 | 隐藏后端服务器的真实 IP 地址 |
| **主要功能** | 帮助客户端访问目标服务器 | 帮助后端服务器处理客户端请求 |
| **典型用途** | 翻墙、访问受限资源、缓存加速 | 负载均衡、安全防护、SSL 卸载、缓存加速 |
| **工作方向** | 客户端 -> 代理服务器 -> 目标服务器 | 客户端 -> 反向代理服务器 -> 后端服务器 |
| **示例技术** | VPN、Shadowsocks、Squid | Nginx、HAProxy、Apache Traffic Server |

***

### **总结**

* **正向代理**：主要代理客户端，帮助客户端访问目标服务器，隐藏客户端信息，常用于翻墙或加速访问。
* **反向代理**：主要代理后端服务器，帮助后端处理请求，隐藏后端信息，常用于负载均衡、安全防护和性能优化。

两者的核心区别在于**代理的对象**和**工作方向**，正向代理服务于客户端，反向代理服务于服务器。
