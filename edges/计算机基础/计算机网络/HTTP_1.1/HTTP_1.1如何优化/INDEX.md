# 方法
1. KeepALive将HTTP/1.1 从短连接改成长连接。
2. 不发：尽量避免发送HTTP请求
3. 少发：在需要发送HTTP请求时，考虑如何减少请求次数
4. 快发：减少服务器HTTP响应的数据大小



## 不发
1. 强缓存（协商缓存还是会发）



## 少发
1. 减少重定向请求次数(缓存)
    1. 重定向请求交给代理服务器处理（缓存代理，不能是透明代理）
    2. 301和308响应码是告诉客户端可以将重定向响应缓存到本地磁盘，之后客户端就自动用url2替代url1访问服务器的资源。
2. 合并请求次数
    1. 图片请求合并：
        1. 雪碧图
        2. base64编码合并进html
    2. js/css资源合并：webpack

## 快发
1. 资源压缩
    1. 根据语法规则压缩：去除空格换行符等
    2. 无损压缩：content-encoding 告知客户端压缩算法
    3. 有损压缩: 主要用于压缩多媒体数据，汝音频、视频、图片
        1. 请求报文中的Accept字段里的q质量因子，告诉服务器期望的资源质量。
        2. Google的WebP压缩质量很高
    4. 应用层面:根据应用场景压缩：M4
2. 体积
    1. 减少webpack打包体积（peer dependencies。 external看情况，增加次数，减少总体积）
    2.  按需获取，下滑页面时才获取。（过滤面板，虚拟滚动+延迟发送）
